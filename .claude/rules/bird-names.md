# SnowRaven bird-name conventions

Moved verbatim from CLAUDE.md (2026-08-26 context restructure). This file auto-loads when a session works on files matching the `paths` above; for related work that starts elsewhere, read it in full before changing anything it governs. Its rules carry the same force as CLAUDE.md.

- **Render every user-facing bird name through `<BirdName>`** (`frontend/src/components/BirdName.tsx`) — never hand-roll a name + favicons, and don't use `SpeciesLinks` directly in new code (BirdName composes it). Props: `commonName`, `scientificName?`, `taxonCode?`, `hasEntry?`, `onOpenSpecies?`, `showSci?`, `size?` (`sm`/`md`/`lg`).
- **Link the common name only when `hasEntry`** — i.e. the species is in the user's loaded backbone (recorded). Birds the user hasn't recorded (nemesis, unseen map targets, a comparer's other-list-only column) get plain name + favicons, never a Species-Detail link. Source `hasEntry` from a normalized backbone set (`normalizeSpeciesName`); tabs whose lists are entirely from the backup pass `true`.
- **Navigation:** pass `onOpenSpecies={navigateToSpeciesDetail}` (from `App`) so clicking a name opens it on Species Detail. `App.requestedSpecies` + `SpeciesDetail`'s consume effect handle selection (single-use, pending until `phase==='ready'`, subspecies-normalized). Species Detail's own internal names use its local `selectSpecies`.
- **Favicons need a taxon code** — resolve codes for the species a tab shows (batched `/taxonomy/codes`); BirdName no-ops favicons when the code is missing. If names render without favicons, the tab isn't resolving codes for that set.
- **"Move the link to the number":** where a name previously linked somewhere (a count, a checklist, a map pan), keep that link on the count/element (or a ↗ / locate icon) and point the name at Species Detail. Exclude form controls (`<select>`, checkboxes) and the Species Detail entry header.
- Component tests use `jsdom` via a per-file `// @vitest-environment jsdom` docblock (see `BirdName.test.tsx`); the rest of the suite stays node-env.
- **ALL Macaulay Library media-catalog links (Statistics, Multimedia, Species Detail) build on ONE host + ONE pattern: `media.ebird.org/catalog?…&taxonCode=<code>` via the shared `ML_CATALOG_BASE` (`lib/statsFormat.ts`) — the legacy `search.macaulaylibrary.org` host and the `?taxaName=<name>` fallback are BOTH retired (v0.5.57 consolidation, done).** Never emit `?taxaName=`, never build on the legacy host, and never ship a bare (filter-less) link for a resolvable species. A media link resolves its taxon code by **normalizing the name FIRST** (so a trailing-parenthetical form name — `Scaly-breasted Munia (Scaled)`, `Dark-eyed Junco (Oregon)` — still resolves the species code; the raw name misses the species-only lookup) and interpolates it `encodeURIComponent`-wrapped. The link **follows the "Show subspecies" toggle** on the two surfaces that have one (Species Detail + Multimedia) via the centralized `resolveMediaLinkTaxonCode(showSubspecies, formCode, speciesCode)` in `lib/mlCatalog.ts` — OFF → species code (all the bird's media), ON → the form's own issf code (just that form); Statistics has no toggle → always species code; species code is the universal fallback when a form code is unresolvable. Reuse that one helper, don't re-derive the branch (the ON-case degrade to species-level is a one-line change there — the deploy-smoke carry-forward). The ON-case form codes come from `/taxonomy/codes`' **additive `formCodes` map** (all-category name→code, inverted from the bundled snapshot's `byCode`; `routers/taxonomy.py` `_by_com_all` ↔ `taxonomyService.ts` `byComAllFor` twins, locked by a `formCodes` parity test on the shared `taxonomyCollapse.fixture.json` — extend that fixture, not a per-transport ad-hoc test). **`codes`/`orders` (species-only, feeding favicons + taxonomic sort) MUST stay byte-identical** — `formCodes` is purely additive; form names still MISS `codes`. Behavior counts still carry `?userId=<id>&tag=<slug>` from the fixed `BEHAVIOR_TAG_SLUG` map in `lib/mediaStats.ts`: slugs are NOT derivable from the display label (`Flying`→`flying_flight`, `Mechanical Sound`→`non_vocal`, `Preening…`→`preening`, `Courtship…`→`courtship_display_or_copulation`) — verify any new slug against the live catalog UI; an unmapped behavior renders plain (never a broken link). The count carries the link (move-the-link-to-the-number) via `BarRow`'s `href`/`linkLabel`, whose accessible name leads with the visible count.
- **Countability is eBird's question and eBird answers it in the taxonomy's `reportAs` field. ONE predicate, `isNonCountableForm(name)` (`lib/speciesUtils.ts`), at every call site (v0.5.89).** A published name counts when its code is itself a species, or when `reportAs` resolves it to one. As a birder reads it: **ambiguity about which SPECIES does not count; ambiguity about which SUBSPECIES counts as the parent.** Pass the name **as exported**, trailing parenthetical intact — the form is what eBird is judging and the form exists only in the raw name. The three string-shape predicates it replaced (`isSpuhOrSlash`, `isNonCountableSpecies`, `isNonCountableObservedName`) are **gone**; do not reintroduce a local one. Shipped call sites: `filterObservations` (Statistics + the Map Explorer county aggregates), `lib/calendar.ts`, `mediaStats.ts`, `frivolousLists.ts`, `countyCompleteness.ts`, `parseEbird`, `parseMLExport`, both Breeding Codes paths, and the two widened row filters (Multimedia, Species Detail). The parsers still classify the raw cell and then call `truncateAtFirstParen` — v0.5.86's classify-then-normalize contract is unchanged, only the classifier moved.
  - **The naming convention survives as the FALLBACK for a name eBird does not publish, not as an inference — and that is why the old raw-versus-normalized asymmetry is still in the code.** Shipping a verdict for all 17,891 published names costs ~105 KB gzipped on a module statically reachable from `App.tsx`, so the shipped artifact is the convention plus its **169 corrections** (2.6 KB gz), with `countableForms.test.ts` asserting the pair equals the full `reportAs` lookup **name by name over the whole snapshot**. `isNonCountableNameShape` keeps v0.5.83's deliberate asymmetry (` x ` tested on the NORMALIZED name, ` sp.`/`/` on the raw name) because it is still right for the names it now judges: a trailing parenthetical can carry its own ` x ` for a countable intraspecific intergrade (`Yellow-rumped Warbler (Myrtle x Audubon's)`) where a base-name ` x ` is a true hybrid (`Mallard x American Black Duck (hybrid)`). **Collapsing the raw/normalized PAIR was a silent data-loss bug before this build and v0.5.83 said so at length; what discharges that warning is not care but the sweep** — the 36 intergrades it protected stay countable, and the discriminating case goes red on a revert. Keep that reasoning attached to any future change here: the old rule was wrong in **both** directions (88 names eBird counts were excluded, folding into 59 parents; 81 it rejects were counted), and a birder holding `Brewster's Warbler (hybrid)` had it counting as a species.
  - **The fallback is deliberately NOT "an unknown name counts."** A name from an older revision or a since-renamed species behaves exactly as it did before this build. The v0.5.87 escapee precedent runs the other way (an unresolved species COUNTS) and does not transfer: there an unresolved name would erase a bird the birder really saw and resolution is a live network pass that starts empty, whereas this lookup is complete the moment the module loads.
  - **The user-facing labels are `Count all forms` (Statistics, Calendar) and `Show all forms` (Multimedia, Species Detail), single-sourced in `lib/countabilityCopy.ts`.** They do not enumerate, so they survive the set moving again; they keep the `Count <plural noun>` parallel with the stacked `Count escapees`; and they are positive rather than a negated noun. **`countabilityCopy.ts` is separate from `exoticCopy.ts` for a BUNDLE reason, not a subject one** — `LifeList.tsx` is on `App.tsx`'s static graph, so importing the lazy `exoticCopy.ts` (~3.7 KB gz) for one 15-character string would move all of it onto first paint. `exoticCopy.ts` imports the label it quotes rather than repeating it. Consequence to know before reaching for either: **`exoticCopy.ts` now holds copy that is not about exotics** (`COUNT_RULE_SENTENCE`, `COUNT_RULE_SENTENCE_NO_ESCAPEES`, `ALWAYS_COUNTABLE_NOTE`, `COUNTY_COUNT_RULE_SENTENCE`), so its name under-describes it; put a new string where its consumers' bundle position requires, and if a third copy module appears, add it to the em-dash/apostrophe sweep in `ExoticProvenanceAccount.test.tsx` ("copy hygiene"), which names the modules it sweeps.
  - **The Statistics same-tab asymmetry is deliberate and is now stated on screen.** The header checkbox moves the species tile but NOT media documentation coverage or the Frivolous Lists, which are *about* the canonical life list rather than about what was recorded (a coverage denominator a reader can inflate with `Gull sp.` asks "have you photographed a spuh", which has no answer). It is structural, not incidental: both derive from `effectiveObs` and never from `filteredObs`, which is the only thing the toggle reaches. `ALWAYS_COUNTABLE_NOTE` renders on both surfaces; `HELP.md`'s old "across every card" claim was false and is gone.
  - **The countable rule has a SECOND half, and it is the only NETWORK-DERIVED one: eBird "Exotic: Escapee" provenance (v0.5.87).** (It was recorded as a fourth exclusion class when the first half was three string shapes; v0.5.89 collapsed those three into the one `reportAs` rule above, so the pairing is now form-then-provenance. The escapee half is unchanged by that collapse and composes with it: form excludes by shape of the taxon, provenance by how the bird got there.) An off-by-default **Count escapees** toggle on Statistics makes the headline total follow eBird's own life-list rule — `P` (Provisional) and `N` (Naturalized) count, `X` (Escapee) does not — so with the toggle ON the total is byte-identical to the pre-v0.5.87 number. Six properties are load-bearing and each was a live wrong turn or a stated success criterion:
    - **Provenance is stored PER OBSERVATION but the question is PER SPECIES, and the answer is a monotone OR** (a species counts if at least one of its observations is not `X`). One `product/checklist/view` call therefore returns provenance for every species on that checklist at once, which makes resolution a **set cover** over data the app already holds — computed offline from the loaded export — and NOT a per-observation sweep. Getting this backwards is what priced the feature at ~3,252 calls and got it declined; the measured cover is 73.
    - **An UNRESOLVED species COUNTS.** A species is dropped only once every checklist carrying it has been consulted and every one came back `X`, so the total converges downward and never wrongly erases a lifer. A partial pass says how far it got and offers a retry on every partial reason, not only the error one (a birder who presses Stop otherwise has no route back, and a tab stays mounted for the session).
    - **The offline `category === 'domestic'` shortcut is FORBIDDEN, under any label.** The bundled taxonomy has no provenance field, and its `category` is wrong in both directions: eBird returns `N` for Red Junglefowl and `P` for Indian Peafowl and counts both. **If either disappears from the total, the shortcut was built instead of the rule** — that is the falsifiable criterion, and `exoticProvenance.test.ts` → "the taxonomy category field can never decide countability" is the guard. A control labelled "escapees" running a different rule than eBird's claims a parity it does not have. The gate is the explicit `exoticCategory === 'X'` test; the companion `userDoNotCount` is recorded in the cache but never consulted, and a test asserts that stripping it from every token changes no classification.
    - **Join on `speciesCode`, never a common-name round trip** (a probe round-tripping codes through the bundled taxonomy's names produced 4 mismatches). Names map to codes once, in one direction.
    - **Resolution is initiated ONLY from Statistics; every other surface reads the cached result passively**, so the Calendar's v0.5.63 zero-network guarantee survives — and that is enforced by the IMPORT GRAPH, not by discipline (`exoticProvenanceGraph.test.ts` walks the closure of the passive modules and fails if one ever gains a `transport` / `lib/tauri/*Service` edge, with a guard-the-guard pointing the same walker at the controller).
    - **Scope is the surfaces that HEADLINE a life-list count** — Statistics totals and milestones, media documentation coverage, county Completeness, Calendar species counts, Frivolous Lists — never the surfaces that LIST species (Life List/Multimedia table, Species Detail, Breeding Codes, List Comparer, Map Explorer display filtering). Two stated asymmetries, deliberate rather than oversights: county Completeness applies the rule to the NUMERATOR only (filtering eBird's regional denominator would mean classifying every species eBird publishes for a region), which the popup caption now says in words rather than naming exactly three excluded kinds; and Statistics' Geographic Stats per-county species counts are out of scope, so they no longer agree exactly with the Completeness numerator they were aligned with in v0.5.86. **This scope statement is about the ESCAPEE half only, and v0.5.89 made that distinction load-bearing rather than academic:** the FORM half also governs the row filters on Multimedia and Species Detail (so those tabs' visible rows and their own `X of N species` count agree by construction). **The escapee half has ONE named exception among the list surfaces, added by user direction in v1.0.18: Species Detail reads the rule PASSIVELY, behind an off-by-default `Show escapees` reveal switch** (`SHOW_ESCAPEES_TOGGLE_LABEL` in `exoticCopy.ts`, session-only, never persisted, never shared with Statistics' `includeEscapees`), so its selector and "N species" figure agree with the Statistics headline at both tabs' defaults. It is a layer on the tab's display list composed with the form filter, keyed by normalized name so a domestic-type form hides with its escapee parent, and the Statistics-only initiation rule is untouched: the tab imports `useProvenanceLookup` and never `useExoticProvenance` (`exoticProvenanceGraph.test.ts` pins it), confirms each published name against the ledger with its own observations, and a request for a hidden species from another tab or the Subspecies and forms control REVEALS it (turns on whichever switch hides it, then selects) rather than dropping it silently. Multimedia, Breeding Codes, the List Comparer and Map Explorer display filtering remain outside the escapee half; Multimedia's "X of N species" is now the one list count without the rule (ROADMAP follow-on). Do not read one bullet as licence to extend the other.
  - **Where a repo convention and an approved pipeline artifact disagree on which predicate a call site takes, the CONVENTION wins and the deviation is stated in code.** v0.5.87's `schema.md` specified the normalized-name predicate for the escapee cover index while the raw-versus-normalized rule required the raw-name one at a site holding a raw CSV name, which also keeps countable intergrades in the cover; it was implemented per the convention with the reason at the call site. (Both predicates are gone as of v0.5.89 — `isNonCountableForm` takes the raw name — but the precedence rule is what this bullet is for, and an approved artifact is still not evidence for a fact the builder can measure.)
  - **When a change alters WHICH names are excluded, sweep the bundled taxonomy snapshot rather than reasoning from examples.** That is what sized the options here and picked the narrow one: the raw-name form excludes 818 names (782 true hybrids, correct, plus **36 countable intergrades**, wrong); the shipped predicate excludes exactly the 782, loses 0 intergrades, and newly keeps 0 names the old code excluded. An 88-name subspecies-group slash class was also surfaced and left alone. **A guard test for over-exclusion must use a case that actually discriminates** between the old and new predicate, and must say so in-code when it does not: `Xantus's Hummingbird` passes under both and proves nothing (kept, labelled a guard); the discriminating case is a trailing-parenthetical intergrade, and reverting the helper to the raw-name form must turn a test red on every affected surface.
  - **When real data CANNOT discriminate between a correct and an incorrect implementation, the snapshot sweep is necessary but not sufficient, and exhaustive enumeration over a small alphabet is the probe set (v0.5.84).** Every eBird name is well formed (at most one `(`, always closed, always trailing), so rewriting `normalizeSpeciesName` scored **0 divergences across all 58,104 snapshot strings under the WRONG implementation too** — a snapshot-only sweep would have passed the parsers' local `indexOf('(')` variant, which diverges 10,300 times on malformed shapes. Build the alphabet from the characters the function actually branches on plus the ones that break naive implementations (here `(`, `)`, a letter, and space / tab / newline / U+00A0 / U+2028 / U+FEFF / U+3000 — U+2028 earns its place because it is both `\s` and a LineTerminator, yet a non-multiline `$` does not treat it as end of input, so a line-aware primitive diverges there and nowhere else), enumerate to length 4, and **assert BOTH numbers in the suite** — that real data scores zero and that the probes do not — so the test states in its own body why it is shaped this way. A guard-the-guard that names the competing wrong implementation is what makes the claim falsifiable. **Two v0.5.85 additions, both earned by a probe alphabet quietly losing members.** (1) **Write every exotic whitespace member as a `\uXXXX` ESCAPE in source, never as a literal character.** Literals are invisible in a diff and were silently flattened into ordinary spaces four times across two builds, leaving the alphabet weaker with every test still green (one attempt also wrote `\\t` where `\t` was meant, over-escaping rather than flattening). Pin the code points directly in the suite rather than trusting they were written down correctly; that assertion catches both slips and did. (2) **A hand-written character-class helper needs mutation coverage MEMBER BY MEMBER, not just "remove the whole check".** Where a predicate can delegate to a quantifier-free single-character regex (`/\s/`, `/\d/`) it cannot drift; `isLineTerminatorChar` cannot (JS exposes no class for exactly what `.` excludes), so it is the one that can — deleting `ch === ' '` left the whole 1,550-test `src/lib` suite green because only U+2028 was in the alphabet. Every member of such a predicate must appear in some suite's probes, and the alphabet grew to include U+2029 for exactly that reason. **v0.5.89 extension, which moves the BOUNDARY of the v0.5.85 "apply it to every instance in the module" rule: where a synthetic probe is written because real data cannot discriminate, write it for EVERY SURFACE that implements the property, or state in the unguarded one that it is unguarded and why.** The module is the wrong unit. Grouping all 17,891 published names by normalized base gives 13,758 groups and **zero** that mix a countable with a non-countable raw name, so real eBird data cannot distinguish a monotone OR from last-write-wins at all; the OR is implemented in two components, got its synthetic pair in one, and the unguarded one is precisely the surface where the correct behaviour falls out of the data structure (an add-only `Set`) rather than from an explicit choice — which is where a future refactor away from that structure goes unnoticed. Say which surfaces were checked, not just which files.
- **A named bird's MEDIA is matched by a per-row PRECEDENCE over the `[name:…]` tag, NEVER a union: the asset's OWN comment (`caption` + `mediaNotes`) wins outright when it carries a tag, and ONLY a tagless own comment falls back to `observationDetails` — keyed by the shared `namedBirdKey` (v0.5.66 Named Birds media; precedence + fallback v0.5.75).** The pure matcher `computeNamedBirdMedia` (`lib/namedBirdMedia.ts`) reuses `parseNameTags` (`lib/namedBirds.ts`). Precedence rather than union so a per-asset caption *corrects* a broader observation tag instead of being added to it (caption a photo `[name:Pilgrim]` on an observation tagged `[name:Winky]` and it counts only for Pilgrim). **The gate is a PARSED TAG, not caption text** — a plain descriptive caption with no `[name:…]` in it does not override anything, it simply leaves the row on the fallback; never document the override as "caption the asset."
  - **Why `observationDetails` is now read here but still excluded in `lib/mediaComments.ts` — the two are DELIBERATELY divergent; do not re-unify them.** v0.5.66 excluded it outright, reasoning that the ML export copies the observation comment onto every asset from that observation. True, but it grouped `observationDetails` with the *checklist* comment, which is far broader. An observation comment is scoped to **one species on one checklist**, and it is the very field `computeNamedBirds` parses to discover a named individual in the first place — so excluding it meant the tag that CREATES a named bird could never attribute that bird's media, and a birder who tags the ordinary way (in the species comment rather than per asset) got a guaranteed empty state. The two modules answer different questions: `mediaComments.ts` **lists comments**, where that copied text would repeat identically across every asset from one observation (noise); this matcher asks **which assets show this individual**, for which a species-and-checklist-scoped tag is real evidence. Keep the reason with the rule — without it a later change will quietly re-unify the two field selections.
  - **Accepted limit:** the fallback attributes every *uncaptioned* asset from a name-tagged observation to that name, so it over-attributes when a birder photographs a different, untagged bird of the same species on the same checklist. Captioning that asset is the explicit override. When one observation names two individuals, both get all of its uncaptioned assets — the honest superset; do NOT suppress the fallback on multi-name observations, which would blank exactly the birders who tag the most.
  - Group matched assets by `namedBirdKey(name, commonName)` — the SAME name-plus-normalized-species key `computeNamedBirds` buckets on — so the media join can never cross-attribute the same name across two species; a key-parity unit test locks the two formulas byte-identical (extend it, don't re-derive the key inline). Matching + the date/checklist labels are fully offline from the already-loaded `mlExportCache`; only the embed iframe needs the network. **A precedence rule needs at least one test a union would fail** — fallback-only cases pass under both implementations, so name the competing wrong implementation and confirm the suite rejects it.
- **Hardcoded bird-name collections (the Frivolous Lists) use current canonical eBird names, VERIFIED against the live taxonomy before shipping.** Matching is exact-by-normalized-common-name against the user's data, so a stale or renamed name silently never ticks (unit tests won't catch every name). POST the names to `/taxonomy/codes` (the live eBird taxonomy the app uses) and fix any that don't resolve — recent traps: `Cattle Egret` → `Western Cattle-Egret`, and the Night-Herons dropped the Night/Heron hyphen (`Black-crowned Night Heron`). Grouped (sub-category) collections reuse `GroupedListResult` / `groupedList()` / `GroupedNameList` in `lib/frivolousLists.ts` + `FrivolousListsSections.tsx` — one whole-list badge; sub-group labels are cosmetic (need not be canonical).
- **The bundled eBird taxonomy snapshot is the OFFLINE FLOOR for favicons/sort/reportAs (FR-21/22, offline-support) and ships TWICE — `frontend/src/assets/ebird-taxonomy.json` (desktop floor) and `backend/staticdata/ebird_taxonomy.json` (web/Pi floor) — kept identical, regenerated by `scripts/build-ebird-taxonomy.mjs` (needs `EBIRD_API_KEY`).** When regenerating for a new annual Clements/eBird revision, the snapshot's version key AND the desktop IndexedDB `CACHE_KEY` in `lib/tauri/taxonomyService.ts` (currently `taxonomy-v2027`) must advance in LOCKSTEP — a fresher snapshot under a stale `CACHE_KEY` strands desktop users on the old IndexedDB copy until its 7-day TTL expires (the live fetch still supersedes both when online, FR-25). The snapshot is an on-demand chunk (dynamic import), never the entry chunk (NFR-16) — re-confirm with the QA-37 build inspection after any taxonomy-loading change.
- **A `/taxonomy/codes` batch that feeds a COVER or countability consumer must request each observed name AND its normalized parent (v1.0.1).** `codes` is species-only by contract on both transports, so a bird recorded ONLY as a form name (`Swan Goose (Domestic type)`) resolves no species code from its raw name alone, and a consumer that joins on codes then silently skips the species — the v1.0.1 escapee defect: the cover classified the three domestic-form escapees 'unknown' (which counts, by design) and Statistics read zero escapees, masked everywhere by each store's cached verdicts until a fresh pass ran. `BirdingStats.tsx`'s batch now sends the normalized parent beside each raw name (the raw name stays for `formCodes` consumers; `codes`/`orders` remain species-only and byte-identical). Two companions ride with it, both red-first tested: **a fresh ledger entry does NOT stand for a recordless cover species** — `carriersNeedingRefetch` (`lib/exoticProvenance.ts`) re-opens exactly those checklists — and the refetch intent is passed EXPLICITLY to `dedupedFetchChecklist({refetch})`, whose own fresh-ledger short-circuit is a second enforcement point that would otherwise refuse the re-selected wave. Known residual, on ROADMAP: the other tabs' own codes batches still miss form-only species (favicons/sort only, no count effect).
