# SnowRaven documentation and website conventions

Moved verbatim from CLAUDE.md (2026-08-26 context restructure). This file auto-loads when a session works on files matching the `paths` above; for related work that starts elsewhere, read it in full before changing anything it governs. Its rules carry the same force as CLAUDE.md.

- **`docs/HELP.md` is the single source of truth for all in-app help content.** When a feature is added or changed, update this file to reflect the current behavior before pushing.
- **Any hand-maintained index over a document declared the single source of truth needs a parity test (v0.5.75).** `HelpDocs.tsx`'s sidebar TOC is a separate hand-kept array over `docs/HELP.md`, and three sections (Calendar, Using SnowRaven offline, Updating SnowRaven) drifted out of reach for several versions with nothing failing. `frontend/src/lib/helpToc.test.ts` is the pattern: parse both sides and assert the set, the order, and that each generated id actually resolves. Extend it rather than re-checking the TOC by eye.
- **A TAB STAYS MOUNTED once opened, so a session-only `useState` toggle survives leaving and returning to its tab and only resets on relaunch — published prose must never say otherwise (v0.5.81).** `mountedTabs` only grows and a hidden panel is `display: none`, never unmounted. This applies to every session-only toggle in the codebase, not just the newest one: `wideMode`, "Pin code labels" and its Multimedia twin "Pin column labels", Point Size, county Use Textures, the Calendar view toggle, and the share pin. **Check the mount lifetime, not just the `useState`, before writing any sentence about how long a setting lasts.** The settled house phrasing is **"per-session, resetting on relaunch"** (used throughout `docs/HELP.md`) — reuse it rather than inventing a new formulation. This defect occurred TWICE in one bundle, once new and once in already-shipped v0.5.80 prose about the map share pin, which makes it a repeating shape rather than a one-off.
- **Where published prose states a trigger, grep the predicate; where one rule is documented in several places, write the precise formulation once and propagate it (v0.5.75).** Two real defects in one commit: a published accessibility statement quoted an accessible name the component never emits, and a repair instruction ("caption the asset") named a condition narrower than the code's real gate (a parsed `[name:…]` tag). Separately, the Named Birds precedence rule drifted across `docs/HELP.md`, `README.md`, and `website/index.html` *within a single commit*. `docs/HELP.md`, `README.md`, `website/index.html`, `PRIVACY_POLICY.md`, and `ACCESSIBILITY.md` are all hand-maintained restatements of shipped behavior — when you change a rule, change every copy in the same edit and check each against the code that implements it. Two v0.5.83 recurrences, both caught in review: `ACCESSIBILITY.md` said the map location button "reports being busy" when it ships `aria-disabled` and `aria-busy` appears nowhere (grep count 0), and the same paragraph claimed a sidebar copy of the message that `CenterPointControl` renders only on the three centre views. **A CONTROL LABEL is subject to the same rule and can become inaccurate rather than merely stale when a feature's scope moves** — "Pin code labels" was right, became wrong under a two-axis freeze, and is right again. Re-check labels against what the code does whenever scope changes; naming the axis is what makes the label accurate. **This rule governs a scope claim in SOURCE as much as in published prose (v0.5.84):** a comment asserting "this was the last instance of X" is a claim about the whole codebase that decays, and it shipped false in this bundle. Re-derive it when you write it, or scope it to the file. **Two v0.5.87 extensions, both earned:**
  - **Single-sourcing a copy constant prevents DRIFT between copies; it does nothing to prevent a copy being DROPPED. Assert every copy renders — one test per surface, each with an absent case.** The escapee cross-tab count sentence was single-sourced correctly and rendered on four surfaces, and the whole 2,475-test suite stayed GREEN with it gated off on one of them, because the only assertion was on the constant. Same shape as the per-partition non-vacuity rule for guards that split their work into buckets: one assertion for the whole is not one assertion per part. Drive the real hook through the real store on at least one surface rather than mocking it everywhere, and add a guard-the-guard that flips the flag against an unchanged input.
  - **Fixing an over-claim is exactly where the NEXT over-claim gets written.** The escapee privacy sentence was corrected for claiming too much ("the one place where a number is derived from a live lookup" — county Completeness and hotspot popups are both counter-examples) and the correction introduced a *different* false clause in the same sentence ("the Statistics tab was previously computed entirely on your device" — that tab has posted to `/taxonomy/codes` and fetched `/map/hotspot-region` all along). A prose repair earns the same grep-the-predicate treatment as the prose it replaces; being a correction is not evidence of being correct.
  - **Grepping the predicate is not enough when the predicate is an INPUT-MODALITY-dependent state: either scope the sentence to the modality, or verify it in every shipping engine (v0.5.91).** Three published surfaces claimed the "Search this area" control stays in place after a press. It is gated on `document.activeElement === e.currentTarget`, which holds in Chromium for pointer and touch and is **false in WebKit** — the engine behind the shipped macOS and iOS apps — because WebKit does not focus a button on press. The sentence it replaced had the mirror-image defect (true on WebKit, false on Chromium), so a one-engine check would have caught neither. The existing rule caught it only because the predicate was read as what it literally says rather than as "after you press". Same for hover, `:focus-visible`, and anything else whose truth depends on how the user arrived. The keyboard path was made unconditional in both engines instead (an explicit `tabIndex={0}`, so it does not depend on the macOS Full Keyboard Access setting), and the published sentences now scope the promise to it.
- **No em dashes (—, U+2014) in the app's user-facing copy, `docs/HELP.md`, or the published prose surfaces — `README.md`, `website/` user-facing prose (`website/privacy.html` included), `PRIVACY_POLICY.md`, `ACCESSIBILITY.md`, `appstore/LISTING.md`, and `appstore/REVIEW_NOTES.md` (v0.5.68 sweep; scope extended to the published surfaces in v0.5.78, and to the App Store record files and the privacy page at 1.0.0).** This covers on-screen text, tooltips, `title`/`placeholder`/`aria-label` values, headings, buttons, messages, and empty states, plus all of `docs/HELP.md` and the published files above. Replace per context (a period between independent clauses, a comma for a light aside, a colon before a list/definition, or parentheses for a true parenthetical — not a blind character delete; collapse the surrounding spaces of a ` — ` to match the replacement). TWO standing exclusions: (1) provider-mandated attribution / credit strings (e.g. Esri's required map-tile attribution) — leave them verbatim; (2) data-parsing regexes and any dash that is load-bearing in matching logic. Out of scope entirely: code comments, tests, historical records (`DECISIONS.md`, `CHANGELOG.md`, pipeline archives), and eBird/Macaulay DATA passthrough (bird names, place names, user comments — not our copy). En dashes (–, U+2013) are also out of scope (e.g. the `2019–2025` year span, a `min–max` range) and are the sanctioned glyph for an empty/placeholder table cell (the website List Comparer mock's two placeholder cells use them). A `grep -rn '—'` over rendered `.tsx`/`.ts` strings, `docs/HELP.md`, `README.md`, `PRIVACY_POLICY.md`, `ACCESSIBILITY.md`, `website/index.html`, `website/privacy.html`, `appstore/LISTING.md`, and `appstore/REVIEW_NOTES.md` should stay clean.
- `HelpDocs.tsx` imports `docs/HELP.md` via Vite's `?raw` loader (`import helpText from '../../../docs/HELP.md?raw'`). Content is bundled at build time — no runtime fetch. Offline-available by design.
- `vite.config.ts` sets `server.fs.allow: ['..']` to allow the dev server to resolve the `?raw` import outside the `frontend/` root. This is dev-only — production resolves at compile time.
- **Also review and update `README.md`** before every push to ensure it reflects the current feature set.
- **The public showcase website lives in `website/` and ships to GitHub Pages — keep it in sync with the README and docs.** It is a static, dependency-free site (hand-written `website/index.html` + `styles.css` + `app.js`, system fonts only, **no third-party requests** so it embodies the privacy-first promise, all asset paths relative for the `/snowraven/` project-pages base). `.github/workflows/pages.yml` redeploys it on every push to `main` that touches `website/` (one-time setup: repo Settings → Pages → Source = "GitHub Actions"). **Whenever a feature is added or changed, or `README.md`/`docs/HELP.md` are updated, update `website/` in the same change** — the feature list, copy, the version pill + footer version (kept in lockstep with the app version from `frontend/package.json` — the live value lives in `website/index.html`, not hardcoded here), and screenshots must reflect the current app. The site is NOT in the desktop/web app bundle, so it does **not** get a `package.json`/`tauri.conf.json` version bump and does not ship in releases.
  - **Screenshots (`website/assets/shots/*.webp`) must come from SYNTHETIC demo data, never the user's real eBird data** — the privacy-first brand means the published site must never contain personal sighting locations. Regeneration tooling is in `website/tools/` (`gen-demo-data.mjs` builds a fictional dataset, `capture.mjs` drives the running app with Playwright, `process-img.mjs` resizes to WebP); see `website/tools/README.md`. Point the backend at the demo dataset with `SR_DATA_DIR` (see `.claude/rules/backend.md`) — never `mv` the real `data/` aside, which strands it if a capture crashes partway.
  - **The capture VIEWPORT WIDTH is load-bearing against the TabNav collapse threshold — adding a tab may require raising it (v0.5.77).** At ten tabs the strip needs ~1409px while TabNav collapses below ~1457px, so the old 1440px width silently photographed a *dropdown* instead of the tab strip; it is now 1600px. Re-check it whenever a tab is added or a tab label grows. Relatedly, `clickTab` now THROWS on a label it can't find — it used to return `false`, yielding a screenshot of whatever tab happened to be open. Verify each output image actually shows its intended tab; an exit code of 0 was never proof. **The threshold binds ANY Playwright probe, not just this tool (v0.5.84):** an ad-hoc probe opening a tab at the very common 1440px width finds no `[role="tab"]` strip at all, so a strip-only selector times out — carry the dropdown fallback, or drive the probe at 1600px. **Two more probe hazards, both silent (v0.5.91):** Playwright resolves a request against the **most recently registered** matching route, so a catch-all registered last swallows every specific stub; and `page.mouse.wheel` does not zoom this map in headless Chromium at all, which made an early run measure one viewport twice and report it as two zoom levels (drive the map's own NavigationControl buttons instead). The second was checked rather than blamed on the app: `MapExplorer` renders `<SnowMap>` without `scrollZoom` and the wrapper resolves handler props with `?? true`, so scroll zoom is enabled and there is no defect to report. `website/tools/probe-search-area-radius.mjs` records these in its own header.
  - **Voice:** informative, not promotional. The site exists so a birder can learn what SnowRaven does and decide for themselves; it is a personal project shared as a free public good, and it does not try to sell or push downloads. Frame SnowRaven as working *alongside* eBird and the Macaulay Library and letting you explore your own exported data in new ways. Never imply it replaces, fixes, or improves on eBird, and keep the gratitude toward those free services intact (no "finally working for you" framing, no star-begging).
- **`PRIVACY_POLICY.md` and `ACCESSIBILITY.md` (repo root) are published, user-facing statements — keep them true.** The privacy policy asserts SnowRaven collects nothing and runs no server: if any feature ever adds analytics, telemetry, crash reporting, an account, or a new third-party service, update `PRIVACY_POLICY.md` in the same change (a stale privacy policy is a liability, not just a doc bug). Update `ACCESSIBILITY.md` when accessibility behavior changes. Neither is bundled into the app, so they don't require a version bump on their own.
