# SnowRaven media-embed conventions

Moved verbatim from CLAUDE.md (2026-08-26 context restructure). This file auto-loads when a session works on files matching the `paths` above; for related work that starts elsewhere, read it in full before changing anything it governs. Its rules carry the same force as CLAUDE.md.

- **An inline Macaulay Library media embed is `macaulaylibrary.org/asset/<id>/embed` in an iframe — IDENTICAL for photo/audio/video (only the id + player height vary) — and its catalog id is `^\d+$`-guarded + `encodeURIComponent`-wrapped before it reaches the `src`.** The Named Birds media (`components/NamedBirdMedia.tsx`, v0.5.66) and Species Detail both use this. Load embeds ON DEMAND (only when the containing row/section is open, and bound the number of concurrently live players — Named Birds caps an initial batch of 6 behind a "Show more"). Reuse the shared `.sr-media-grid` / `.sr-media-item` / `.sr-media-iframe` CSS (already responsive to 1-column ≤640) with per-format height modifier classes — never inline breakpoint styles. A media catalog id from the ML export is parser-guaranteed digits-only; still pass it through `mlAssetUrl` (which encodes it) for any link-out.
- **Cornell runs an Anubis bot gate in front of `macaulaylibrary.org`, and a mounted player CANNOT pass it — the gate is detected out-of-band and the frame is never mounted while it is up (v0.5.76).** The interstitial needs `Secure; SameSite=None; Partitioned` cookies a cross-site iframe cannot hold, so it renders Cornell's "Missing feature Cookies" card. **The existing give-up timer and `onError` are structurally blind to this** — the interstitial is a same-status HTTP **200** that fires `onLoad` — and `fetch` cannot see it either (no CORS headers on the endpoint), so detection MUST leave the page through the transport seam: `GET /media/embed-status` (`backend/routers/media.py`) with its desktop twin `lib/tauri/mediaService.ts`. **Keep the twins in lockstep**: the same browser User-Agent (the gate only challenges browser-shaped requests — with a default agent the real page comes back and the probe reports "not gated" while every viewer is blocked), the same two independent markers (the interstitial's markup ids AND its `anubis` cookie name, so a change to either alone cannot blind the probe), and the same result shape. Match the page as SERVED, never the visible "Missing feature Cookies" text — that string is not in the HTML, the challenge's own script writes it later. `lib/mlEmbedGate.ts` owns the client side: session-scoped, single-flight, and **NOT** in `CACHED_GET_PATHS` (one caching layer per call). Two properties are load-bearing and must survive any refactor: it **FAILS OPEN** (any probe failure resolves to not-gated, so a probe that cannot run never hides working media), and the signal is **GLOBAL, not per-viewer** (nothing in the page can observe a cross-origin frame's outcome), which is what lets it self-heal with no code change when Cornell lifts the gate. Do NOT "fix" this by rendering media directly from `cdn.download.ams.birds.cornell.edu` — that path works and was deliberately rejected (see DECISIONS.md v0.5.76): this project works alongside Cornell's free services, not around their protection.
- **Every inline-media surface consumes the one hydrated App-root eligibility gate before it can mount player machinery (v0.5.72).** `useEmbeddedMediaPreference` owns the durable `disableEmbeddedMedia` setting; its unresolved `null` state and saved `true` both mean `embedAllowed === false`, while only the exact hydrated value `false` opens the gate. Pass `embedAllowed` through any future embed surface and keep `MediaFrame` in `components/MediaEmbed.tsx` as the sole iframe constructor, with an explicit eligibility prop as defense in depth. Disabled content uses the shared neutral `EmbeddedMediaDisabled` status with the exact sentence “Embedded media is disabled in Settings.”; render it only where embed-backed content exists, never a shimmer/error/offline fallback, and keep local metadata plus direct links. The setting itself stays off by default and uses the storage seam, never raw `localStorage` or component-local persistence.
- **A slow/broken/offline inline embed degrades via a NON-DESTRUCTIVE overlay — keep the iframe MOUNTED for its lifetime and flip only a `position:absolute` fallback over it; NEVER unmount the frame on a timeout (v0.5.66).** The naive give-up timer that tears down the iframe was caught in review: it kills a slow-but-working embed and latches a permanent "unavailable" state with no recovery. The correct pattern (`MediaFrame` in `NamedBirdMedia.tsx`): a give-up timer (`EMBED_GIVE_UP_MS`, 20s) and the iframe's `onError` only REVEAL the fallback overlay (the item's metadata + a "View on Macaulay Library" `OutboundLink`), and a late `onLoad` CLEARS the latch so a slow embed recovers in place. Offline→online recovery is an online-keyed remount (`key={online ? 'online' : 'offline'}`), NOT `setState`-in-effect. The offline/failed state ALWAYS keeps the item's local metadata (date + `ChecklistLink` + link-out) — it is never a broken or blank frame. Online status comes from the shared `useOnline` hook (`lib/useOnline.ts`, extracted from the `SnowMap` `navigator.onLine` + `online`/`offline`-listener pattern): read `navigator.onLine` in the state initializer and event handlers ONLY, never in a render body or memo (render-purity). NOTE: as of v0.5.71 these frame/fallback/shimmer primitives are SHARED in `components/MediaEmbed.tsx` (constants split to `lib/mediaEmbed.ts` so the component file stays component-only for react-refresh), used by BOTH Named Birds and Species Detail's Recent Media (`components/RecentMediaEmbed.tsx`, extracted so it's unit-testable without SpeciesDetail's maplibre deps). Species Detail's Recent Media also shows an info + attribution row beneath each player — capture date, a Macaulay Library link that opens that asset (its required credit + a way to view/play it), and the eBird checklist — and uses ONE uniform full height for all three formats (`.sr-media-iframe--recent`, 230px / 280px-phone): the compact per-format audio height (116px) clips the Macaulay audio player's controls under the frame's `overflow:hidden`. `MediaFrame` takes a **REQUIRED** `compact` prop so each caller picks its fallback density — required, not defaulted, because a default that encodes a display decision is invisible at the call site and silently hands the next caller a choice they did not make. **The discipline belongs where the display decision is MADE, not on every forwarder in the chain (v0.5.80).** A component that merely passes the prop through to a host that has already decided may default it; making it required all the way up just relocates the same invisible choice into a wrapper's call site and forces unrelated callers to answer a question they have no stake in. Pin Share is the reference: `compact` is required on `SharePin` and `SharePopup` (which render it) and defaulted on `SightingsMap` (which only forwards it). **The Macaulay audio player needs ~230px to expose its transport controls; anything near the old compact 116px clips them under the frame's `overflow:hidden`, so audio anywhere in the app gets the full height (v0.5.75 gave Named Birds' audio the same 230px / 280px-phone as Species Detail).** Named Birds keeps its OWN per-format classes (`.sr-media-iframe--photo/--video/--audio`) rather than adopting `--recent`, so the two surfaces stay independently tunable even where their current values agree; both call sites now pass `compact={false}`. Reuse these shared primitives for any inline ML embed; pick the tile height per surface. **A caller that reaches `MediaFrame` down two independent paths (one it renders directly, one the shared child renders internally) must pass the display choice at BOTH, and each path needs its own test — a single combined test passes on a half-fix.**
