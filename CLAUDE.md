It holds the standing rules every builder follows, in short form, and each rule names where its full story lives: `DECISIONS.md` (post-mortems, by version), `.claude/rules/*.md` (path-gated detail, backed by guard tests), the `snowraven-release` skill (ship mechanics) and `RELEASE_LEDGER.md` (the per-version App Store and Android record). ## Device boundary (user direction, 2026-09-26)

- **Agents work on the developer Mac and its local simulators only. Never discover, query, pair, install on, or otherwise access any physical, production, or personal device, including Hydra and Telesto. Do not access other machines for testing or infer what devices the user has.** If a physical-device check is needed, ask the user to perform it with exact steps and record only their reported result. The launch check of the exact uploaded build before an App Store submission is such a user-performed check; it is not a condition for uploading to TestFlight. This overrides older device-testing language anywhere else.
- **Automated tests are the usual verification path.** Do not add manual platform, device, trace or accessibility sweeps to routine QA on your own. An approved acceptance criterion that is not covered and that the user defers is marked Partial and left deferred; do not keep asking or treat it as passed.
- **When a fix must work on a device no agent may touch, a readout comes before a third fix, and a check that is not the app comes before either (v1.0.40).** After two blind fixes fail, ship a readout of what the platform itself reports (Settings' **Copy iCloud details** is that readout for sync), and early on ask the user for a one-minute check that does not involve the app: a device-level stall reads exactly like an app defect from the app's own status line. DECISIONS.md, v1.0.40.

## Versioning

- Version is tracked in `frontend/package.json` (semver; patch by default, never minor or major unless explicitly told).
- **A version bump is a SIX-file set, all asserted by guards:** `frontend/package.json`; `src-tauri/tauri.conf.json` (the desktop bundle version and the updater's check, plus `bundle.android.versionCode` as `major * 1000000 + minor * 1000 + patch`, `androidVersionSource.test.ts`); `CHANGELOG.md`; `website/index.html` (the `version-pill` text AND its `aria-label`, plus the `footer-version` line, asserted by `it('the website version pill and footer follow the app version')` in `frontend/src/lib/icloudKeysPublishedClaims.test.ts`, a repo-wide check housed in a feature-named suite); the three Fastlane changelogs `fastlane/metadata/android/en-US/changelogs/<10 * versionCode + 1, 2, 4>.txt` with the same text and none under the unsplit code (`fastlaneMetadata.test.ts`; published copy, so it waits for the user's yes, and it must exist AT the tag because F-Droid reads the folder there); and the in-repo F-Droid recipe `pipeline/android-release/fdroid/com.dtgibson.snowraven.yml` (`CurrentVersion`, `CurrentVersionCode` as the `+ 4` code, and the three per-ABI `Builds` entries, `fdroidRecipe.test.ts`). The website leg's rule file is path-gated on `website/**`, so a prep session touching only the manifests never loads it, which is how 1.0.14 shipped with the pill stale and the suite red for five commits. Known weakness: the pill guard is a `toContain` over the whole file, so a corrected pill with a stale footer still passes (ROADMAP).
- **Always bump the version and update the changelog when adding a feature or fix**, even if the user does not ask. A dev-only or toolchain change that does not affect the shipped bundle (a dev-dependency audit fix, a lockfile refresh, test-only tooling) needs no bump, changelog entry, tag or release: commit it to `main`.
- **After pushing a version bump, run `./release.sh`** to build, notarize and publish the macOS app, sign the updater bundle and generate `latest.json`. **Never `gh release create` directly** for the desktop app: the in-app update check depends on `latest.json` being in the release assets. Credentials stay local. **Tauri v2 macOS updater:** `downloadAndInstall` replaces the bundle in place synchronously; afterwards call `relaunch()`, never `exit(0)`, which leaves the user with no running app.
- **Release rhythm:** bump → commit → push `main` → push the `vX.Y.Z` tag (starts Windows and Android CI; F-Droid builds its own APK from it) → CI green → `./release.sh` → sign the Android APK, get the user's device check, attach it → TestFlight build of the SAME version → submit that build for App Store review. **A release goes to ALL available platforms, every time** (user direction, v0.5.78); it is not done until every leg has shipped and been submitted. The full runbook is the `snowraven-release` skill.
- **VERIFY THE APP STORE LEG AGAINST APP STORE CONNECT AT EVERY SHIP; NEVER INFER IT FROM THE REPO, AND WRITE EVERY VERSION'S DISPOSITION IN `RELEASE_LEDGER.md` IN THE SAME SHIP.** Three releases (1.0.15, 1.0.16, 1.0.18) shipped a VALID TestFlight build and never got a store version record, and each was found only by querying ASC at the next ship; a ROADMAP item and a rule in this file each failed to stop it, so do the query (`GET /v1/apps/{id}/appStoreVersions`, plus every TestFlight train) rather than adding a reminder. A version that ends with a VALID build and no record of its own can be a **rollup** into the next version, a **deferral** behind one in review, a **TestFlight-only** release by the user's direction, or a **skip**, and ASC cannot tell them apart: the written sentence is the only thing that does. **A version with no record and no sentence in the ledger is a skip.** When you roll one up, defer one or withdraw and resubmit, add it to the ledger in that ship, naming both versions and the record and submission ids; the ledger list has been found incomplete twice, which is the failure it exists to prevent. On a new version record, read EVERY listing field back against `appstore/LISTING.md` rather than assuming it carried: the promotional text has arrived empty on ten new records. The ledger's per-ship entries, the rollup list and the three genuine skips are in `RELEASE_LEDGER.md`.
- **THE ANDROID LEG GETS THE SAME PER-VERSION SENTENCE IN `RELEASE_LEDGER.md` (first Android ship 1.0.53):** the F-Droid state in one of seven words (not yet submitted; merge request open; included and this tag not yet built; included and built, not yet published; included and this tag picked up; superseded on F-Droid, naming the version that carries it; deferred, with the reason), read from fdroiddata's recipe, from F-Droid's build log for each code and from whether F-Droid has published it (the recipe and the published list alone conflated the two middle states and missed a pruned version; the 2026-10-22 readout in `RELEASE_LEDGER.md`), and the GitHub APK asset with its signer SHA-256 (`42a3576e445bda4a994793f2ffa056663113275c9805eb2f6cffdc252375996a`, which every APK must print), published after the device check or deferred in writing. SnowRaven has been on F-Droid since 2026-10-14; the update bot picks up new tags, so a release sends nothing to fdroiddata unless the recipe's build steps or toolchain pins change. The user owns no Android device, so every Android device check is Partial on emulator evidence by standing decision. Mechanics: the release skill's Android section.
- **A released version string's pre-release train is closed, so there is no TestFlight-only path against it (2026-09-15).** Once a record is `READY_FOR_SALE`, Apple refuses every new build on that version (`altool --validate-app` errors 90186 and 90062). An iOS-only fix has exactly two routes: a full version bump with the whole all-platforms rhythm, or riding the next release. Keep `--validate-app` before `--upload-app` unconditional; `iosSceneManifest.test.ts` refuses an iOS bundle version that leads `frontend/package.json`.
- **A green suite, green CI and a simulator screenshot are not evidence that an iOS build launches, so the user's device install of the exact uploaded build precedes the App Store submission (v1.0.31).** The 1.0.31 build crashed on launch on a fully green commit, from a release-profile-only use-after-free in tao that no debug or simulator check can see; `altool --validate-app` checks icons and entitlements, not whether the app runs. The one-line fix is vendored at `src-tauri/vendor/tao`, and since v1.0.36 that vendored crate also carries the widgets' cold-start URL, so its removal condition is the one in `src-tauri/vendor/tao/VENDORED.md`, not "a newer tao". DECISIONS.md, v1.0.31 and v1.0.36.
- **Cross-platform Rust deps live in `[dependencies]`, never in a platform block.** A crate real on both Apple platforms goes in the `cfg(any(target_os = "macos", target_os = "ios"))` block, an Apple crate needed only on iOS (`objc2-ui-kit`) in its own `cfg(target_os = "ios")` block, never the android|ios mobile block: the cfg says where a crate is real, not which build pulls it (`tzf-rs` mis-scoped to macOS broke Windows; v1.0.11).
- **iOS app icons are fully OPAQUE in BOTH `src-tauri/icons/ios/` AND the committed `AppIcon.appiconset/`** (altool 90717 otherwise; desktop icons may keep alpha). Flattening is in the release skill.
- **NEVER POINT `xcodegen` AT `src-tauri/gen/apple/project.yml`, not even as a probe (v1.0.42):** the app target's `info:` block makes it rewrite `snowraven_iOS/Info.plist` with defaults that drop both version strings, `ITSAppUsesNonExemptEncryption` and the background-mode keys. A probe runs against a copy in scratch; an intentional regeneration follows the release skill's keep-aside-and-restore procedure. A target that needs another target's sources names that folder once, narrowed with `includes`, never a nested path (`iosAlertsManifest.test.ts`).
- **A launch-lifecycle or scene-manifest change is verified with a SCREENSHOT, never a process check (2026-09-15).** With the manifest present but `UIApplicationSupportsMultipleScenes` false, the app stays alive, loads the page and shows a blank screen; `true` is the only configuration that renders, and the manifest must name a real `TaoSceneDelegate` configuration, not Tauri's empty dict (tauri #15719). The manifest lives in three files pinned identical by `iosSceneManifest.test.ts` (`gen/apple/snowraven_iOS/Info.plist`, `gen/apple/project.yml`, and `src-tauri/Info.ios.plist`, the one that survives `tauri ios init`). The manifest was the TRIGGER of the 1.0.31 crash, never the fault; do not weaken the guard. DECISIONS.md, v1.0.31.
- **A guard that must run in CI parses Apple plists in pure JS** (ubuntu has no `plutil`), strips a config file's comments before scanning it, and asserts the stamped iOS plist "never leads" `package.json` rather than equality, because `main` legitimately sits with the plist behind the app version for the length of every ship. `iosSceneManifest.test.ts` is the reference.
- **For ANY release, packaging, updater, TestFlight, App Store, Android APK or F-Droid work, invoke the `snowraven-release` skill** (`.claude/skills/snowraven-release/SKILL.md`). Do not ship from this file alone.

## Pipeline overview

This project uses the Weft framework. Run /new-feature to start a new feature.

- **A feature with a visible surface gets a live look at the BUILT app before the deploy gate, and what that look finds goes back to The Designer** rather than shipping as a post-ship fix (v1.0.29). jsdom, a stylesheet scan and a fixture cannot measure a drag that re-snaps or a view that wants prominence.
- **A decision not to act on a measured difference is written down as a decision**, with the evidence, what would reverse it, and the exact fix with its location (2026-09-15): a silent non-action and an oversight leave the same evidence. The `.sr-combobox-list` scroll-anchoring difference in DECISIONS.md and ROADMAP.md is the shipped instance.
- **This repo's Weft pipeline tracks SnowRaven only.** Issues from other projects (e.g. snowraven-mini) go to the user in chat, never into pipeline state, ROADMAP.md or the record files.

## Conventions

### Ports
- Backend runs on port **1620** (not 8000); the Vite dev server on **5173**.
- Vite proxies the backend route prefixes to `http://localhost:1620` (`frontend/vite.config.ts`). **When you add a backend route, add its prefix to that proxy**, or the web-dev path hits Vite's SPA fallback and the call silently fails under `npm run dev`.

### Environment
- API keys live in `backend/.env`, never committed. Required: `EBIRD_API_KEY`, `OPENWEATHER_API_KEY` (subscribed to "One Call by Call").

### Running locally
```
cd backend && uvicorn main:app --reload --port 1620
cd frontend && npm run dev
```

### Running tests
```
cd backend && .venv/bin/python -m pytest tests/ -v
```
The backend interpreter is `backend/.venv`; a bare `python` is not on PATH, so `python: command not found` is a PATH miss, not a failure.

### Production build
```
./start.sh
```
Builds `frontend/dist/` and starts uvicorn on 1620, which serves the built frontend.

### Standing rules and lazy-loaded convention files

The detailed conventions live in `.claude/rules/*.md`. Each auto-loads when you work on files matching its `paths` frontmatter; if your change is related but starts from other files, READ the relevant file first. Never work from these summaries alone, and never weaken a rule without reading its full entry; most are backed by guard tests.

**WHEN A CHANGE ADDS, MOVES OR TWINS A FILE A RULE GOVERNS, EXTEND THAT RULE'S `paths` IN THE SAME CHANGE (v1.0.32).** A rule gated off the file it governs silently stops loading, which is indistinguishable from the rule being absent. Two shapes recur: a twinned rule (Python route and its `lib/tauri/` service) must gate both halves, and a rule that names a canonical implementation must have it inside its own gate, so relocating code is a two-part edit. **A schema that declares a new scan over user-file text, or a loop driven by a number read from it, names the `security.md` glob the build adds and states the clamp's measured cost per draw and per re-draw** (v1.0.52, recurred v1.0.54: the obligation is triggered by the scan, not by a new file, and it is the gate on the module that HOLDS the scan). The citation-matches-no-glob check is mechanically possible and not yet built (ROADMAP).

- **UI** (`.claude/rules/ui.md`). Every color via `var(--sr-*)` tokens in both themes; layout made responsive by classes, never inline styles; WCAG 2.1 AA at 320px and 200% text scale; the brand mark is `RavenGlyph`; **every app-owned button and href link renders through the native `Button` or `Link` primitive**, which supplies the `tabIndex={0}` WebKit needs (`lib/tabOrderCoverage.test.ts`); a DOM id or ARIA IDREF is keyed on an INDEX, never on user file content (v1.0.21); a size threshold derived from a mockup's container is re-measured against the real container in the built app (v1.0.50).
- **Maps** (`.claude/rules/maps.md`). All maps render through `<SnowMap>`; maplibre and the county geometry stay OFF the entry chunk (`entryChunk.test.ts`); a tile-provider change is a `PRIVACY_POLICY.md` change.
- **Bird names** (`.claude/rules/bird-names.md`). Every user-facing bird name renders through `<BirdName>`; countability goes through `isNonCountableForm`; ML links build on `ML_CATALOG_BASE`.
- **Testing** (`.claude/rules/testing.md`), read before writing or judging any frontend test, CSS fix, performance claim or guard. `vitest` and `eslint` are NOT the pre-push gate: run `npm run build` (at least `npm run typecheck`) before pushing; never `npm audit --offline`; **after a commit that edits text another guard pins word for word, run the FULL vitest suite** (v1.0.53). An agent's editing tools can turn a written escape into its literal character (three times); grep for the literal, and a module handling non-ASCII data carries a source row asserting its code holds none. The methodology rules below are stated in full in that file and in DECISIONS.md at the version named:
  - **Replacing a predicate owes its symmetric difference in both directions, filled from a measurement over a generated corpus, with the seam's own failure return as the first row** (v1.0.32; four fixes in one bundle each reintroduced the bug they closed in the unargued direction).
  - **An agreeing wrong number is invisible to cross-transport parity checking**, so derive the assertion structurally (the output from an input with the bad element equals the output with it removed) or against an oracle outside both runtimes (v1.0.32).
  - **Guard quality (v1.0.33):** a `testTimeout` cannot interrupt a synchronous loop, so a hang guard walks a capped replica first; a scan for a code shape the codebase also names in a comment strips comments and proves the strip; a guard's failure message claims no more than its assertions check; a whole-file phrase assertion is measured against HEAD for pre-existing occurrences; two declarations of one number are compared to each other, never restated; and a shared register landing on a repaired surface pins the PROPERTY at that surface as a resolved cascade, not a declaration's presence.
  - A guard never reads a gitignored per-run file unconditionally (v1.0.12); a timing-ratio suite is judged only with nothing else compiling; a deliberately expensive guard states its own `testTimeout` (vitest's 5,000 ms default took `main` red at 6% headroom); a same-run quotient reads CPU time through `frontend/src/test/cpuTiming.ts`, not the wall clock (v1.0.40).
  - A null result is per-scrollport and per-engine, never inherited by analogy, and Chromium exposure says nothing about WebKit (2026-09-15).
  - An async test waits for the exact downstream observable its next assertion consumes, never a sleep; a key pressed into a `ModalDialog` waits for focus inside the dialog (v1.0.25, v1.0.40, v1.0.46).
  - A count of calendar days between two local midnights ROUNDS the millisecond difference, and each such site gets a row pinned to a daylight-saving zone (v1.0.39, v1.0.51; `lib/mapExplorerFormat.test.ts`).

On Android no third-party iframe is mounted, because wry injects the IPC bridge into every frame (v1.0.53); Macaulay Library media renders as its link card through `allowInlineMediaFrame()` in `lib/platformGates.ts`, and any new embed surface goes through the same gate.
- **Security standing checks** (`.claude/rules/security.md`), applied to ANY change touching hrefs, **any scan over untrusted text (regexes and ordinary primitives alike)**, routes, outbound requests or lookup tables keyed by external strings; a security review reads the file. ### Desktop app seams

Permanent architectural seams route all platform-sensitive operations. Use them in new code; do not bypass them. Each rule's measurement and post-mortem is in DECISIONS.md at the version named.

- **Transport:** `transport.get()` / `transport.post()` from `frontend/src/lib/transport.ts` for all outbound HTTP. In Tauri mode `TauriTransport` routes each API path to a TypeScript service; in web/Pi mode `WebTransport` delegates to the Python backend. A failed file-status lookup is UNKNOWN, never EMPTY: both seams keep the difference between an absent record and an unreadable status, and consumers route the latter to their load-error state, never setup guidance (v1.0.25).
- **Caching layers, picked by lifetime.** `CACHED_GET_PATHS` in `transport.ts` is the ~90 s repeat-call cache; `replayStore` is the live-first offline replay of a last-loaded result; a long-TTL persistent network cache follows `lib/countyCompletenessCache.ts`: a storage-seam document with an in-memory mirror, TTL-gated reads, per-entry validation on load (malformed dropped, never thrown), a strict entry cap plus a `JSON.stringify(data).length` payload budget with FIFO eviction, an in-flight dedupe Map, errors never cached, offline stale reads served. One caching layer per call: a path served by a durable cache stays OUT of `CACHED_GET_PATHS`. Three rules from the later instances: a durable cache computes AND VALIDATES its derived fields at ONE chokepoint, the module's own `dedupedFetch`, through the same validator the load path uses (`hotspotActivityCache`, v0.5.92; `checklistProjectsCache`, v1.0.5); check a FIFO against the order its producer actually writes, and evict by a comparator when insertion order does not track age (`countyDayObsCache`, v1.0.39); and a cache may hold two stores with OPPOSITE retention, FIFO where an eviction costs one redundant request and fill-then-stop admission where it would destroy a paid-for answer, gated on the container's own size and measured at capacity+1 as work done (the escapee document, v0.5.87). A denormalized published classification field may live in such a document only while the raw evidence stays the source of truth and the passive reader CONFIRMS it against its own observations (`ProvenanceSnapshot.excludedNames`, v0.5.87). `replayStore` has no per-entry validation on load and a `bytes` guard that admits negatives, both bounded by its 300-entry cap (ROADMAP).
- **A durable store inside a settings document is capped by the web/Pi settings route (`_MAX_BYTES`, 16 MiB, `backend/routers/settingskv.py`), not by what an export needs (v1.0.57):** past it the write fails silently with a swallowed 413. Each cap is the largest power of two whose worst-case document fits (`settingsRouteBudget.test.ts` builds it through the store's own load path); a store that needs more moves to its own document.
- **A bundled build-time asset and a persisted runtime cache are different trust boundaries (v0.5.89):** a Vite-inlined JSON import is defended at build time (a generator that fails closed) and CI time (equivalence against an independent re-derivation, an entry-chunk size bound), not with runtime validation; `ebird-countability.json` is the reference, and `build-taxonomy-history.mjs` fails closed unless each year's splits and lumps equal eBird's announced totals (v1.0.41). If such an asset becomes runtime-loaded, the cache rule applies in full.
- **A durable store keyed on USER-FILE CONTENT registers in `lib/clearDerived.ts` (`purgeDerivedOnClear`), the one teardown called from Settings' delete and both iCloud clear paths, with `cacheInventory.test.ts` pairing each store's exported purge to a row (v1.0.14).** The purge is a PRODUCTION export, never a `_reset*ForTests` seam; a store registers on where its KEYS come from, not its values (`county-completeness-v1` is in, `hotspot-activity-v1` is out); purge on CLEAR only, never on REPLACE; the purge SUPERSEDES in-flight work (cancel the flush timer, stop a parked `ensureLoaded` adopting the old document, refuse a write from work begun before the purge), with the purge-generation capture at the FETCH CHOKEPOINT before the request, handed in as a required argument where the chokepoint is outside the store (a native IPC transfer counts, v1.0.40); and a best-effort teardown returns what it could not do. `clearDerived.ts` carries no static imports, reaching every store through `import()`, so `countyCompletenessCache.ts` stays off the entry chunk. **An in-memory derivation is outside this registry by design** (v1.0.20): the house answers are a `WeakRef` on the source (`lib/speciesIndex.ts`) or, for a worker holding a copy, a stated termination chain with a test asserting the terminate.

### Desktop storage (Tauri)

`TauriStorage` in `storage.ts` uses **`tauri-plugin-fs` with `BaseDirectory.AppLocalData` for everything**, under `AppLocalData/data/`:

| File | Contents |
|---|---|
| `data/api-keys.json` | API keys and, since v1.0.12, a per-key `meta` (change time and origin, or a cleared marker) validated on every read |
| `data/settings.json` | App settings; the `icloud-sync` object is the one place sync state lives, and anything new about sync joins it as one link per save |
| `data/metadata.json` | Uploaded file metadata |
| `data/ebird-backup.csv`, `data/ml-export.csv` | The two data files |
| `data/barcharts.json`, `data/barcharts/<regionCode>.txt` | The bar-chart manifest (a SHARED document on its own `docChains` key, v1.0.39) and one eBird bar-chart file per US county, synced per county by iCloud Sync (v1.0.40); not a derived store |
| `data/county-day-obs.json` | The Targets tab's per-(county, day) eBird answers: its OWN document with its own ordered writer, registered in `clearDerived.ts`, synced as one snapshot per device (v1.0.39, v1.0.40) |

Every write calls `mkdir(DATA_DIR, { recursive: true })` first.

**Shared-document writes serialize on a per-document promise chain (v1.0.9).** Every read-modify-write on a shared JSON document runs as a link on that document's chain in `TauriStorage` (`docChains`, keyed by the closed set of path constants); a new writer joins the chain, a link never awaits another chained op, and a failed link rejects only its own caller. Unserialized read-modify-write is the lost-update clobber that erased the projects ledger (DECISIONS.md, v1.0.9); a future store that rewrites a shared document owes the same mechanism and an interleaving test shaped like `storageWriteSerialization.test.ts`.

**SINGLE-WEBVIEW INVARIANT (the v1.0.9 entry, extended 2026-09-15; the reversal condition lives here).** That serialization is per-JS-CONTEXT: `docChains`, the two ordered writers (`replayStore`'s and `countyDayObsCache`'s `writeThrough`) and the three purge generations (`replayStore.ts`, `exoticProvenanceCache.ts`, `countyDayObsCache.ts`, moved by `clearDerived.ts` through `import()`) are module-scoped JavaScript state, so they protect the shared documents ONLY while the app runs exactly one webview. What keeps that true is a CHOICE, not a handler: `src-tauri/src/lib.rs` ends at `.run(tauri::generate_context!())`, and `Builder::run` installs Tauri's own no-op callback, so a second iPadOS scene (`UIApplicationSupportsMultipleScenes: true`) never constructs a second webview; `RunEvent::SceneRequested` appears nowhere under `src-tauri/src`. All three capabilities are scoped `windows: ["main"]` as the backstop. Since v1.0.51 the one window is built in code in the one setup closure every target shares (`"create": false` in `tauri.conf.json`), and **`Builder::setup` keeps only its LAST closure, so a platform-specific setup step joins that shared closure behind a cfg, never a `.setup` of its own** (DECISIONS.md, 1.0.51). **Reversal condition: if a second window or webview is ever created on any platform, all three protections stop being sufficient and the shared documents need cross-context exclusion, a native-side lock or a single owning context, never a promise chain.** Real iPad multi-window support and the deferred Tauri 3 upgrade would each dissolve it. Six notes carry the marker phrase `SINGLE-WEBVIEW INVARIANT` (`storage.ts`, `replayStore.ts`, `clearDerived.ts`, `exoticProvenanceCache.ts`, `countyDayObsCache.ts`, the keeper in `lib.rs`), each pointing back here, and `singleWebviewInvariant.test.ts` asserts the marker at all six, the keeper's shape, and that `lib.rs`'s `from_config` is the only window or webview constructor in `src-tauri/src`.

**`data/replay.json` and `data/county-day-obs.json` each have an ordered writer of their own (`writeThrough`) and deliberately do NOT join `docChains` (v1.0.14, v1.0.39).** Each is its own file with a single writing module, so there is no read-modify-write to clobber, but one module is not one write at a time: the next write is not CALLED until the previous one settles, and the purge's delete rides the same chain. The structural reason this suffices is that a write is reachable only from a flush requiring a completed `ensureLoaded`, or from the purge, which awaits it. A re-load-after-purge, a second writing module, or any read of the file that feeds a write removes that reason, and the document then owes the full `docChains` treatment.

**Do not use `localStorage`** (ephemeral in WKWebView, cleared on relaunch) **or the system Keychain** (needs entitlements this app lacks, fails silently). **Persist all UI settings through the `storage` seam**; the web/Pi path may read `localStorage` synchronously inside the seam for a flash-free first paint, but the seam is the source of truth (the tab-layout post-mortem, DECISIONS.md).

**A shipped default that users may have a saved copy of migrates at read time, and only from the default it immediately replaced (v1.0.19):** keep the previous default as a NAMED CONSTANT, compare after normalization, preserve the hidden set, write nothing back, and migrate exactly one generation; "saved CUSTOM layouts preserved" is the formulation. **Where the stored value is written whole on any change, every write from the new build carries a version marker and only an UNMARKED previous default migrates** (`calendarOverlays.ts`, `CALENDAR_OVERLAYS_VERSION`, v1.0.40), or a deliberate choice of the old default is migrated away on every launch.

**Native-side state written by native code sits outside the `storage` seam, and that is not a violation (v1.0.13, v1.0.42).** Window geometry (`tauri-plugin-window-state`, `.window-state.json` in `app_config_dir()`, applied before the first frame; do not "fix" `src-tauri/src/window_geometry.rs` into the seam) and the iOS Alerts documents (`alerts/settings.json`, `state.json`, `inbox.json` in the App Group container, written only by one Swift actor and reached by the webview only through the `alerts_*` commands) take no `docChains` link, no seam route and no sync. Such a document stays out of the webview's granted `fs` scope only while its name begins with a DOT, and every native read of a file outside the sealed bundle owes the `record_text_at` regular-file-plus-size-bound treatment (`.claude/rules/security.md`).

**Native window facts, measured (v1.0.13, v1.0.59).** `available_monitors()` returns an EMPTY list on macOS 26 (`CGGetActiveDisplayList` reports zero; `primary_monitor()`, `current_monitor()` and `NSScreen` still work), so `window_geometry.rs` reapplies position itself. `set_size`/`set_position`/`maximize` are asynchronous on macOS, so at `setup()` decide from the SAVED record, never from `is_maximized()`. Prefer a shared compile-time constant to a runtime `Manager::state` lookup, which panics when unmanaged and under `panic = "abort"` aborts during `setup()` with no window shown; `let _ = fallible()` swallows `Err`, not panics. **On iOS no code calls a monitor lookup:** on the iPhone Duo's inner screen tao's `current_monitor()` and `available_monitors()` abort (tao #1373), so monitor code stays in `#[cfg(desktop)]` modules and `iosMonitorLookups.test.ts` fails a lookup anywhere else.
