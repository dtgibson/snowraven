# CLAUDE.md

This file is auto-loaded by Claude Code at the start of every session.
It holds pipeline conventions, tool rules, and project-specific
decisions that all builders must follow.

## Versioning

- Version is tracked in `frontend/package.json` (semver, patch increments for small features/fixes, minor for larger features)
- **Bump BOTH `frontend/package.json` AND `src-tauri/tauri.conf.json` to the same version.** `tauri.conf.json` is the source of the desktop *bundle* version (macOS `CFBundleShortVersionString`, Windows installer version, and the in-app updater's version check) and does NOT read from `package.json`. Forgetting it ships a mislabeled bundle and breaks the updater; `release.sh`'s version guard catches the macOS side, but the Windows installer is built by CI from `tauri.conf.json` at the tagged commit, so the tag must point at a commit where both are bumped. (Patch-only by default — never minor/major unless explicitly told.)
- `CHANGELOG.md` at the repo root must be updated with every version bump
- **Always bump the version and update the changelog when adding a feature or fix**, even if the user does not ask
- **A dev-only / toolchain change that does NOT affect the shipped bundle — a dev-dependency `npm audit fix`, a lockfile refresh, test-only tooling — does NOT require a version bump, changelog entry, tag, or release.** It produces a byte-identical app, so commit it straight to `main`; it reaches the release machine on the next `git pull`. The "always bump" rule above is about user-facing features and fixes. (Precedents in `DECISIONS.md`: the `dev-dependency-cleanup` `undici` patch, and the Node-25 release-tooling fix — both "no version bump.")
- **After pushing a version bump, run `./release.sh`** to build, notarize, and publish the macOS desktop app. This script creates the GitHub release (or uploads to an existing one), signs the updater bundle, and generates `latest.json` for in-app update detection. Credentials (Apple API key, notarization) stay local — never stored in GitHub.
- **Do not use `gh release create` directly** for desktop app releases — always use `release.sh` so the signed binary and `latest.json` are included. The in-app update check depends on `latest.json` being present in the release assets.
- **Tauri v2 macOS updater mechanism:** `downloadAndInstall` performs synchronous in-place bundle replacement — no shell script, no sleep, no `open -a`. The `.app` bundle is fully replaced on disk before the Promise resolves. After `downloadAndInstall` returns, call `relaunch()` (not `exit(0)`). `relaunch()` spawns `current_exe` (now the new binary) and exits cleanly. `exit(0)` just terminates the process with no relaunch, leaving the user with no running app.
- **macOS ships a UNIVERSAL binary (v0.5.5+).** `release.sh` builds `--target universal-apple-darwin`, so one DMG (`SnowRaven_<ver>_universal.dmg`) and one updater bundle (`SnowRaven.app.tar.gz`) run on both Apple Silicon and Intel. With an explicit `--target`, Tauri nests the bundle under the target triple — `$CARGO_TARGET_DIR/universal-apple-darwin/release/bundle/...`, not `release/bundle/...`. The build needs BOTH Rust targets installed (`rustup target add aarch64-apple-darwin x86_64-apple-darwin`); `release.sh` preflights this and aborts with the install command if either is missing.
- **`release.sh` Intel arch:** `latest.json` maps BOTH `darwin-aarch64` and `darwin-x86_64` to the one universal updater bundle (same URL, same signature). The Intel key must be exactly `darwin-x86_64` — Tauri's `updater_arch()` returns `"x86_64"` on Intel, so mapping it to `"x64"` means Intel users never see any update as available.
- **`createUpdaterArtifacts: true` is required in `tauri.conf.json`** — `@tauri-apps/cli` v2.11.2+ defaults this to `false`. Without it, `tauri build` creates the `.app` and `.dmg` but skips the `.app.tar.gz` updater bundle entirely. The setting must be in `bundle.createUpdaterArtifacts`.
- **`release.sh` version guard:** After the build, `release.sh` reads `CFBundleShortVersionString` from the bundle's `Info.plist` and aborts if it doesn't match `tauri.conf.json`. This catches stale-artifact issues before anything is uploaded to GitHub.
- **The release machine MUST be on the pinned Node (`.nvmrc` = 24; `frontend/package.json` `engines.node >= 20.19`), and `release.sh` is self-healing (mac-release-build-blocked post-mortem).** A bleeding-edge/non-LTS Node (e.g. 25) crashes `npm ci` with npm's internal `Exit handler never called!` (npm/cli#8766) — this blocked the 0.5.45 release for days on a Mac that had drifted to Node 25, while the build VM (Node 24) and Windows CI (Node 20) installed the identical lockfile fine. `release.sh` now runs `npm ci` ITSELF at BOTH the repo root AND `frontend` (the **root** install provides the `tauri` CLI that `npm run desktop:build` resolves from root `node_modules/.bin` — a frontend-only install dies with `tauri: command not found`), and preflights — loudly, each naming its remedy — the required tools, the Node version against `.nvmrc`, `gh auth`, npm-registry + GitHub reachability, and a clean working tree, all BEFORE the slow build. Dev and releases now run on ONE machine — **Hephaestus**, the single dev+release Mac (the build VM and the old release Mac are retired); Node 24 is the nvm default wired into its `~/.zprofile`, which the `zsh -lc` login shell sources, so its whole release job is just `zsh -lc ./release.sh` — no manual `nvm use`, and no separate manual `npm ci` (release.sh runs the root + frontend installs itself). Homebrew's `node` on Hephaestus is 26 and is deliberately NOT used for this project. Dry-run the portable half (preflight + `npm ci`) with `CHECK_ONLY=1` (other knobs: `SKIP_NPM_INSTALL`, `ALLOW_DIRTY`, `ALLOW_NODE_MISMATCH`, `ALLOW_NPM_INSTALL_FALLBACK`). The signing/notarization/`latest.json` logic is unchanged. Bump `.nvmrc` deliberately (a logged decision) on any toolchain move.
- **Run `release.sh` from a non-GUI / automation context with `CI=true`** so Tauri passes `--skip-jenkins` and builds the DMG headless. Tauri's `bundle_dmg.sh` styles the disk-image window with Finder AppleScript (`osascript`), which needs a logged-in GUI session; without one the DMG step dies with `failed to run bundle_dmg.sh`. `CI=true` skips that GUI-only styling, so the raw DMG comes out unstyled — but `release.sh` then **re-applies the install-window layout headlessly**, injecting a committed `.DS_Store` (`src-tauri/dmg/dmg-DS_Store`, captured from a prior styled release, copied in with `hdiutil` right before notarization), so the shipped DMG is styled identically to an interactive build. Regenerate that template only if the DMG's volume name or item names change. **codesign/notarize/`latest.json` are unaffected** (they work cross-session). The seamless headless command is `CI=true SKIP_NPM_INSTALL=1 zsh -lc ./release.sh` (drop `SKIP_NPM_INSTALL=1` for a cold checkout). An interactive logged-in desktop run needs no flag (its Finder styling and the injected `.DS_Store` produce the same layout).
- **The shipped DMG *container* carries no code signature, BY DESIGN — a `codesign -dv` on the DMG reporting "not signed" is not a release regression (v0.5.74 ship).** The `.DS_Store` styling step above re-converts the disk image (`hdiutil convert` → UDRW, attach, inject the layout, detach, convert back to UDZO) *after* `tauri build` has signed it, which writes a NEW image file and drops the container signature. Everything that actually gates a user's download still holds: the converted DMG is what gets submitted to `notarytool` and `stapler staple`d (the styling deliberately runs BEFORE notarization so the ticket staples the final image), and the `.app` inside it is Developer-ID signed by the build. The signature the **updater** verifies is the minisign one on `SnowRaven.app.tar.gz`, never the DMG wrapper. Don't "fix" this by re-signing the DMG or by moving the styling after notarization — the latter would invalidate the staple.

- **After a Hephaestus reboot, the login keychain is LOCKED for remote (SSH/tailnet) sessions — every signing step fails until the USER unlocks it (v0.5.73 ship).** Symptoms: `codesign`/`xcodebuild -exportArchive` dies with `errSecInternalComponent`, `security show-keychain-info` says "User interaction is not allowed," and git's osxkeychain helper fails with `-25308`. The fix is once per reboot: the user runs `security unlock-keychain ~/Library/Keychains/login.keychain-db` in THEIR OWN terminal on the machine (a second ssh is fine). Claude cannot collect the password — the in-chat `!` command has no interactive TTY, so `security` reads EOF and fails without ever prompting; never ask for the password in chat. Check `security show-keychain-info` before a ship to catch this up front. (For git pushes, `git -c credential.helper='!gh auth git-credential' push …` sidesteps the keychain entirely.)
- **`release.sh` runs `touch src-tauri/src/main.rs` to force a Cargo relink, so a running `npm run desktop:dev` watcher will rebuild and RELAUNCH the dev app mid-release (v0.5.74 ship).** Harmless — the dev app and the release build use separate target dirs, and the release is unaffected — but it looks alarming if unexplained, and it matters when a live preview is being shown to the user during a ship: their app window will disappear and come back on its own. Either quit the dev watcher before releasing, or tell the user to expect the relaunch. Don't chase it as a crash.

### Windows desktop release (v0.4.0+)

- **Windows builds run in GitHub Actions** (`.github/workflows/windows-build.yml`, `windows-latest`), triggered by pushing a `v*` tag. The build uses a *throwaway* signing key (discarded) only so Tauri produces the artifacts; `release.sh` re-signs locally with the real key. The real minisign key never goes to GitHub — same keep-it-local stance as the Apple credentials.
- **`release.sh` is the single multi-platform assembler.** It builds + notarizes macOS, then `gh run download`s the CI Windows installer, signs it locally, and writes ONE `latest.json` with both `darwin-aarch64` and `windows-x86_64` entries. `SKIP_WINDOWS=1` publishes macOS-only (emergencies).
- **Release rhythm:** bump version → commit → push to main → push the `vX.Y.Z` tag (starts Windows CI) → wait for CI → run `./release.sh` → **ship the iOS TestFlight build for the same version** (see the iOS section below). The tag must be pushed *before* `release.sh` so the CI artifacts exist to fetch. **A release goes to ALL available platforms, every time (user direction, v0.5.78)** — `release.sh` covers macOS + Windows + `latest.json`, the Pages workflow covers the website, and the iOS TestFlight upload is the remaining manual leg; a release is not done until it has shipped.
- **A re-pushed `vX.Y.Z` tag leaves a stale successful Windows CI run that `release.sh` can mis-select (0.5.34 post-mortem).** `release.sh` picks the Windows installer from the most-recently-*created* successful `windows-build.yml` run (`gh run list --workflow windows-build.yml --status success --limit 1`), and its only guard checks the installer *filename* contains the version — which CANNOT distinguish two runs of the same version. If the tag was moved (a false-start: tag pushed at commit A, then re-pointed to commit B), the first push's run for orphaned commit A stays a *successful* run; if A's run is newer-created than B's, or B's run hasn't finished yet, `release.sh` silently ships A's binary (the version-filename guard passes either way). **Standing check before running `release.sh` after any tag re-push:** verify the selected run's commit equals the tag commit — `gh run list --workflow windows-build.yml --status success --limit 1 --json databaseId,headSha` and confirm `headSha == git rev-parse vX.Y.Z^{commit}`. You can't cancel a run that already completed; rely on the create-order (the correct re-push is newer) and wait for *that* run to go green before releasing.
- **The Windows updater target is the NSIS installer itself (`*-setup.exe`), NOT a `.nsis.zip`.** Tauri v2 signs the installer (`.exe.sig`) for updates on Windows; there is no separate archive. The `latest.json` `windows-x86_64.url` points to the `-setup.exe`.
- **Cross-platform Rust deps must live in `[dependencies]`, not `[target.'cfg(target_os = "macos")'.dependencies]`.** `tzf-rs` (used by the cross-platform `get_timezone` command) was mis-scoped there and broke the Windows build with "unresolved import." The macOS-only block is only for genuinely macOS-only crates (objc2*, the CoreLocation stack).
- **`tauri signer sign`: don't pass `--private-key-path` (`-f`) when `TAURI_SIGNING_PRIVATE_KEY` is already exported** — the env key and the path flag are mutually exclusive. `release.sh` exports the env key for the macOS build, so the Windows-install signing step relies on the env, no flags.
- **Windows is distributed unsigned** (no Authenticode) for now — first launch shows a SmartScreen "unknown publisher" prompt. The in-app updater is unaffected (minisign verification, not Authenticode).

### iOS release (TestFlight)

- **Every desktop/web release is followed by an iOS TestFlight build of the SAME version, build 1 (standing rule since v0.5.78; user direction).** iOS is no longer a selective catch-up — run the recipe below after `release.sh` verifies, on every release, bundled Spool releases included. iOS-only follow-ups still increment the build number without a desktop release.
- **iOS app icons must be fully OPAQUE — NO alpha channel — or App Store Connect rejects the upload (altool error 90717).** The check is on the large 1024 app icon and it fires on *any* alpha channel, even a fully-opaque/redundant one (the SR icons carried an all-opaque alpha with anti-aliased edges and were still rejected on the first upload). Keep BOTH `src-tauri/icons/ios/` AND the committed `gen/apple` AppIcon.appiconset (`src-tauri/gen/apple/Assets.xcassets/AppIcon.appiconset/`) flattened to opaque RGB — composite onto white and save with NO alpha (all 18 PNGs). The desktop icons (`tauri.conf.json` `bundle.icon`, `src-tauri/icons/icon.png`) MAY keep their alpha — this rule is iOS-only. `gen/apple` is a committed generated artifact, so the flattened icons must be committed there (re-running `tauri ios init` would re-stamp Tauri's placeholders — don't rely on init). Precedent: the v0.5.68 iOS icon fix (`e070d73` icon swap + `21fd5b2` flatten).
- **iOS build + TestFlight upload is Claude's to run (same posture as `release.sh`), and is NOT `release.sh`** (that assembler is macOS + Windows desktop only). The recipe (full detail + fallback in `pipeline/mobile-app/how-to-see.md`): `tauri ios build` SCRUBS `DEVELOPER_DIR` from the `xcodebuild`/`xcrun` it spawns, so build through the `/tmp/xcshim` wrapper (`printf` the two shim scripts that re-export `DEVELOPER_DIR` and `exec` the real tool, `chmod +x`, then `PATH=/tmp/xcshim:$PATH`) AND `export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` in the parent shell. Do NOT `sudo xcode-select` (it needs a password). Build the TestFlight archive with `--export-method app-store-connect --build-number N`, then upload with `xcrun altool --upload-app -f <ipa> -t ios --apiKey $APPLE_API_KEY_ID --apiIssuer $APPLE_API_ISSUER_ID` (the App Store Connect API key + issuer live in the login shell / `~/.appstoreconnect/private_keys/`). An iOS-asset-only change (like the icon fix) does NOT bump the desktop version — it ships as an iOS build-number increment against the current version (v0.5.68 build 2), no `release.sh`, no tag, no `latest.json`.
- **`tauri ios build` STAMPS the committed `gen/apple/snowraven_iOS/Info.plist`** (`CFBundleShortVersionString` + `CFBundleVersion` from the version and `--build-number`), so an iOS build leaves the working tree dirty. **Commit the stamp before `release.sh`** (its clean-tree preflight aborts otherwise) — a one-line `chore(ios): stamp iOS <ver> build <n>` commit, precedent `c505f2e` (v0.5.73) and the v0.5.71 closeout stamp.
- **`tauri ios build --export-method app-store-connect` ALSO needs the App Store Connect API key under TAURI's env names for its export/signing step — DISTINCT from the `altool` upload creds, and a real gap in the recipe above (hit + fixed on the 0.5.69 iOS build).** The upload step reads `APPLE_API_KEY_ID` / `APPLE_API_ISSUER_ID` from the login shell (passed to `altool --upload-app` as `--apiKey` / `--apiIssuer`); the *build/export* step reads three different names — `APPLE_API_KEY` (the key id), `APPLE_API_ISSUER` (the issuer id), and `APPLE_API_KEY_PATH` (path to the `.p8`). Map the login-shell ids across before building: `export APPLE_API_KEY="$APPLE_API_KEY_ID"; export APPLE_API_ISSUER="$APPLE_API_ISSUER_ID"; export APPLE_API_KEY_PATH="$HOME/.appstoreconnect/private_keys/AuthKey_$APPLE_API_KEY_ID.p8"`. Without all three the build dies at export with `APPLE_API_KEY, APPLE_API_ISSUER and APPLE_API_KEY_PATH must be provided for code signing`. Do this every iOS ship so the next one doesn't repeat it.

## Conventions

### Ports
- Backend runs on port **1620** (not 8000)
- Frontend dev server runs on port **5173** (Vite default)
- Vite proxies `/weather`, `/tide`, `/nominatim`, and the other backend route prefixes to `http://localhost:1620` (see `frontend/vite.config.ts`). **When you add a backend route, add its path prefix to that proxy.** Otherwise the web-dev path hits Vite's SPA fallback (HTML) instead of the backend and the call silently fails under `npm run dev` — this bit the new `/tide/at` route in 0.5.34 (and, latently, the existing checklist tide, which is normally exercised only via the desktop app or the FastAPI-served build).

### Environment
- API keys live in `backend/.env` — never commit this file
- Required keys: `EBIRD_API_KEY`, `OPENWEATHER_API_KEY`
- OpenWeather key must be subscribed to "One Call by Call" at openweathermap.org
- **The on-disk data directory is single-sourced in `backend/datadir.py` (`DATA_DIR`, overridable with `SR_DATA_DIR`) — a backend module that reads `data/` MUST import it, never re-derive `Path(__file__).parent…/"data"` (v0.5.77).** Four routers (`settings`, `settingskv`, `mapdefaults`, `taxonomy`) each derived it independently until the override was added; a **partial** override is worse than none — the app would read demo data on one route and real data on the next, which is precisely the privacy failure the override exists to prevent (it lets the website screenshot capture drive a throwaway synthetic dataset instead of `mv`-ing the user's real eBird export aside). `backend/tests/test_datadir.py` asserts every consumer resolves through the one module, so a new router that re-derives its own path fails the suite — extend that test rather than adding a parallel one.
- **An env var read at MODULE IMPORT time cannot be set in `backend/.env`, and fails SILENTLY when you try (v0.5.77).** Routers import while `main` is still importing, which is before `load_dotenv()` runs, so an import-time `os.environ` read never sees a `.env` value — the code just uses its default with no error. `SR_DATA_DIR` is the live example and must be set in the process environment before the backend starts. The API keys above are unaffected (they are read per-request, after `load_dotenv()`). The same import order is why a file write can never redirect the data root — the security-positive half of the same fact, so don't "fix" it by moving the read later. State both halves at the definition site (`backend/datadir.py`'s docstring is the reference).

### Stack
- Backend: Python 3.10+, FastAPI, Starlette, uvicorn, httpx, timezonefinder
- Frontend: React, Vite, TypeScript, Tailwind CSS v4, shadcn/ui
- Tests: pytest (backend), vitest (frontend)
- CI: GitHub Actions (`.github/workflows/pipeline.yml`)

- **Backend runtime and CI verification versions are exact security/reproducibility pins (v0.5.72).** Keep `backend/requirements.txt` at the audited compatible runtime set (`fastapi==0.141.1`, `starlette==1.3.1`, `python-multipart==0.0.32`, `python-dotenv==1.2.2`) until a deliberate, tested upgrade. Keep backend CI's development tools explicit too: `ruff==0.15.20` and `pytest==9.1.1`; never restore unconstrained `pip install ruff pytest`, which made a tagged release depend on whatever PyPI served that day.

- **No impure calls during render — `react-hooks/purity` is enforced by eslint (build-blocking).** Never call `Date.now()` / `new Date()` (or other impure functions) inside a component render body or a `useMemo`/`useCallback`. For a "now" reference in recency / time-window filters, use a module-level session constant (`const SESSION_NOW_MS = Date.now()` at module top) and read it in the memo, or thread a `nowMs` arg into a pure helper — the pattern in `MapExplorer.tsx` (the Time Range window) and `BirdingStats.tsx`. Event handlers may call `Date.now()` directly (they don't run during render).

- **A histogram whose bin count derives arithmetically from a data VALUE (not from row count or distinct values) must bound its ladder structurally in the compute layer (v0.5.78).** The CSV parser admits any `parseInt`-able integer, so one corrupt cell can otherwise mint millions of bins (~3 GB heap and a render-time `RangeError` from a `Math.max(...spread)` — the checklist-duration Medium, empirically confirmed). `computeDurationBins` (`lib/birdingStats.ts`) is the reference: a plausible-range input guard (`[0, 1440]`, eBird's 24 h checklist cap — out-of-range rows fall into the honest "N of M have a usable duration" coverage note) PLUS a structural `DURATION_MAX_BIN_INDEX` clamp so the ladder is bounded even if the guard is bypassed. Pair it with reduce-not-spread for any `Math.max`/`Math.min` over a data-length array (bounded spreads over fixed-size arrays are fine). A histogram bounded by distinct values (the observer-count chart) is a different, inherently bounded shape — do not generalize from it.

- **When a preference's copy multiplies combinatorially (N independent toggles means 2^N labels), GENERATE it from one ordered manifest plus pure functions — never a hand-written lookup table (v0.5.81).** `SHARE_PARTS` in `lib/shareLocation.ts` is the reference: one ordered table drives the payload lines, the switch labels, their accessible names, the popup button label, and the mode sentence, so adding a fourth destination is one row and zero new copy. Three properties are load-bearing:
  - **Keep the manifest noun its OWN column, never the visible label lowercased.** The one-column-plus-`.toLowerCase()` shortcut reads correctly on today's rows and silently produces "Bing maps link" on the next one. Same class of trap: a `countWord` ladder that stops at the shipped count and starts mixing a digit into a sentence of word forms.
  - **The generic functions take the driving table as a DEFAULTED parameter, and the suite proves the claim by actually adding a hypothetical extra row** and asserting every derived output from it. Extensibility asserted only against the shipped table is untested by construction; this is the mechanism that surfaced the noun trap before it shipped.
  - **Where a copy decision rests on a rendered measurement (a character ceiling, a wrap count, a fixed-width container), state the number AND keep a test that fails if the generated string exceeds it.** The prose figure alone drifted by one character here with nothing failing.
  A structural state (all toggles off) is a structural answer, not an extra string: **no control that looks pressable may put an empty string on the clipboard** — replace the control with a sentence rather than disabling it.
- **A displayed whole-percent share for a NONZERO count must never render a bare rounded "0%" (v0.5.79).** Route share display through `fmtSharePct(count, total)` (`lib/statsFormat.ts`) — "<1%" for a nonzero share that rounds to zero, honest "0%" only for a truly zero count — never raw `Math.round(count/total*100)`.

### Running tests
```
cd backend && python -m pytest tests/ -v
```

- **`frontend/src/test-setup.ts` installs baseline `requestAnimationFrame`/`cancelAnimationFrame` shims for every test file** (wired via vitest `test.setupFiles` in `vite.config.ts`). Reason: recharts bundles `@reduxjs/toolkit`, whose autoBatch fallback timer (100 ms, calls bare `cancelAnimationFrame`) can outlive a jsdom test file and fire in a later DOM-less node-env file in the same worker — the source of the old ~11% full-suite flake. Never remove the shims or convert them to per-test `vi.stubGlobal` stubs (per-test stubs can't cover timers that fire after their file's environment is torn down). The shims are `typeof === 'undefined'`-guarded, so jsdom files keep their natives and a file's own stubs still win.
- **Component tests that stub a scheduling queue must wait on an observable stub-queue precondition before flushing.** A `waitFor` on rendered DOM resolves on the React commit, which under suite load can land BEFORE a passive effect queues into the stubbed queue — flushing then drains an empty queue and the test asserts against a frozen shell (the BirdingStats frozen-shell flake). After the DOM wait, add `await waitFor(() => expect(rafQueue.length).toBeGreaterThan(0))` (or the equivalent for the stubbed queue), then flush. Never assume effect timing relative to `waitFor`, and never substitute a wall-clock sleep. Reference: `renderAndLoad()` in `BirdingStats.test.tsx`.
- **A strict performance contract may sample complete executions to resist shared-runner scheduling noise, but may not weaken its threshold (v0.5.72).** Calendar QA-41 still requires one complete `buildDayCells` execution below 50 ms; it measures seven full executions and asserts their minimum. Do not time partial work, raise the limit, or discard the contract. Use this bounded repeated-measurement pattern only for deterministic work whose isolated baseline is comfortably below the threshold and whose one-off wall time is vulnerable to unrelated parallel test load.
- **Every jsdom test file that mounts recharts charts must end with `afterAll(() => new Promise((r) => setTimeout(r, 120)))`.** Toolkit's 100 ms autoBatch fallback timers armed during the file must fire before its jsdom environment is torn down — the `test-setup.ts` shims never install in jsdom files (the globals exist there), so a timer that outlives the file fires where `cancelAnimationFrame` no longer exists and fails a later file with all tests green. Currently applied in `BirdingStats.test.tsx` and `MediaStatsSections.test.tsx`; copy the pattern into any new chart-mounting jsdom file.
- **A CSS-only fix is verified against a REAL RENDER, not a parsed stylesheet — and this repo already has the browser (v0.5.81).** A stylesheet test proves a rule exists and is scoped; only a browser proves it *wins* against the inline styles it must beat, and only measuring the element that owns the visible text proves what the user actually reads. Playwright is already a dependency in `website/tools/` for the screenshot pipeline, and there is a synthetic demo dataset: point the backend at it with `SR_DATA_DIR` (never the real export) and measure BOTH revisions on the same DOM nodes. When two builds differ only by a class, resolve blocks by structural DOM path from the build that HAS the class so the comparison is like-for-like, and guard the resolved node (tag, child count) rather than trusting the path. Geometric claims — whether focus lands under a sticky band, whether a band is opaque, what `elementFromPoint` returns inside it, whether a row wraps — are invisible to vitest/jsdom (no layout engine, no media queries, no computed font size, no cascade against React inline styles) and equally invisible to a built-CSS text assertion. A throwaway static HTML reproduction of the exact DOM and CSS settles them in about a minute; reach for it when a change's core claim is geometric. Three sharpenings from v0.5.82, each a wrong turn that was actually taken:
  - **A NUMERIC browser measurement is still not a render when the element is a native control with UA-drawn internals.** Neither `scrollWidth`/`scrollHeight` nor a canvas `measureText` is admissible evidence that a control clips, and both were wrong in OPPOSITE directions on the same elements: an `<input type="date">` reports `scrollWidth === clientWidth` while visibly cutting the year off (proxy under-reports), a `<select>` reports `scrollHeight > clientHeight` at 200% text scale while rendering perfectly (over-reports), and `measureText` on the value string declared a clipped `Longitude` placeholder a fit by 0.04px because it cannot see the picker icon, the spinner buttons, or the control's internal field spacing. Screenshot the control and look.
  - **Render the declarations PARSED from the real stylesheet, never retyped into a fixture.** Retyping is how a reproduction quietly stops testing the shipped code. Substituting a platform value (e.g. `env(safe-area-inset-top)` → a literal 59px) is fine and is the point; re-authoring the rule around it is not.
  - **Page `scrollWidth` alone is not a usable assertion for an overflow fix — measure the ELEMENT against its container.** A broken build can read a clean integer `scrollWidth` when the overflow is sub-pixel or absorbed by panel padding (a cluster 24.23px past its content box read exactly 320 on a 320px viewport), and the leak's size tracks the data (a count label reading `428 species` reproduced 3px, `1247 species` gave 12px, `88 species` gave none), so a dataset-dependent defect hides behind a viewport-width equality.
- **A stylesheet test for a rule that must apply at ALL viewport widths parses exact top-level selectors and skips at-rule blocks WHOLE (v0.5.81).** A substring or regex match over the raw stylesheet cannot distinguish a top-level rule from one nested inside a media tier, so it passes silently on a DRY-consolidation that strands every width outside that tier — the concrete harm being the iPad Help-TOC case. The third arrived (`skip-link-safe-area`) and the helper was extracted as anticipated: **`frontend/src/lib/cssTopLevelRules.ts` (`parseTopLevelRules`) is now the one parser**, and `mapIosFullscreen.test.ts` (whose `stripMediaBlocks` + `iosRule` + `cssRule` trio it replaces) and `iosChrome.test.ts` (which hosts the skip-link guard) both read `globals.css` through it. Reuse it for a fourth; its own three properties — exact selector keys, at-rule blocks skipped whole, comments stripped before the brace walk — are asserted against fixtures in `cssTopLevelRules.test.ts`, so the guards assert about the stylesheet rather than about their plumbing. It is test-only and nothing in the app imports it, so it is never bundled. **Not every stylesheet test belongs on it:** `filterControlSizeCss.test.ts` and `breedingCodePinnedCss.test.ts` ask *offset* questions (is this rule inside the ≤640 tier? does it come after that one?) that a selector→body map cannot answer, and they stay as they are.
- **`vitest` + `eslint` are NOT a substitute for the production build as the pre-push gate (0.5.35 post-mortem).** vitest transpiles with esbuild (no type-check), and an `// eslint-disable-next-line @typescript-eslint/no-unused-vars` silences ESLint but NOT the TypeScript compiler. A trailing unused **parameter** trips `tsc`'s `noUnusedParameters` (TS6133) and fails `npm run build` (`tsc -b && vite build`) — which is exactly what the Windows CI build AND the macOS `release.sh` build run. 0.5.35's first build failed CI this way (an unused `nowMs` param on `buildNearbyLifers`) while vitest + lint were green on the build machine, blocking the release until it was fixed on the Mac. Run `npm run build` (or at minimum `npm run typecheck`) before pushing a feature, not just `vitest`/`lint`. (As of 0.5.52 `npm run typecheck` is `tsc -b`, which follows the project references and actually type-checks; it was previously `tsc --noEmit`, which compiles ZERO files in this project-references repo — so the "at minimum typecheck" fallback now genuinely catches type errors.) To deliberately keep an unused param, prefix it with `_` (tsc exempts `_`-prefixed identifiers) rather than relying on an eslint-disable.
- **Backend outbound HTTP goes through the shared pooled client — `get_client()` from `backend/http_client.py` (v0.5.55), NEVER `async with httpx.AsyncClient()` per call.** It is one process-wide keep-alive `httpx.AsyncClient` (pooled connections reused across requests), a **LAZY singleton created on first use — NOT lifespan-created** (the test suite mounts `TestClient(app)` at module scope without a context manager, so lifespan startup never runs; a lifespan-created client would be `None` under every test). `main.py`'s lifespan only *closes* it on shutdown; never close it per request. It carries **no default headers/cookies/auth/base-URL** — pass the per-request `timeout=` AND any auth (the eBird `X-eBirdApiToken` header, the OpenWeather `appid` param) at each `.get()`/`.post()` call site, so there is no cross-request state bleed. Test mocks patch the shared accessor, not the `httpx.AsyncClient` constructor.

### Responsive layout — standing conventions

The app is responsive from ~320px phones to large desktops (the 0.5.37 sweep, extended by the 0.5.55 mobile-prep pass with touch-target sizing and iOS input-zoom lenses). The rules:

- **Make layout responsive by LIFTING it to a class, never with an inline style.** React inline styles are specificity 1,0,0 and BEAT class rules, and an inline `display:grid`/`flex` can't be reached by a media query — that is exactly why `.sr-two-col`/`.sr-compare-panels` and the sweep's hooks exist. To make a container respond, REMOVE its inline `display`/`gridTemplateColumns`/`flex-direction`/`flex-wrap`/`gap` and add the class; keep colors/padding/borders inline (tokens only). The sanctioned inline exceptions are responsive-by-construction (no breakpoint math): px→rem width conversions and `minmax(min(<px>, 100%), 1fr)` self-collapse tracks so a fixed track shrinks below a phone width instead of overflowing.
- **The shared layout vocabulary (all in `globals.css`):** `.sr-action-row` (a label + trailing action(s) row that wraps instead of overflowing; give the growable child `.sr-min0`; add `.sr-action-row-stack` to stack ≤480), `.sr-grid-2/-3/-4` (fixed N-up that collapses 3/4→2 at ≤1024 and all→1 at ≤640), `.sr-grid-auto` (self-collapsing `auto-fill minmax(--sr-grid-min,1fr)` — no breakpoint math; best default for tile grids), `.sr-grid-chart-aside` (content + a pie/donut aside that stacks ≤640), `.sr-field-row` (inline form controls that stack ≤480 where native date inputs can't shrink), `.sr-scroll-x` (contained horizontal scroll for wide tables), leaf helpers `.sr-min0`/`.sr-truncate`/`.sr-wrap-anywhere`, `.sr-pad-x-trim` (trim component-local side padding on phones), and `.sr-map-explorer-panel`.
- **The 0.5.55 mobile-prep additions (also `globals.css`) — use these, don't re-inline:** `.sr-touch-target` (raises a dense fixed-height button/pill toward ~44px min-height, in the ≤640 tier ONLY — desktop density is untouched; it does not change the visible glyph/label size, and a control that must be 44px on desktop too needs its own rule), `.sr-map-popup-body` (wrap the inner content div of any map popup that can grow tall — `max-height: min(60dvh, 26rem)` + internal scroll + `overscroll-behavior: contain`, so it never runs off a short phone viewport), `.sr-input-16` (add to any `<input>`/`<select>`/date-time control carrying a sub-16px inline font-size — sizes it in the ≤640 tier to suppress iOS focus-zoom; **the one place a px font-size is correct**, since the iOS zoom threshold is an absolute px value, and it avoids a `maximum-scale` viewport clamp that would kill pinch-zoom. **The class must sit on the `<input>`/`<select>` element ITSELF and out-rank its inline font-size** — the rule carries `!important` precisely because the thing it must beat is an inline style (specificity 1,0,0); put it on a wrapper, or leave the rule non-`!important` against an inline sub-16px font, and the guard is silently inert. This was inert on ~25 inputs app-wide until fixed in v0.5.61), `.sr-ctl-row` (v0.5.81 — put it on a **filter block**, and every interactive descendant inside it gets one phone-tier text size; it sizes descendants, never the container), and `.sr-wrap-flex` (wrapping inline flex control groups / header rows — lift the inline `display`/`flex-wrap` here, keep gap/colors inline or via `--sr-wrap-gap`). The `index.html` viewport carries `viewport-fit=cover`.
- **A phone-tier size that must clear an absolute px floor AND stay consistent with a scale-tracking neighbour is written `max(<px floor>, <rem>)`, ONCE, as a single declaration covering both sides (v0.5.81).** The old flat `.sr-input-16` value satisfied the 16px iOS floor and nothing else: at 1x it left pills at 12px beside 16px selects in the same wrapping filter row, and at 200% in-app text scale it INVERTED (pills 24px, controls still pinned at 16px), so the controls became the small ones for exactly the user who enlarged their text. `font-size: max(16px, 0.75rem) !important` in the ≤640 tier is shared verbatim by `.sr-input-16` and `.sr-ctl-row :is(button, select, input)`; the two sides can never differ at any scale, which two rules holding two literals that agree today cannot promise. State the guarantee as a property of the FORMULA across the whole input domain (`max(16px, rem)` is ≥16px for every value of `rem`, including a browser/OS default font size the user has lowered), not as "it computes 16px at 1x and 24px at 200%" — sampling the four in-app text scales would have missed that `rem` also tracks the browser default. The two selectors deliberately differ in specificity ((0,1,0) vs (0,1,1), both `!important`), which is exactly why they must share one declaration and a test must lock the values identical: then which one governs a guarded control is moot rather than reasoned about. Guard: `frontend/src/lib/filterControlSizeCss.test.ts` (parses the real `globals.css`, same posture as `milestoneContrast` / `countyContrast` / `calendarContrast`). **Corollary for VERTICAL fit, which the formula answers structurally so it needs no measuring (v0.5.82):** `max(16px, <rem>)` never TIGHTENS a box whose inline size is already that rem. It raises only while the rem is below 16px (below ~133% text scale, where it pins to exactly 16px); above that it returns the rem, i.e. the inline value the box was already built for. So a fixed-height control guarded this way cannot start clipping vertically at any scale — which is why adding the guard to nine controls sitting in fixed 34px boxes needed no accommodation.
- **A phone-tier size guard that makes a row stop FITTING inside a fixed-width container needs a companion layout rule, and the companion belongs beside it in the same tier, scoped to the feature's own subtree (v0.5.82).** Raising a control to 16px can push a side-by-side pair past its container: the Map Explorer's Date Range pair renders `08/09/2026` at 12px and `08/09/202` at 16px in the 120.5px each gets from a 282px sidebar. The repair is a `.sr-field-row` stacking rule scoped to the map sidebar through the whole ≤640 tier — NOT widening `.sr-field-row`'s own 480 breakpoint, which has six consumers and would restack five surfaces that sit in the full-width main panel with 220px+ per field and have no problem. Never weaken the `.sr-input-16` guard to resolve a clip; the guard is the requirement and the layout is what yields. Same "prefer the rule that lives inside the feature's own subtree" principle as the scroll-margin case above.
- **Put a control's font size on the control ELEMENT, not on a label span nested inside it (v0.5.81).** A size on a descendant beats any class on an ancestor, so a container rule like `.sr-ctl-row` cannot reach it — and the two forms are visually indistinguishable until the container rule exists, so this is invisible in review. Calendar's local `Switch` declared its size on the label `<span>` and would have stayed small beside everything else in its strip; the declaration moved up to the `<button>` (the span inherits, so desktop is byte-identical) and a test pins it. Corollary when measuring: a font size read off a control's box is not the size the user reads — measure the text-owning element.
- **A `rem` cap inside a fixed-`px` container measures the wrong thing — measure the container (v0.5.80).** `--sr-text-scale` multiplies the root font size, but a `height: 220px` card (the Named Birds card map) does not follow, so a `rem` max-height GROWS on a container that did not, and at 200% text scale it can double. When a popup or panel must fit a px-measured box, compute the cap from container geometry and write it as a **px custom property from a ref side effect** (no `setState`, no render-time measurement), with a floor at the ~44px touch-target size so the cap can never shrink a control out of reach. `SharePopup.tsx`'s `COMPACT_BODY_MAX_PX` / `COMPACT_BODY_MIN_PX` / `COMPACT_CHROME_PX` / `COMPACT_EDGE_MARGIN_PX` are the reference. This does NOT replace `.sr-map-popup-body` (`min(60dvh, 26rem)`) — that one is correct because its constraint is the *viewport*, not a container. Known modelling limit: `COMPACT_CHROME_PX` is a fixed px estimate of partly rem-sized chrome, so it under-estimates at large text scales; the cap itself is sound.
- **Two standing mobile checks for new UI (the 0.5.55 lenses beyond the 0.5.37 sweep):** (1) touch targets on fixed, dense controls must meet the ~44px posture in the ≤640 tier (reach for `.sr-touch-target`); (2) no form control may ship a sub-16px font-size on phone (reach for `.sr-input-16`) or iOS auto-zooms on focus. Both hold at 320px and 200% in-app text scale.
- **Any `position: fixed` OR `position: sticky` element escapes `.sr-ios-app body`'s safe-area padding and needs its OWN `.sr-ios-app`-gated inset — and therefore cannot keep its positioning in an inline style (v0.5.81, proven three times).** `.sr-ios-app body { padding-top: env(safe-area-inset-top) }` protects every in-flow surface; a fixed element is viewport-relative and a sticky one resolves `top` against its scrollport, so both sit ABOVE that padding and render under the status bar / Dynamic Island (and, in landscape, the sensor housing). An inline `inset: 0` / `top: 0` is specificity (1,0,0) and unreachable from a stylesheet, so the positioning must be **lifted into a `globals.css` class first** (values byte-identical), which is the only thing that gives the inset somewhere to hang. Shipped instances: `.sr-map-fullscreen-panel` (map fullscreen), `.sr-help-panel` + `.sr-help-toc` (the Help overlay), `.sr-bc-matrix--pinned thead th` (the pinned Breeding Codes band), and `.sr-skip-link:focus` (the "Skip to main content" link). Rules that hold:
  - **Gate on `.sr-ios-app`, NEVER a bare `env()`.** `index.html` ships `viewport-fit=cover` to browsers too, so `env(safe-area-inset-*)` is non-zero in iOS Safari on the **web** build; an ungated rule fixes the app and silently changes shipped web rendering on every notched phone. `.sr-ios-app` is set on `<html>` by `main.tsx` only when `isIOS()`, so desktop and web stay byte-identical. Assert in the test that the ungated base rule contains no `env(`.
  - **Pad, don't shrink; top/left/right only.** Tailwind preflight's global `box-sizing: border-box` keeps a `100dvh` panel exactly `100dvh` with only its content box moving inward. Mirror `.sr-ios-app body` and add no `padding-bottom` (the FAB cluster and each overlay's own bottom padding already clear the home indicator; adding one shrinks a `flex: 1` scrollport into a dead band).
  - **A viewport-height calc INSIDE such an overlay must subtract the top inset too**, or a child capped that way over-extends by exactly the inset — invisible on a phone, live on iPad. The Help TOC's `calc(100vh - 52px)` stranded its last entries there until the gated variant subtracted it. Same family as the v0.5.80 "measure what actually bounds it" rule.
  - **Each overlay gets its OWN sibling rule; do not generalize.** The two full-screen overlays share only the three-line inset block (the map panel additionally needs `height: 100dvh` and carries a landscape coupling where the sidebar overlay reaches the padded edge through `.sr-map-content`'s `position: relative`; Help has neither), so a shared utility would still need a per-overlay positioning class and buys one declaration block at the cost of a second class name on the element. **Revisit a shared utility at a third overlay, not at two.**
  - **Watch the containing block when an inset is expected to reach a descendant.** An absolutely positioned child resolves against its nearest *positioned* ancestor's **padding box** — so a fixed panel's own padding does NOT inset an `absolute; left: 0` child unless that panel is the containing block. Name the actual positioned ancestor and assert its `position`, since removing it fails nothing today.
  - **Pad only a full-viewport box; a POINT-ANCHORED element is RE-POINTED, and only in the state that is on screen (`skip-link-safe-area`, the last of the family).** The "pad, don't shrink" rule above is the two panels' shape *because* they are `inset: 0` boxes; padding a `width: auto` pill instead grows it by the inset and paints its own background across the Island. The precedent that fits a point-anchored element is `.sr-ios-app .sr-bc-matrix--pinned thead th`, which moves an offset. Three sub-rules, each of which was a live wrong turn:
    - **Gate on the on-screen state, not the element.** `.sr-skip-link`'s base `top: -100px` is an off-screen *park* and is load-bearing: the pill is 41px tall at 1x and 62px at 200% text scale (measured, not estimated), so adding a 59px inset to the parked state — by `calc()` or by `padding-top`, both fail identically — puts its bottom edge at +21px and the HIDDEN link becomes permanently visible in the Island band. The inset belongs on `:focus` alone. Generally: before insetting a fixed element, ask which of its states the offset is describing.
    - **Only the edges the element actually declares.** `left` yes (at risk in landscape, and self-correcting — in the rotation where the housing is on the far side `inset-left` is 0 and the `calc` collapses to the shipped 16px); `right` never, because the element declares none and adding one to a `width: auto` fixed box stretches it across the viewport. This is the deliberate deviation from the two panel rules, which need both edges only because `inset: 0` pins both. Say so in a comment beside the rule, or it reads as an omission.
    - **Anchor the `calc` to the shipped literal** (`calc(16px + env(…, 0px))`), so the rule degrades to today's exact geometry wherever the inset is 0, and keep the `0px` fallback or the whole declaration is invalid where the variable is unsupported.
  - **This does NOT make it three overlays.** The skip link shares the escape and the gate, not the pad block, so the "revisit a shared utility at a third overlay" count above still stands at two.
- **Breakpoint tiers:** ~480 (small phone), **640 (the established phone boundary — don't move it; lots hangs off it)**, ~1024 (tablet), and a `.sr-panel` max-width cap (1280px, centered) for large desktops. Prefer self-collapsing `.sr-grid-auto` so most grids need no breakpoint; reserve explicit collapses for column control. Do NOT add JS `window`/`resize`/`innerWidth` checks — TabNav's ResizeObserver and the CSS tiers cover it. **When a render BRANCH (which DOM mounts, not just styling) must change by breakpoint and pure CSS can't express it**, use a render-safe `useSyncExternalStore` over `matchMedia` (`lib/useIsPhone.ts`: subscribe to the `MediaQueryList` `change` event, `getSnapshot = () => mql.matches`, `getServerSnapshot = () => false`, old-Safari `addListener` fallback), NEVER a `window.innerWidth`/`resize` listener. This is the React-sanctioned external-store media pattern (no innerWidth arithmetic, no per-pixel handler, no impure render read), so it honors the spirit of the no-resize rule while doing what CSS cannot. (NOTE: the Calendar tab NO LONGER uses `useIsPhone` to force a view — as of v0.5.68 its Compact/Large toggle governs at ALL widths, so the two views are distinct on a phone too. Earlier docs describing a phone-forced Compact calendar view are obsolete; the hook remains blessed and is still used where a genuine render-branch must flip by breakpoint.)
- **A user-relabelable / swappable toggle stores label-AGNOSTIC internal state values — what the option renders semantically (e.g. `'months'` / `'overview'`), NOT value names that encode the visible label (`'large'` / `'compact'`).** The Calendar view toggle churned labels twice: v0.5.60 coupled the enum values to the labels for "code and UI agreement," so v0.5.62's label swap would otherwise have forced a lockstep value rename. Semantic, label-agnostic values let the labels and the code drift independently — a future relabel/swap touches only the option copy, never the state values or their consumers. (The values are session-only `useState` here, so there is no persisted string to migrate either way.)
- **When a child's legibility depends on its OWN cell size — not the viewport — gate it with a CSS container query, not a viewport breakpoint.** The same viewport width yields very different cell sizes (a desktop 3-up narrow panel and a phone single column are both "narrow" to a media query but sized oppositely), so a viewport tier can't decide whether an in-cell number fits. Give the sized element `container-type: inline-size` and reveal the number span under a `@container (min-width: …)` floor; below it, hide only the number span so the cell/grid never distorts and the shading still carries magnitude. The `.sr-cal-minimonth` (152px floor) day-number reference from v0.5.60 was RETIRED in v0.5.62 (the year-overview mini-cells reverted to shading-only, so both the numbers and the container-query CSS are gone) — the pattern remains the sanctioned approach when a cell-sized number genuinely earns its place. If you re-introduce it, the px floor is the same sanctioned legibility exception as `.sr-input-16`, and size everything else in rem so it holds at 200% text scale.
- **A `position:absolute` element wider than the viewport leaks PAGE horizontal scroll on a phone even when invisible.** Two such bugs were fixed in 0.5.37 (TabNav's `visibility:hidden` overflow probe; absolutely-positioned `.sr-only` spans inside a horizontally-scrolled table). **Standing check:** any wide / `max-content` element or off-screen measurement node must sit under an `overflow:hidden` / `position:relative` ancestor so it can't extend `document.scrollWidth` on a phone. Wrap any new wide table in `.sr-scroll-x` (which carries `min-width:0` + `position:relative`); don't add a blanket `body{overflow-x:hidden}` (it would break the tables' `wideMode` page-scroll). Fixes must hold at 200% in-app text scale — size in rem, never convert rem→px to "fix" overflow.
- **`.sr-wrap-flex` is INERT on a cluster that also carries an inline `flexShrink: 0` — the class needs a width cap to bind (v0.5.82).** A pinned flex container is never narrowed, and a container that is never narrowed has no reason to break a line, so `flex-wrap: wrap` computes correctly and changes nothing: the Breeding Codes count-and-view cluster measured 475px inside a 296px box with the class applied and wrapping enabled the whole time, the single largest unclipped overflower on any tab at 320px/200%. Pair the class with `maxWidth: '100%'` (responsive by construction, no breakpoint math, the same pairing `.sr-scroll-x` already uses) — measured identical in effect to dropping `flexShrink: 0`, and preferred because it keeps the do-not-get-squeezed intent rather than discarding it. Write the TEST as the invariant (given an inline `flexShrink: 0`, a width cap must be present) so either measured-equivalent form stays green and neither-of-them does not. General shape: **adding a responsive class is not evidence the layout responds** — a stylesheet test passes on an inert class, which is exactly how this one shipped inert.
- **The Breeding Codes matrix is BY DEFAULT a NATURAL full-height, page-scrolling table at ALL widths — NOT a capped-height frozen-header data-grid (v0.5.69, amended v0.5.81).** A frozen title row + capped-height data-grid was built and live-tested during the mobile pass, then REVERTED at the user's request for the natural table (the reason is in DECISIONS: pure CSS cannot combine a page-frozen header + an unbounded-height table + contained horizontal scroll — `overflow-x:auto` forces the vertical axis to `auto`/`hidden`, binding a sticky header to the wrapper instead of the page). The tier legend sits in normal flow after the last row. **v0.5.81 adds an opt-in "Pin code labels" toggle (default off, session-only) that pins the header — offered ONLY in the "↔ Unbounded" view**, where neither the card nor the wrapper sets `overflow`, so a `position: sticky; top: 0` `<th>` anchors to the page for free and the table keeps its full natural height. Normal view is deliberately NOT given the capped box: at 200% text scale a row is ~68px, so `60dvh` leaves ~5 rows with the legend stranded (worse than what v0.5.69 reverted) and `26rem` (832px) exceeds the viewport, which puts the scrollport's top — and the pinned header with it — off-screen. That arithmetic, not preference, is why the v0.5.69 shape stays reverted. Invariant: **pinned implies Unbounded** (pinning from Normal switches and pins in one press; unpinning restores the view you came from; pressing `↔ Normal` clears the pin). `position: sticky` sits on each `<th>` individually, NEVER on `<thead>`/`<tr>` (WKWebView honors sticky on cells only), and `border-collapse: separate` is required. **Phone narrowing is single-sourced in `.sr-bc-code-col`** (`frontend/src/globals.css`): base ~44px on desktop, `@media (max-width:640px)` → ~30px dot-width columns + 0.625rem headers. Change the phone width THROUGH that class, never an inline width. Thin vertical column rules come from `--sr-border-subtle` right-borders on `.sr-bc-code-col` / `.sr-bc-name-col` (all widths). The species-name column is horizontally sticky ONLY (`left:0`, no `top`). Magnify is native viewport pinch — NO CSS `zoom` / `transform:scale` (unreliable in WKWebView, same reason the v0.5.64 ZoomableWideSurface was reverted). **The ≤640 dot-width narrowing holds in BOTH the Normal and the "↔ Unbounded" (wideMode) views (v0.5.70):** `.sr-bc-matrix` on the `<table>` (base `width:100%; min-width:max-content`; `@≤640` `table-layout:fixed; width:max-content; min-width:0`) makes the declared `.sr-bc-code-col` widths *authoritative* — under `table-layout:auto` a cell width is only a floor a wide/uncapped table never reaches — and `.sr-bc-card` on the wideMode card (base `max-content`; `@≤640` `min-content`) hugs the fixed-width table so there's no trailing whitespace. **CSS caution:** `table-layout:fixed` needs a *definite* width (`max-content; min-width:0`), NEVER `width:100%` inside a `max-content`/shrink-to-fit container (a circular constraint that runs the table to the browser's ~500,000px element-width cap); and a `max-content` card over a fixed table sizes to the columns' *intrinsic* width (huge whitespace) — use `min-content` to hug it (both layout-only, caught only in live phone preview). ### Accessibility — standing conventions

The app targets WCAG 2.1 AA (the 0.5.31 pass). These are the durable, enforceable contracts; the published statement is `ACCESSIBILITY.md` and must stay true to the shipped code (a wrong accessibility statement is a liability, same posture as the privacy policy).

- **Contrast is fixed at the token, in BOTH themes — with a typed naming system.** Three text-on-X cases have distinct token families in `globals.css`: `--sr-tier-N-fg` (tier-colored text ON an 8–15% tier tint), `--sr-tier-N-text` (text ON the solid tier fill), and the on-fill tokens for specific surfaces (`--sr-map-target-*-text`, `--sr-milestone-*`, `--sr-rank-pin-*`, `--sr-on-chart-blue-dark`, `--sr-border-input` for form-control boundaries at ≥3:1 non-text). Pick the family by what the text sits on; never reuse a fill token (`--sr-tier-N` / `-rgb`) as a text color (the fill palette is left untouched for atlas/hatch parity). Verify with the same WCAG luminance math, both themes, before shipping a new pair.
- **`--sr-text-disabled` is for genuinely disabled CONTROLS only** (WCAG-exempt). Informative text, empty states, and captions use `--sr-text-muted`. Do not use `text-disabled` for content.
- **A token whose underlying fill differs by theme may need OPPOSITE text colors per theme** — `--sr-on-chart-blue-dark` is `#FFFFFF` light / `#0A0A0A` dark for exactly this reason. A single value can't always pass on a light-in-one-theme, dark-in-the-other fill.
- **Filter controls follow the Checklists.tsx pattern: an explicit `aria-label` on every `<select>` / date input / search box** that would otherwise rely on a placeholder or a nearby caption. `Checklists.tsx` is the reference; the pattern is now applied app-wide.
- **`SegControl` and segmented/pill toggles carry `aria-pressed`** reflecting the selected state.
- **Overlays route EVERY close affordance (Escape, Close button, backdrop) through one close function that restores focus to the opener.** If the opener unmounts while the overlay is open (e.g. a FAB that only mounts when the panel is closed), run the restore in an effect AFTER the close render commits via a flag ref — not at close() time, when the ref is still null (the `closeSidebar` / `restoreFiltersFocusRef` pattern in `MapExplorer.tsx`). A focus trap must **re-query its focusables per Tab keydown**, not cache them once (collapsed/`inert` content changes the set); `HelpDocs.tsx` and `MapExplorer.tsx` are the references.
- **Wrap a decorative recharts chart in `inert` — recharts ignores `accessibilityLayer={false}` on `PieChart`** (its root `<svg>` stays focusable and leaves an axe aria-hidden-focus ghost). The same `inert` clamps collapsed filter panels so hidden controls aren't stray tab stops.
- **`scroll-padding` goes on the SCROLLPORT, `scroll-margin` on the FOCUS TARGET — and in this app the focus target is almost never the cell (v0.5.81).** When a sticky band can obscure keyboard focus (WCAG 2.2 SC 2.4.11 Focus Not Obscured), the vertical guard is `scroll-margin-top` on the elements that actually receive focus. Table cells, rows, and list items are not focusable; the real target is the `<button>`/`<a>` inside them (`BirdName` nests one three levels deep in every species row), and `scroll-margin` neither inherits nor applies to an ancestor — so a rule on the cell computes `0px` on every focusable and is completely inert. Use the descendant combinator (`… tbody th *`), not a child combinator, and verify by reading the computed `scroll-margin-top` **off the element that receives focus** before claiming the SC. The `scroll-padding-top`-on-the-scrollport half is geometrically correct and is nonetheless the WRONG reach here: the scrollport is the page, and `mountedTabs` only grows with hidden panels at `display: none`, so a root-scoped rule (or a `:root:has(…)` variant — selectors match the DOM tree irrespective of computed `display`, verified in Chromium) stays in force on every other tab after the user pins and navigates away. **Prefer the rule that lives inside the feature's own subtree.** The same component's horizontal axis IS the genuine `scroll-padding` case (`BreedingCodeTable.tsx`'s `scrollPaddingLeft`), because there the wrapper really is a scrollport; the two axes are not symmetric. Scope any regression tripwire to the leak (a `:root`/`html`-scoped declaration), not to the property or selector vocabulary — a stylesheet-wide ban on `scroll-padding-top` or `:has(` fails unrelated future work under a test name that points at the wrong thing.
- **An overlay hosted INSIDE a map binds its Escape handler in the CAPTURE phase at `document`, with `stopPropagation` (v0.5.80).** `MapExplorer`'s shipped fullscreen-exit and sidebar-close Escape handlers are bubble-phase on `document`, so a bubble-phase handler on a new in-map overlay cannot beat them — one Escape would dismiss the overlay AND exit fullscreen. Capturing at `document` and calling `stopPropagation` makes the overlay the innermost dismiss layer and prevents the outer handlers firing at all. `SharePopup.tsx` is the reference; it stays one close path (the close control, Escape, and any maplibre dismissal all route through the same function, per the bullet above).
- **A live region whose text is set to the SAME string does not announce — put the message in a sequence-keyed child node (v0.5.80).** `aria-live` fires on DOM *mutation*, and React bails out when reconciling a text node to an identical string, so pressing the same control twice announces once while the visible confirmation re-renders both times and every `textContent` assertion stays green. The repo rule "render the region from the start, only change its text" is necessary but NOT sufficient. The fix is `{msg ? <span key={seq}>{msg}</span> : null}` inside the `role="status"` region, with `seq` advancing per announcement — each one is a real node replacement while the region's `textContent` stays exactly the message. Do NOT append an invisible character to force a diff: it makes every `textContent` assertion quietly false. Any such region needs a test that presses the same control twice and counts DOM mutations (`SharePopup.tsx` + `SharePopup.test.tsx` are the reference). **One nuance on that test, verified empirically in v0.5.81:** mutation-counting only discriminates against the wrong implementation when the message node stays **permanently mounted** and its text is toggled. Where the node unmounts while the region remains (the Breeding Codes pin note), the remount is already a real DOM addition, so an unkeyed child passes the same test. Still write the keyed child — but describe the guard by what it actually rejects, rather than banking a false confidence.
- **To portal a control into an EXISTING flex row, use `display: contents` on the slot — never `order` (v0.5.80).** `order` moves the box visually while leaving DOM order unchanged, which desynchronizes tab order from reading order (WCAG 2.4.3 Focus Order). `display: contents` makes the wrapper transparent to layout so DOM order IS visual order, and the new control simply takes its place in the sequence. `.sr-map-fab-slot` (the share pin's slot as the first item of `.sr-map-fab-cluster`) is the reference; it also means no shipped control in the cluster moves.
- **DOM map markers are real `<button>`s** via `neutralizeMarkerWrapper` (`lib/mapPins.ts`) on the `<Marker>` ref — never a clickable `<div>`.
- **The "open this checklist on eBird" affordance is the shared `components/ChecklistLink.tsx`, used for EVERY checklist link app-wide.** One visual signature (the lucide external-link icon) and one accessible-name formula, which is **label-aware**: with a visible date/count the name leads `{label} — open checklist on eBird (opens in a new tab)` (WCAG 2.5.3 Label in Name, so Voice Control can activate it by what's on screen); with no label it names the id directly; the functional suffix is identical everywhere (WCAG 3.2.4). A `compact` prop renders icon-only for dense spots (species pills, fixed-width cells, map popups) while keeping that same name; an optional `title` adds a hover tooltip without changing the accessible name. It keeps the `SUBMISSION_ID_RE` guard (junk id → plain text, never a styled 404 link).
- **Every NON-checklist external link goes through the shared `components/OutboundLink.tsx`** — it guarantees `target="_blank"` + `rel="noreferrer"` and an "(opens in a new tab)" cue (a clean spaced `aria-label` from string children / an explicit label, else an `.sr-only` cue node for JSX children). Canonical new-tab wording is "(opens in a new tab)". It is named `OutboundLink`, **not** `ExternalLink`, to avoid colliding with lucide-react's `ExternalLink` ICON; decorative ↗/→ glyphs beside a link are `aria-hidden`. Don't hand-roll an external `<a target="_blank">` — use `OutboundLink` (or `ChecklistLink` for checklists).
- **A location NAME that is a PUBLIC eBird hotspot renders through the shared `components/HotspotLink.tsx` (v0.5.40).** It turns the name into a link to `ebird.org/hotspot/{locId}` ONLY when the caller passes `isHotspot` true AND the id passes `LOCATION_ID_RE` (`/^L\d+$/`); a personal location, a junk/absent id, or a not-yet-resolved Set all render as plain text — never a styled 404 link (the pre-existing inline links gated on id-format ALONE, which wrongly linked personal locations; this is the fix). It wraps `OutboundLink` and reuses the `Open {name} on eBird (opens in a new tab)` name formula (`hotspotLinkAriaLabel`); `compact` = icon-only (map popups), `truncate` = ellipsis a long name while keeping the trailing icon (the link color is forced `var(--sr-accent)` so a caller's plain-text color can't bleed onto it). **Public-vs-personal is decided by `isPublicHotspot` against a region-scoped Set** (`lib/hotspotSet.ts`): one cached fetch per distinct `stateProvince` region in the backup via `GET /map/hotspot-region` (eBird `ref/hotspot/{regionCode}`) → union of locIds → O(1) membership, NOT one call per location. Tabs get it via the parameterless `useHotspotSet()` hook (loads the backup itself through `observationsCache`; the `getHotspotSet` module cache keys on the region list so all tabs share one build). No key / a failed fetch degrades to an empty Set (everything plain). When a list renders many rows, call `useHotspotSet()` ONCE in the parent and pass `isHotspot` down — don't call the hook per-row. The backend route and `lib/tauri/mapService.ts` `getHotspotRegion` are dual-transport parity — keep them in lockstep, and `/map/hotspot-region` is in `CACHED_GET_PATHS`.
- **The Calendar tab is deliberately OFFLINE / zero-network — render location names there as PLAIN TEXT, NOT through `HotspotLink` (v0.5.63).** The app-wide "a public-hotspot location name links to eBird via `HotspotLink`" convention above is **explicitly waived on the Calendar tab**: `HotspotLink` needs `useHotspotSet()`, whose region-scoped `GET /map/hotspot-region` fetch would add a live network dependency to a tab whose entire promise is that it computes purely from the already-loaded backup and works with no connection. The day-popup checklist rows show the checklist's location as escaped plain-text JSX (no anchor, no `OutboundLink`, no fetch); a code comment in `Calendar.tsx` marks this, and this note makes it a durable convention so a future dev doesn't "upgrade" those names into linked hotspots and silently break the tab's offline guarantee. Any new Calendar-tab surface follows the same rule.

### Overlays and stacking

- **Sighting-pin maps use the shared `SightingsMap` (`components/SightingsMap.tsx`) — don't re-inline the Species Detail pins map (v0.5.26).** It owns the DOM `<Marker>` pins, the single state-driven `<Popup>` (its own `selectedCoord`), `MapBoundsFitter`, and the static `SP_PIN_HTML` sprite; Species Detail and the Named Birds card both consume it. Build its `markers` with the pure `lib/sightingMarkers.ts` `buildSightingMarkers` (skip null coords, group by `lat,lng`, dates newest-first) so skip-null / empty→no-map / same-coord aggregation stays one tested function. ### Media embeds

- **An inline Macaulay Library media embed is `macaulaylibrary.org/asset/<id>/embed` in an iframe — IDENTICAL for photo/audio/video (only the id + player height vary) — and its catalog id is `^\d+$`-guarded + `encodeURIComponent`-wrapped before it reaches the `src`.** The Named Birds media (`components/NamedBirdMedia.tsx`, v0.5.66) and Species Detail both use this. - **Cornell runs an Anubis bot gate in front of `macaulaylibrary.org`, and a mounted player CANNOT pass it — the gate is detected out-of-band and the frame is never mounted while it is up (v0.5.76).** The interstitial needs `Secure; SameSite=None; Partitioned` cookies a cross-site iframe cannot hold, so it renders Cornell's "Missing feature Cookies" card. **The existing give-up timer and `onError` are structurally blind to this** — the interstitial is a same-status HTTP **200** that fires `onLoad` — and `fetch` cannot see it either (no CORS headers on the endpoint), so detection MUST leave the page through the transport seam: `GET /media/embed-status` (`backend/routers/media.py`) with its desktop twin `lib/tauri/mediaService.ts`. **Keep the twins in lockstep**: the same browser User-Agent (the gate only challenges browser-shaped requests — with a default agent the real page comes back and the probe reports "not gated" while every viewer is blocked), the same two independent markers (the interstitial's markup ids AND its `anubis` cookie name, so a change to either alone cannot blind the probe), and the same result shape. Match the page as SERVED, never the visible "Missing feature Cookies" text — that string is not in the HTML, the challenge's own script writes it later. `lib/mlEmbedGate.ts` owns the client side: session-scoped, single-flight, and **NOT** in `CACHED_GET_PATHS` (one caching layer per call). Two properties are load-bearing and must survive any refactor: it **FAILS OPEN** (any probe failure resolves to not-gated, so a probe that cannot run never hides working media), and the signal is **GLOBAL, not per-viewer** (nothing in the page can observe a cross-origin frame's outcome), which is what lets it self-heal with no code change when Cornell lifts the gate. Do NOT "fix" this by rendering media directly from `cdn.download.ams.birds.cornell.edu` — that path works and was deliberately rejected (see DECISIONS.md v0.5.76): this project works alongside Cornell's free services, not around their protection.
- **Every inline-media surface consumes the one hydrated App-root eligibility gate before it can mount player machinery (v0.5.72).** `useEmbeddedMediaPreference` owns the durable `disableEmbeddedMedia` setting; its unresolved `null` state and saved `true` both mean `embedAllowed === false`, while only the exact hydrated value `false` opens the gate. The setting itself stays off by default and uses the storage seam, never raw `localStorage` or component-local persistence.
- **A slow/broken/offline inline embed degrades via a NON-DESTRUCTIVE overlay — keep the iframe MOUNTED for its lifetime and flip only a `position:absolute` fallback over it; NEVER unmount the frame on a timeout (v0.5.66).** The naive give-up timer that tears down the iframe was caught in review: it kills a slow-but-working embed and latches a permanent "unavailable" state with no recovery. Online status comes from the shared `useOnline` hook (`lib/useOnline.ts`, extracted from the `SnowMap` `navigator.onLine` + `online`/`offline`-listener pattern): read `navigator.onLine` in the state initializer and event handlers ONLY, never in a render body or memo (render-purity). NOTE: as of v0.5.71 these frame/fallback/shimmer primitives are SHARED in `components/MediaEmbed.tsx` (constants split to `lib/mediaEmbed.ts` so the component file stays component-only for react-refresh), used by BOTH Named Birds and Species Detail's Recent Media (`components/RecentMediaEmbed.tsx`, extracted so it's unit-testable without SpeciesDetail's maplibre deps). Species Detail's Recent Media also shows an info + attribution row beneath each player — capture date, a Macaulay Library link that opens that asset (its required credit + a way to view/play it), and the eBird checklist — and uses ONE uniform full height for all three formats (`.sr-media-iframe--recent`, 230px / 280px-phone): the compact per-format audio height (116px) clips the Macaulay audio player's controls under the frame's `overflow:hidden`. `MediaFrame` takes a **REQUIRED** `compact` prop so each caller picks its fallback density — required, not defaulted, because a default that encodes a display decision is invisible at the call site and silently hands the next caller a choice they did not make. **The discipline belongs where the display decision is MADE, not on every forwarder in the chain (v0.5.80).** A component that merely passes the prop through to a host that has already decided may default it; making it required all the way up just relocates the same invisible choice into a wrapper's call site and forces unrelated callers to answer a question they have no stake in. Pin Share is the reference: `compact` is required on `SharePin` and `SharePopup` (which render it) and defaulted on `SightingsMap` (which only forwards it). **The Macaulay audio player needs ~230px to expose its transport controls; anything near the old compact 116px clips them under the frame's `overflow:hidden`, so audio anywhere in the app gets the full height (v0.5.75 gave Named Birds' audio the same 230px / 280px-phone as Species Detail).** Named Birds keeps its OWN per-format classes (`.sr-media-iframe--photo/--video/--audio`) rather than adopting `--recent`, so the two surfaces stay independently tunable even where their current values agree; both call sites now pass `compact={false}`. Reuse these shared primitives for any inline ML embed; pick the tile height per surface. **A caller that reaches `MediaFrame` down two independent paths (one it renders directly, one the shared child renders internally) must pass the display choice at BOTH, and each path needs its own test — a single combined test passes on a half-fix.**

### Security — standing checks

- **The atlas block popup is built as escaped JSX (`AtlasLayer.tsx`), not an HTML string.** Block name/code render as React children (auto-escaped) and the eBird atlas URL is `encodeURIComponent`-wrapped, so it's injection-safe even though the data is bundled/trusted (`ca-atlas-blocks.json`). **Standing check:** keep this popup — and the other map popups — as JSX; do NOT switch atlas/marker popups to `dangerouslySetInnerHTML`. The few `dangerouslySetInnerHTML` uses on the maps are static SVG constants or run user/external text through `escHtml` first (e.g. the target-chip label in `MapExplorer.tsx`); preserve that.
- **An eBird id from CSV data is shape-validated before it becomes a link.** Gate a checklist `href` on `SUBMISSION_ID_RE` (`/^S\d+$/`, from `components/speciesDetail/ui`) — and a location id on `/^L\d+$/`, a catalog id on `/^\d+$/` — before interpolating it into an anchor; render the id as plain text when it doesn't match (don't ship a styled 404 link from a junk column value). For checklist links this guard now lives inside the shared `ChecklistLink` (so every checklist site inherits it); apply it directly for location/catalog ids and anywhere else a raw id becomes an href. Pair it with `encodeURIComponent` where the id rides in a query string.
- **User/API comment text renders only through the shared `components/CommentText.tsx`** — escaped JSX segments, anchors emitted only for validated `http(s)` URLs. Its input contract matters: pass entity-ENCODED text (eBird API data, e.g. the comparer) as `raw`; pass ALREADY-DECODED text (anything from `lib/checklistsTab.ts` / `stripWeatherTideBlocks`, which operate on decoded text) with the `decoded` prop. Never decode twice — a double decode renders text differently than written and breaks the Checklists tab's display==search invariant.
- **Module-level `/g` regex hygiene (0.5.27 post-mortem):** a global regex carries shared mutable `lastIndex`, and `String.prototype.matchAll` CLONES the regex *including* its current `lastIndex` — a stale offset silently skipped matches and made the weather/tide strip fail order-dependently. Reset `lastIndex` (or scan once up front) before any reuse. Regexes that scan untrusted comment text must also be linear by construction: precompute match positions in single passes and length-bound lazy quantifiers (`commentBlocks.ts`, same posture as `namedBirds`' `NAME_TAG_RE`) — the unbounded version was quadratic (4.1s on a 400KB hostile comment, on the main thread).
- **A backend pydantic pattern that twins a JS shape guard must use `[0-9]`, never `\d` (0.5.54 security review).** pydantic v2's rust-regex engine treats `\d` as Unicode decimal digits — `US-CA-٠١٢` passed `^US-[A-Z]{2}-\d{3}$` — while the JS twin's `\d` is ASCII-only, so the "same" pattern validates differently on the two transports. Write explicit ASCII classes on the Python side of any twinned guard, and include a non-ASCII-digit case in the malformed-input test (`/map/county-species` in `backend/routers/map.py` is the reference).
- **A route that interpolates a user-supplied value into an OUTBOUND URL must constrain that value to a character class which cannot express a scheme, host, credential, or path separator — and must say in its docstring why the destination cannot be steered (v0.5.76 security review).** This is the SSRF check, and it is the one that matters whenever the backend fetches on the user's behalf. `/media/embed-status` is the reference: the host and path are a module constant and only `^[0-9]+$` (bounded length) can reach the single interpolated segment, so no `://`, `@`, `?`, or `../` is representable. Also confirm redirects are not followed (`httpx.AsyncClient()` defaults to `follow_redirects=False`) so a third party cannot bounce the request elsewhere, and never reflect the upstream body, headers, or cookies back to the client — reduce the response to the minimum the app needs.
- **When a refactor RELOCATES security-relevant code, prove it byte-identical against the pre-change revision — don't reason about it (v0.5.77).** Consolidating four routers onto the shared `datadir.py` moved the base path every settings-store traversal guard resolves against, and "I didn't touch the guard" is not evidence. Diff the guard-bearing code against HEAD, and diff the whole surface the refactor could have moved (the OpenAPI schema was diffed in an isolated worktree: identical, 31 endpoints, same order, catch-all still registered last). This repo consolidates constantly, so treat it as the standing check for any such move. **Sharpened in v0.5.81: identical declaration values are necessary but NOT sufficient when the refactor also LOWERS specificity.** Lifting an inline style (1,0,0) into a class (0,1,0) hands every other rule in the stylesheet a chance to win that it did not previously have, so the proof needs a **cascade-competitor scan** alongside the value diff. Two things that scan must get right: (1) it covers **every stylesheet the bundle emits**, not just `globals.css` — SnowRaven also ships `maplibre-gl.css` (imported by `SnowMap.tsx`, emitted as a lazy `vendor-maplibre-*.css` chunk that stays in the document once any map tab has mounted, and the larger of the two); and (2) it tests the **rightmost compound** of each selector, since an ancestor part of a descendant combinator can always be satisfied. Where the lifted rule's correctness depends on beating Tailwind preflight (its `* { padding: 0 }` competes directly with any `padding` a lifted class adds), record the **layer**, not only the specificity: user CSS in `globals.css` is unlayered and preflight sits in `@layer base`, and unlayered beats layered regardless of specificity. Specificity is the second, independent ground; recording only it means a future move of these rules into an `@layer` would silently forfeit the stronger one. Verify the layer mechanically (brace depth at the rule in the built CSS), not by eye.
- **A lookup table keyed by an UNVALIDATED string must be read through `Object.hasOwn`, so the lookup is allowlist driven (v0.5.81).** A bare `TABLE[raw]` on an ordinary object literal returns a *truthy inherited member* for at least twelve strings — `'constructor'`, `'__proto__'`, `'toString'`, `'valueOf'`, `'hasOwnProperty'`, `'isPrototypeOf'`, `'toLocaleString'`, `'propertyIsEnumerable'`, and the four `__defineGetter__` / `__defineSetter__` / `__lookupGetter__` / `__lookupSetter__` accessors — so a `TABLE[raw] ? mapped : fallback` guard silently takes the wrong branch for every one. A null-prototype table also works; prefer the guard, because its safety is visible **at the point of use**, where a null-prototype construction expression is invisible at the lookup and is exactly what a later reader "simplifies" away with no test failing. `normalizeShareCopySelection` (`lib/shareCopyPreference.ts`) is the reference. **A normalizer's malformed-input test list must include prototype-chain member names**, not just nonsense strings: `''` / `'nonsense'` / `0` / `[]` / `NaN` all exercise the same path, while `'constructor'` and `'__proto__'` exercise a different one. Add a pollution probe too, and **write it with `JSON.parse`, not an object literal** — `{ __proto__: … }` in source is special-cased by the language to set the prototype and creates NO own property, so it tests a shape that cannot arrive from storage; `JSON.parse` produces the real own `__proto__` key that can. (`Object.hasOwn` is the first ES2022-era runtime API in the app's shipped source — Safari 15.4 / Chrome 93 — and was cleared against both native targets: `minimumSystemVersion: "16.0"` on macOS and `IPHONEOS_DEPLOYMENT_TARGET = 16.0`, with Windows on evergreen WebView2. The `es2023` tsconfig target governs syntax downleveling and type-checking, not runtime API availability, and Vite polyfills no runtime methods, so the next such crossing needs the same explicit check.)
- **A "no outbound request" claim is verified by tracing every consumer of the URL-shaped strings, not by grepping for `fetch` (v0.5.81).** The absence of a network primitive is necessary but not sufficient — a URL string can leave the page through an `href`, an `img.src`, a `new URL()` handed onward, a `preconnect` hint, or a navigation. Confirm where each built URL actually goes.
- **A change that alters WHICH COMPONENT makes a third-party request is a `PRIVACY_POLICY.md` change, even when the destination host is unchanged (v0.5.76).** The policy describes who talks to whom, so moving a request from the browser to the self-hosted backend (or the reverse), or adding a request the user did not initiate, needs the policy updated in the same change — the same standing rule as adding a new provider. It is easy to conclude no update is needed because the host was already disclosed; that reasoning is wrong.

### Weather/tide blocks in comments

- **`stripWeatherTideBlocks()` (`lib/commentBlocks.ts`) is the single source of truth for hiding pasted weather/tide blocks** (the Checklists tab's toggle). A block is a SPAN — emoji header → end of attribution link — never whole lines: eBird's CSV export collapses pasted newlines into spaces, so user prose shares the block's line and can continue after the attribution. While blocks are hidden, display AND search both use the stripped text ("search matches what you see"), and an empty-after-strip comment counts as having no comment; the has-weather/has-tide FILTER flags read the raw comment regardless. The marker vocabulary must stay synced with `weatherFormatter.ts`/`tideFormatter.ts` — the tests build fixtures by calling the real formatters so a format drift breaks them. When changing any of this, re-verify against a real export: the three shipped strip bugs (same-line prose, moon-emoji night blocks, attribution-less blocks) were all invisible to formatter-fixture tests and only surfaced on real data.
- **Generated night-block headers are condition emoji + moon-phase emoji, UNSPACED (`☁️🌗`, v0.5.28).** The stripper anchors a block on its LAST emoji run before the first labeled line, so any future header change that splits the emoji into separate runs (e.g. adding a space) will leak the leading emoji on strip — keep the header emoji one contiguous run. The moon emoji needs NO strip-marker vocabulary entry (`EMOJI_RUN_RE`'s `\p{Extended_Pictographic}` already covers it); don't add one.
- **The moon-phase algorithm is a hand-ported `lunarphase-js@2.0.3`** — pure-UTC Julian Day, a deliberate deviation from the library's runtime-tz-dependent form so both runtimes are deterministic and identical — **duplicated byte-for-byte in `frontend/src/lib/weatherFormatter.ts` and `backend/formatters/weather.py`.** Change it in BOTH ports plus the golden oracle (`frontend/src/lib/weatherFormatter.golden.py`) in the same change; the byte-golden tests lock the parity. It is NOT an npm/pip dependency — do not add the library.

### Desktop app seams

Permanent architectural seams route all platform-sensitive operations. Use them in new code — do not bypass them.

- **Transport:** `transport.get()` / `transport.post()` from `frontend/src/lib/transport.ts` — for all outbound HTTP calls. In Tauri mode, `TauriTransport` routes each API path directly to a TypeScript service (weather, map, taxonomy, nominatim, stats, version). In web/Pi mode, `WebTransport` delegates to the Python backend.
- **Caching layers — pick by lifetime.** `CACHED_GET_PATHS` in `transport.ts` is the short-TTL (~90s) repeat-call cache; `replayStore` is the live-first offline replay of a last-loaded result. A **long-TTL persistent network cache** ("hold live data for days") follows `lib/countyCompletenessCache.ts` instead: a storage-seam document with an in-memory mirror, TTL-gated reads, per-entry shape validation on load (malformed entries dropped, never thrown on), entry-count + byte caps with `order[]` eviction, an in-flight dedupe Map, errors never cached, and offline stale-reads served for display. A path served by such a cache stays OUT of `CACHED_GET_PATHS` — one caching layer per call.
- **Storage:** `storage.getApiKey()` / `storage.getSetting()` / etc. from `frontend/src/lib/storage.ts` — for all key, setting, and file access. Do not call `/settings/*` endpoints directly from new components.
- **Platform detection:** `isTauri()` from `frontend/src/lib/platform.ts` — single source of truth for branching on Tauri vs. web. Do not check `window.__TAURI_INTERNALS__` elsewhere.
- **Clipboard:** `copyText()` from `frontend/src/lib/clipboard.ts` — for all clipboard writes. In Tauri mode it uses the native `@tauri-apps/plugin-clipboard-manager` (no user-gesture requirement, so auto-copy after an `await` works); on web it uses `navigator.clipboard` with an `execCommand` fallback. **Do not call `navigator.clipboard` directly** — an async clipboard write that runs after an `await` (outside a click) throws `NotAllowedError` in WKWebView/WebView2 and is silently lost on desktop. The capability grants `clipboard-manager:allow-write-text` only (write, not read).
- **Opening an external URL from code:** `openExternalUrl(url)` from `frontend/src/lib/openExternal.ts` — **never `window.open()`**. `window.open()` is silently dropped in the Tauri desktop WebView (WKWebView never opens the system browser), so an external open works on web but does nothing on desktop with no error (the Weather Backlog's "Copy weather & go" hit exactly this, v0.5.67). The whole app opens external links only via `<a target="_blank">` anchors, which `tauri-plugin-opener` intercepts; `openExternalUrl` synthesizes exactly that — a transient, detached `<a target="_blank" rel="noopener noreferrer">` that is appended, `.click()`-ed, and removed — so it works in BOTH web and desktop. For a **user click**, prefer the shared link components (`OutboundLink` / `ChecklistLink` / `HotspotLink`); reach for `openExternalUrl` only when the open must happen from code (e.g. after an `await`). Keep the same id-shape guard + `encodeURIComponent` on any id in the URL as everywhere else.

### Desktop storage (Tauri)

`TauriStorage` in `storage.ts` uses **`tauri-plugin-fs` with `BaseDirectory.AppLocalData` for everything** — API keys, settings, file metadata, and CSV files. All data lives under `AppLocalData/data/`:

| File | Contents |
|---|---|
| `data/api-keys.json` | API keys (`ebird`, `openweather`) |
| `data/settings.json` | App settings (map center, zoom, etc.) |
| `data/metadata.json` | Uploaded file metadata |
| `data/ebird-backup.csv` | eBird data file |
| `data/ml-export.csv` | ML data file |

Every write calls `mkdir(DATA_DIR, { recursive: true })` before writing to ensure the directory exists.

**Do not use `localStorage`** — it is ephemeral in Tauri's WKWebView and cleared on every relaunch.  
**Do not use the system Keychain** (`keyring` crate / `invoke('get_api_key', ...)`) — it requires entitlements not configured in this app and fails silently.

**Persist all UI settings through the `storage` seam, never `localStorage` directly.** Anything that must survive a desktop relaunch (e.g. the tab layout) goes through `storage.getSetting`/`setSetting`. The web/Pi path may still read `localStorage` synchronously inside the seam for a flash-free first paint, but the seam — not `localStorage` — is the source of truth on desktop. (See the tab-layout post-mortem in DECISIONS.md.)
