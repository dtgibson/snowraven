# Roadmap

This is a living document. It reflects the current best thinking
on what to build next — not a contract. Things change as you learn
more about your users and your product. Update it freely.

## Shipped

98 versions shipped. Last shipped: **Named Birds media (v0.5.66)** -- on the Named Birds tab, each named individual now shows its own Macaulay Library media (photo, audio, video) below its sightings map, each item labeled with the date it was captured and a link to the checklist it came from. A named bird's media is matched by reading each media asset's own comment in your Macaulay Library export for the `[name:…]` tag that names that individual -- not the checklist or species comment, which name the bird but don't point at a specific photo or recording. Media loads on demand as Macaulay Library inline embeds (a bounded batch with a "Show more" button), and degrades gracefully offline or when an embed can't load to a placeholder plus a link out to the asset, always keeping the date and checklist link. The matching, dates, and links work fully offline; only the embed player needs a connection. This is the first inline media on the tab (it previously only linked out), disclosed in the privacy policy. Released bundled with the v0.5.65 sex-terminology wording fix.

Previously: **Calendar date placement (v0.5.63)** -- correcting the v0.5.62 date-placement the user flagged, plus richer day popups. The day-of-month numbers move off the big month grids (now clean count-only cells) and onto the year-overview thumbnails' day cells (with the small-cell legibility floor restored); the year-overview months stop navigating into the big-grid view (they're read-only now -- the Compact/Large toggle is the only way to switch views), and instead each overview day cell opens the day popup in place; and every day-popup checklist row now shows that checklist's start time, location, and species count (time/location/species drawn from the already-loaded backup, location as plain text to keep the Calendar offline). Frontend-only; no new data, providers, network calls, or settings.

Earlier: **Calendar view clarity (v0.5.62)** -- three Calendar-tab refinements. Frontend-only; no new data, providers, network calls, or settings.

Frontend-only; no new data, providers, network calls, or settings.

Earlier: **Mobile-friendliness pass, plus behind-the-scenes tidies (v0.5.55)** -- groundwork ahead of a mobile app, in two halves. The invisible half is a set of internal tidies: the web / Raspberry-Pi build now reuses one shared connection for its outside calls instead of opening a fresh one each time, the Map Explorer's "nearby lifers" and "media targets" views share a single lookup when centered on the same spot, some tests were tightened, and an unused location plugin was removed from the desktop app (your "Use my location" is unchanged). No new data, providers, or network calls.

Earlier: **County Completeness (v0.5.54)** -- a third county-shading metric on the Map Explorer: alongside Species and Checklists, **Completeness** shades each US county you've birded by how complete your county list is -- your countable species recorded there measured against everything ever reported to eBird for that county -- on a fixed 0-100% scale where the same shade always means the same completeness. Click a county for a progress bar ("X of Y species · Z%"), your five newest county birds (from your own backup, so that part works offline), and a five-species chase list of birds on the county's eBird list that aren't on yours yet; a county you've never birded stays a plain outline until you press "Load completeness" to scout it with a single lookup. Unlike the other metrics this one needs a network connection and your eBird key (the control says so right where you pick it); each county's result is cached on your device for 30 days, cached counties still shade when you're offline, and fetching is strictly bounded to the birded counties in view, a few at a time -- never a bulk sweep. Use Textures and the keyboard "Counties in view" list work with it, and the Species/Checklists shading is unchanged.

Earlier: **Map Explorer Point Size control (v0.5.53)** -- a new Point Size control (Normal / Small / Off) on the Map Explorer's My Sightings map, under the Pins/Heatmap toggle in Pins mode, so your sighting points stop obscuring a shaded breeding-block or county map underneath. Small shrinks the points; Off hides them entirely (and their click/popup target) so the shading reads straight through; Normal is exactly as before. It builds on the existing behavior where points already fade when shading is on -- now you can shrink or hide them on demand. Session-only (resets on relaunch), points only (the heatmap is unchanged), no new data or network calls; frontend-only.

Frontend + backend internals; no new network, providers, or data.

## On the Horizon

Ideas worth tracking, not yet scheduled:

- **Backport the inline-embed offline/failed-load fallback to Species Detail** -- v0.5.66's Named Birds media is the first inline embed in the app with graceful degradation (a non-destructive `MediaFrame` overlay that keeps the iframe mounted, plus the shared `useOnline` hook), so a slow, broken, or offline embed shows a link-out placeholder instead of a dead frame. The pre-existing Species Detail "Recent Media" embed still has no such fallback and would benefit from the exact same treatment. Deferred out of v0.5.66 (Species Detail was out of scope); a natural, low-risk follow-on now that the reusable pattern exists.
- **Richer Calendar day popups / county-style shading parity** — the Calendar day popup now lists a day's checklists with each row's time, location, and species count (v0.5.63), but still not the day's *species*; a natural parallel would extend the map's county-style shading affordances (e.g. a per-species calendar, or listing the day's species names in the popup). Not requested — noted as an obvious follow-on to the shipped tab.
- **County shading on the Species Detail and Statistics maps** — the breeding atlas already appears on those maps, so extending the county overlay to them is a natural parallel (deferred out of the v0.5.46 county feature; it would now carry all three metrics, including v0.5.54's Completeness).
- **Completeness targets ranked by findability** — upgrade the county-completeness targets list from its v0.5.54 taxonomic-order floor to a "which could I actually chase" ranking. The public eBird API has no all-time frequency product and the recency-based alternative doubles the per-county calls, so this needs a data-source decision; the `completenessTargets` seam accepts a ranked pool without a route change.
- **Non-US county support** — v0.5.46 draws US counties only (public-domain Census/TIGER geometry); other countries' eBird Subnational2 regions would need different boundary sources and naming.
- **Per-species county choropleth** — "shade the counties where I've seen Acorn Woodpecker" — a larger, different feature than the all-species county life-list shading.
