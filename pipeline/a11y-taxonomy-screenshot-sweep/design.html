01Statistics · Rainbow Connection name rows

The name cluster is min-width: 0; flex-shrink: 1 and duly crushes to 54px, but BirdName's row is white-space: nowrap with an indivisible two-link group, so 157.8px of name hangs out of a 54px box. Letting the name wrap costs a second line and keeps both links, their targets, and their accessible names.

02Statistics · Breeding tier chips

A chip at min-width: auto measures 92.3px inside a 242px row that will not break between chips. The tier vocabulary is four short words, so the row wraps and the chip keeps its size.

03Statistics · Temporal best-day links

An inline flex-shrink: 0 makes any wrapping class inert — a container that is never narrowed never breaks a line. This is the shape v0.5.82 already recorded, so the remedy is the recorded one: pair it with max-width: 100% rather than deleting the shrink guard.

04Calendar · the Year group and the day cells

Two contributors, one cause. The Year group is a flex item at min-width: auto holding a non-wrapping stepper; the day buttons are floored at min-content inside 32.6px grid tracks. Fixing only the first leaves 18.4px, so both land together. “All years” drops to its own line at 200%; at 100% nothing moves.

05Checklists · not a design change

The 42px here is a screen-reader-only announcement being handed a visible layout box. There is nothing to redesign; a selector is reaching an element it was never meant to describe.

.sr-only is written correctly, then overridden by the phone tier:

<span class="sr-only" aria-live="polite">368 checklists</span>

@media (max-width: 480px) {
  .sr-field-row > * { width: 100%; }   /* globals.css:3304 */
}

Because .sr-only is absolutely positioned, width: 100% resolves against its containing block rather than the row — a 320px box at x=42, right edge 362. Exclude the live region from the stacking rule; the same shape at globals.css:2978 takes the same exclusion. Nothing visible changes, and the region keeps its announcement behavior untouched.
