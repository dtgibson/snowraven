## Android release (android-release)

### What this does
Builds SnowRaven for Android 8.0 and later from the same Tauri project as every other platform: a committed Android project with the application id `com.dtgibson.snowraven`, the iPhone app's compact chrome and phone bar, the app's own colors under the status and navigation bars (with the bar glyphs following the theme the page painted), the keyboard kept clear of the focused field, a green launch with no white frame, and a plain message when the phone's Android System WebView is too old. Every Apple-only surface (iCloud Sync, widgets, Alerts, the updater) is absent rather than broken. The release leg is F-Droid (which builds from source) plus a signed universal APK on the GitHub release; Google Play is not a channel.

### How to test
1. Follow `pipeline/android-release/how-to-see.md` to build the unsigned universal APK with `sh scripts/android/build-apk.sh`, then a throwaway-signed one, and open it on the `sr-api36-phone` emulator (run emulators with `-gpu host`).
2. Expect the welcome screen first. In Settings, the rows read **Import file…**, and pressing one opens the system document picker; backing out changes nothing. Settings shows no iCloud Sync, Alerts or widgets section and no update footer.
3. Flip the emulator to dark (`adb -s emulator-5554 shell cmd uimode night yes`) with the app open under Appearance > System: the page and both bars' glyphs change together. Choose in-app Dark with the system light: both bars' glyphs turn light.
4. Focus any text field: it scrolls above the keyboard and the phone bar slides away; close the keyboard and the bar returns.
5. On the API 26 image (Android 8.0, stock WebView Chromium 58) and the API 30 image (Chromium 91) the app shows the floor message under the raven mark on the green launch frame, with no Reload, instead of the app.
6. Location is branch B (the FR-55 measurement failed its step 9: during a fix the app's own UID held a connection to a Google address, and two controls without a location request held none). The Weather tab offers Plan with no Current, the Map Explorer has no locate disc, and Settings' Default Location has no Use my location; nothing on screen says why, and Help says to search or set a Default Location.
7. Run the frontend suite: the Android guards are `androidProjectPins`, `androidVersionSource`, `androidIcons`, `androidReachableCalls`, `androidReadings`, `androidInsetsCss`, `location.android`, `importMechanism`, `fdroidRecipe`, `androidLicense`, plus the Android rows in `isIOS`, `platformGates` and `launchSplash`.

### Notes for reviewer
- **The floor is minSdk 26, not 24 (the user's decision).** The locked Tauri 2.11.2 Android runtime pins jackson-databind 2.15.3, whose `ExceptionUtil.isFatal` references `java.lang.BootstrapMethodError` (API 26+), reached from a static initializer: the app crashes at launch on API 24 and 25. Measured on the API 24 emulator; the record is under "BLOCKER" in `decisions.md`.
- **Nothing from Google's proprietary families compiles into the Android build.** `tauri-plugin-geolocation` (whose Android module links Play services) is now iOS-only in `Cargo.toml`, `lib.rs` and a new `capabilities/ios.json`; `capabilities/mobile.json` grants only the dialog. The merged runtime dependency tree (kept under `pipeline/android-release/measurements/dependency-tree/`) has no `gms`, Firebase, Play, billing, ads or ML Kit coordinate; the three `com.google.*` coordinates in it are Apache-2.0 libraries (Material Components, error_prone_annotations, the `listenablefuture` stub). The APK asks for INTERNET only and has one activity.
- **The launch frame now draws in old WebViews.** It used the `inset` shorthand (Chromium 87), so on Android 8 to 10's stock WebViews (Chromium 58 to 86) the frame collapsed to nothing and the floor message never showed; the API 26 emulator found it and the API 30 one could not. `index.html` now writes the four offsets and a plain fallback before its `max(..., env(...))`, and `launchSplash.test.ts` holds the launch stylesheet to that.
- **The F-Droid recipe is the form F-Droid's own tools accept.** Schema 6.5's `scandelete` entries for `node_modules` fail fdroidserver's scan, so the prebuild removes `frontend/node_modules` after the frontend build and `scandelete` names only the DMG layout file; the file is in `rewritemeta`'s layout with the changelog on `/blob/HEAD/`. Locally, `fdroid lint -f` and `rewritemeta -l` are clean, the scanner finds nothing, and `fdroid build` built the app from source (`pipeline/android-release/fdroid-verification.md`); only the recipe's `sudo:` block waits for fdroiddata's own pipeline.
- **The build is `cargo tauri`, everywhere.** Gradle's Rust tasks call back into the CLI, so a bare Gradle run cannot build this app; `BuildTask.kt` now calls `cargo tauri` (tauri-cli 2.11.2 from crates.io) instead of `npm run -- tauri`, the wrapper jar and `gradlew.bat` are not committed, and `gradlew` is a shim over Gradle 8.14.3 on PATH. CI and the F-Droid recipe run the same two lines.
- **`bundle.android.versionCode` is committed** in `tauri.conf.json` (1000048 for 1.0.48) so F-Droid can read it at the tag; the Deployer moves it with the version at the bump. Android has no build number.
- **`MainActivity.kt`** is the one hand-edited Kotlin file: the inset listener and the `srAndroid` theme channel (origin allowlist `http://tauri.localhost`, `light`/`dark` only). A regeneration of the Android project overwrites it; the release skill's Android section has the keep-aside-and-restore procedure, and the guards go red if an edit is dropped.
- **Held, not written:** the Fastlane listing, the website and README sentences, the privacy policy edits and the What's New line are in `pipeline/android-release/held-copy.md` for the user's yes. `ACCESSIBILITY.md`'s platform list was edited (one clause naming Android) because its published-claims guard ties it to the capability files.
- **The release Mac's leg is three scripts:** `scripts/android/preflight.sh`, `sign.sh` and `attach.sh`, sharing `release-lib.sh`. Preflight checks the toolchain, the keystore (printing the user's one-time `keytool` step when it is missing), the version pair and the tag, and the CI artifact from the run pinned to the tag's commit; sign uses `zipalign -P 16` (16 KB page alignment, which `-p` would undo) and `apksigner` with the passwords by file; attach only runs `gh release upload` onto the release `release.sh` made, after `ANDROID_DEVICE_CHECK`, and refuses the throwaway or debug signer. They were dry-run with the THROWAWAY key, attach against a `gh` stand-in that refuses writes; nothing was attached. `androidProjectPins.test.ts` pins their no-keystore-creation, passwords-by-file and no-release-create rules.
- **The fdroiddata merge request** is written out step by step in `pipeline/android-release/fdroid/merge-request.md`, with the deferral sentence the Deployer records if it waits.
- **Known limitations:** the tablet's fullscreen map and portrait reading, three-button navigation, a cutout in landscape, the largest system font, a full import with real files and the AOSP location reading are not yet measured on an emulator; the staged F-Droid screenshots have no Weather shot (it needs an OpenWeather key in the app, which the capture did not enter), so Multimedia takes that slot; the release scripts' `gh run download` and upload paths were not exercised (no tag carries the Android build yet); the iOS app's bundled Help now names Android, which App Store guideline 2.3.10 can question; on the Map Explorer's My Sightings view with no backup, the floating discs overlap the setup card's Go to Settings button at phone width (shared with iPhone, not checked there).
