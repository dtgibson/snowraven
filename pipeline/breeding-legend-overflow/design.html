A legend label that will not fit

At 320px and 200% text scale, the Breeding Codes tier legend runs 81px past its own content box and off the edge of the screen. The labels must stay fully readable (v0.5.56), so the only honest answer is to let them wrap. The refinement is three declarations at the phone tier, in Normal view only — and each one is load-bearing.

Why plain wrapping stays readable, and is not a mess

The worry with wrapping a row of chips is that a continuation line strands a word next to the start of the following chip — Material  DD Distraction reading as one run. That cannot happen here, and it is a property of flex line collection rather than luck: items are collected onto a line only while they fit, so an item wide enough to wrap is always alone on its flex line. Confirmed on the render at every probed configuration — zero shared lines. Every line in the panel above therefore begins with a bold code, or is a continuation of the line above it.

The refinement

Two new class names, one view modifier, and a lift of the chip's inline white-space so a media query can reach it.

/* top level — byte-identical to the inline value it replaces, so every
   view at every width above the phone tier renders exactly as it ships. */
.sr-bc-legend-chip { white-space: nowrap; }

@media (max-width: 640px) {
  /* Normal view only. The modifier is present exactly when the card is
     NOT .sr-bc-card, so this block cannot match in Unbounded — the
     v0.5.84 rule keeps reading the legend it always read. */
  .sr-bc-legend--normal .sr-bc-legend-tier { min-width: 0; }
  .sr-bc-legend--normal .sr-bc-legend-chip {
    white-space: normal;
    min-width: 0;
    overflow-wrap: break-word;
  }
}

Why three declarations and not one. Relaxing white-space alone leaves 22.19px still leaking. The tier group and the chip are both flex items with min-width: auto, whose automatic minimum size is their min-content width — and one label, C Courtship/Display/Copul., contains a 24-character run with no break opportunity that measures 236.19px against a 214px line. Both ancestors were being floored at that width. Releasing the floors lets the box reach the line; overflow-wrap: break-word then breaks that one run. Each declaration was removed in turn and the leak returned.

The last two rows are why QA must measure ink, not boxes

Two of the mutations leave a box measurement reading a clean zero while text hangs 22px and 81px outside it. Once a box is allowed to shrink to the line, an unbreakable run simply overflows it, and getBoundingClientRect() on the element cannot see that. The brief's harness measures element boxes against the container's content box, which is right for the baseline — where nowrap text fills its box exactly — but will certify a half-fixed build as clean. Verify with client rects over the text (a Range per text node), not element boxes.

The one rough edge, and what I am not fixing here

One label out of 23 still reads poorly, and the cause is its copy rather than its layout.

Because Courtship/Display/Copul. has no break opportunity — Chromium does not break after / here — the browser first pushes the whole label off the code's line, then breaks it mid-word. It reads:

C
 Courtship/Display/Co
pul.

That is bounded and legible, and it is the correct behaviour for CSS that must hold for any label. But the real repair is the string: eBird's own name for code C is Courtship, Display, or Copulation, and the commas are break opportunities. Rendered with the label reworded, the same configuration gives C Courtship, Display, / Copulation — no orphaned code, no mid-word break, one line shorter.

I am deliberately leaving it out. The label is a compile-time constant that also feeds the column title and the sort button's aria-label, so rewording it changes desktop rendering and an accessible name — a copy decision with reach well past this tier, and past a brief scoped to constraining the chip column. It goes to the roadmap with the measurement attached. The CSS must not be made to depend on it.

Scope: why Unbounded and desktop cannot move

  • Unbounded is a property of the stylesheet, not of a measurement. The refinement is scoped to .sr-bc-legend--normal, which the component adds exactly when wideMode is false — the same condition under which it omits .sr-bc-card. The two can never co-occur, so the block cannot match in Unbounded. This is doing real work, not belt and braces: min-width: 0 on the tier group lowers the legend's min-content, which is precisely the value .sr-bc-card > .sr-bc-legend reads. Scoping is what keeps v0.5.84's floor untouched.
  • v0.5.84's rule is not edited, and its rejection is not reopened. width: min-content; min-width: 100% stays byte-identical. overflow-wrap: anywhere was measured and rejected: it renders identically to the chosen rule (same lines, same height, same zero leak), so it buys nothing, and it would collapse min-content to a single character — the shape that decision named. break-word never affects intrinsic sizing.
  • Desktop is above the tier. The base rule reproduces the inline nowrap exactly; nothing else changes above 640px.
  • The cascade was scanned after the specificity lift. Moving white-space from an inline style (1,0,0) to a class (0,1,0), and giving two previously unclassed elements their first class, opens them to rules that could not reach them before. Across globals.css and the bundled maplibre-gl.css, testing the rightmost compound of every selector that sets white-space, min-width, overflow-wrap, word-break or line-break: one hit, .sr-bc-card > .sr-bc-legend, which targets the legend rather than either newly classed element and is unaffected.

What I traded

  • Vertical height for horizontal containment. At 320px / 200% with all 23 codes, 11 of the labels take a second line and the legend grows from 1014px to 1410px — measured on the frames above. This tab is already a natural full-height, page-scrolling table by decision (v0.5.69); vertical scroll is the currency it already spends, and horizontal leak is not.
  • A wrapped label is not indented under its code. I designed a hanging indent and rejected it: padding-left changes the chip's box at every width in the tier, including the configurations measured clean, and the brief requires those to hold. The chosen rule is inert wherever nothing overflows — verified by fingerprinting every chip's x/y/w/h to 1/100px across 40 configurations, where only the 7 already-leaking ones move. The compensating cue is the bold code that already opens every chip.
  • One label breaks mid-word until its copy is fixed. Named above.
  • Two class names and a view modifier added to a component that was already carrying four. The alternative — a structural :not(.sr-bc-card) > div selector — would be shorter and far more fragile.

Rejected, with reasons

Break beside the code. Insufficient alone — the label without its code still exceeds the line — and it costs every chip a second line to fix a problem that only about half of them have.

Collapse the tier-dot indent on phone. Measured insufficient by the brief (24px recovered of 81px needed), and the indent is what groups a tier's codes under its heading at exactly the moment the legend is tallest.

Scroll the legend. Adds a second horizontal scrollport to a tab that already has one, and makes a touch user swipe sideways to read the very meanings that v0.5.56 spelled out for them. It answers the measurement and reverses the decision.

Force one chip per line at the tier. Unnecessary — flex line collection already guarantees it wherever a chip wraps — and it would restructure the legend at 640px / 1×, where it works.

Frames render the shipped legend markup at 320px with the root font size doubled, in the app's own --font-sans stack and --sr-* tokens for both themes — a different face would move every wrap point and make this document fiction. Figures measured in Chromium against a reproduction that agrees with the brief's independently measured baseline to 0.01px (64.16 against 64.17, widest chip 278.16 against 278.17), and that reads clean at a known-good 1440px / 1×.
