# Bug Brief — capture-provenance-route-scope

## What is broken
`website/tools/capture.mjs` installs the Statistics escapee-pass stub (`installProvenanceRoutes`, `capture-lib.mjs:170`) on EVERY browser context through its `page()` wrapper (line 74), under the comment at lines 65-69: "Built once and installed on every context (harmless on tabs that make no such lookup)." It is not harmless. Registering ANY Playwright route on a context, whatever its pattern, cancels every cross-origin `<img>` load in that context: measured with Playwright 1.62.1 / Chromium 1234 via CDP, both favicon requests are issued and die with `Network.loadingFailed errorText=net::ERR_ABORTED canceled=true` (no CORS error, no blocked reason), identically for the real `**/checklists/**` pattern and for `**/zz-never-matches-zz/**`, eager or `loading="lazy"`; with no route both load (48px natural). The species link glyphs are exactly such loads (`SpeciesLinks.tsx`: `https://ebird.org/favicon.ico`, a 302 to S3, and `https://birdsoftheworld.org/favicon.ico`, a direct 200; `onError` sets `visibility: hidden`), so every shot of a tab that renders `BirdName` / `SpeciesLinks` publishes empty 14px slots where an online user sees the eBird and Birds of the World glyphs. `capture-appstore.mjs` already scopes the stub per shot (`statsRoutes` on `02-statistics.png` only, lines 203-207 and 310) and is correct as-is; `capture.mjs` predates that shape (the stub was ported onto it wholesale in v1.0.4).
Same-origin traffic and fetch-initiated cross-origin loads are not affected: the app rendered, `/taxonomy/codes` resolved, and the map's OpenFreeMap tiles drew on an intercepted context. The breakage is specific to `<img>` element loads.

## Steps to reproduce
1. Isolated (no backend, ~20 s): with `website/tools/node_modules/playwright`, open a page from a local `http://` origin containing the two `<img>` tags from `SpeciesLinks.tsx`. With no route both report `naturalWidth 48`; add `ctx.route('**/checklists/**', r => r.fulfill(...))` (or any non-matching pattern) and both fire `onerror`, with the CDP failure above. Probe scripts used: `/private/tmp/claude-502/-Users-developer-devwork-snowraven/5419ba04-b1b7-4e56-88ba-b9be2ca89925/scratchpad/probe{-route-favicon,2,3}.mjs` (scratchpad, not in the repo).
2. In-repo: run the capture per `website/tools/README.md` (backend on 1620 with `SR_DATA_DIR=<repo>/website/tools/demo-data`, frontend built, `BASE=http://localhost:1620 node capture.mjs`), then open `shots/species-light.png`: no glyphs beside "Northern Cardinal" in the header; `shots/named-birds-light.png`: none beside Ring-billed Gull, Rock Pigeon, Mallard.
3. The reporter's own measurement on the real run: 87 anchors either way; 128 favicons loaded with the stub not installed, 0 with it.

## Expected behavior
The shots of tabs that render species links show both glyphs beside each species name, as an online user sees them. The Statistics shots keep the stub, because without it the escapee pass 404s against the synthetic ids and the tab photographs "eBird could not be reached" instead of "Exotic status checked across 15 checklists. None of your species are eBird escapees." The comment states the real cost of a registered route instead of calling it harmless.

Worth also touching: the `installProvenanceRoutes` JSDoc in `capture-lib.mjs:167-169` (the shared function is the right home for the "any route cancels cross-origin img loads, scope it" note, since both consumers call it) and the Statistics paragraph of `website/tools/README.md`. ## What done looks like
1. `capture.mjs` registers the stub only on the three Statistics contexts (two desktop `tab('Statistics', ...)` calls and the mobile Statistics block), mirroring `capture-appstore.mjs`'s per-shot routes column; every other context has no route registered (the `WEATHER_REPLAY` abort on the weather context excepted, by design). The lines 65-69 comment no longer says "harmless" and names the measured mechanism and the scoping rule; ideally the shared JSDoc in `capture-lib.mjs` carries it too.
2. `species.webp`, `breeding.webp`, `multimedia.webp`, `named-birds.webp` recaptured from the demo backend and verified BY INSPECTING the produced images: both glyphs visible beside species names (Species Detail header; Breeding Codes and Multimedia table rows; the three Named Birds rows). `statistics.webp` re-run or unchanged still shows the terminal "Exotic status checked across N checklists" sentence, never the "eBird could not be reached" banner. Only the intended files are committed; every committed image shows its intended tab (an exit code of 0 is not proof).
3. Cheap measurement, if the rig allows: on an affected tab's context, `document.querySelectorAll('img.sr-favicon')` with `naturalWidth > 0` is 0 before and equals the anchor count after (the isolated probe in step 1 of reproduction reproduces the mechanism in seconds with no backend). Playwright's built-in `page.on('request')` events did not surface these image requests on this rig; use a CDP `Network` session if the count is measured by events.
4. Standing rules: no em dash (U+2014) enters user-facing copy under `website/` (none is expected to change; code comments and `website/tools/README.md` are outside that rule's scope). The demo-dataset guard must pass before the first frame; the backend must be started with `SR_DATA_DIR` pointed at `website/tools/demo-data`, never a moved-aside real `data/`.
