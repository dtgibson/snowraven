# Strategic Brief — Checklist Weather Lookup

## What We're Building
A single-screen web tool that accepts an eBird checklist number, fetches the checklist's time and location from the eBird API, retrieves historical weather data from OpenWeather, and returns a formatted text block ready to paste into an eBird comment field.

## Why Now
This is the first and only feature — it is the product. There is no earlier version to build on and no later feature that makes sense before this one exists. Building it now is the only right move.

## The User Problem
A birder finishes logging an observation on eBird and wants to include weather context in their checklist notes. The public tools that do this are rate-limited and could disappear. Without owning this workflow, the user is dependent on a service they don't control.

## Success Criteria
- User pastes a checklist number or URL into the app and gets a formatted weather block within a few seconds
- The output is identical in structure to raincrow.app: emoji, condition, temperature range, wind, cloud cover, humidity, dew point, sunrise/sunset
- The user can copy the output to clipboard with one click and paste it directly into eBird
- The app runs correctly on localhost and on a Raspberry Pi with no changes

## Scope
- Input: eBird checklist number or full checklist URL (both accepted)
- eBird API call to fetch checklist date, start time, duration, and coordinates
- OpenWeather One Call API (historical/timemachine) call for that time and location
- Formatted text output matching the raincrow.app format
- One-click copy to clipboard
- Error states: invalid checklist number, API key missing, checklist not found, weather data unavailable

## Out of Scope
- Saving or history of past lookups
- User accounts or authentication
- Any output format other than the raincrow.app text block
- Support for weather providers other than OpenWeather
- Batch lookups (multiple checklists at once)

## Key Decisions
- Accept both checklist number and full URL as input — strip the URL to extract the number
- Use OpenWeather's historical "timemachine" endpoint, not current or forecast
- Temperature displayed in Fahrenheit
- Wind described in plain English (light breeze, gentle breeze) not raw mph — match raincrow.app convention
- Attribution line in output will read "Weather generated by SnowRaven" replacing the raincrow.app attribution
