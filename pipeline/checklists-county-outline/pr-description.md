## Checklists county outline (fix, 1.0.35)

### What this does
On Checklists, choosing a county or protocol and then "All counties" / "All protocols" now returns the picker's outline to its resting `--sr-border`, instead of leaving it in the text colour until reload. The closed species picker (Calendar, Species Detail, Statistics' weather section, Map Explorer) now draws its bottom edge in `--sr-border-input` like its other three sides. All three sites had one root cause: React clears a removed or emptied colour longhand and never re-applies the unchanged `border` shorthand it overlapped, so the colour fell back to `currentcolor`.

### How to test
1. `cd frontend && npm run build`, then `cd backend && .venv/bin/uvicorn main:app --port 1620`, and open http://localhost:1620 with an eBird backup loaded.
2. Checklists tab, "Where & when" row: choose a county. The outline turns the accent tint and the text turns accent and bold, as before.
3. Choose "All counties". The outline goes back to the same light grey it had on first load (near-black in light theme and near-white in dark theme before this fix).
4. Do the same with the Protocol picker in the Effort row and "All protocols".
5. Calendar tab: look at the closed species picker. The bottom edge is the same grey as the top and sides. Open it with the chevron: accent top and sides, no bottom edge where the list attaches. Close it: all four sides grey again.
6. Repeat at a phone width (390px) and in dark theme.

### Notes for reviewer
- **The fix.** "Conditional values, never conditional keys." `selectStyle` in `Checklists.tsx` now uses `borderWidth` / `borderStyle` / `borderColor` longhands, so the set state's `borderColor` override replaces a key that is always present and a clear writes the resting value back. `SpeciesCombobox.tsx` has one `borderColor` key with a conditional value (`'var(--sr-accent) var(--sr-accent) transparent'` when open, `'var(--sr-border-input)'` when closed) in place of `border` plus `borderBottomColor: open ? 'transparent' : undefined`. The set state stays `--sr-accent-border` + accent text + weight 600, and `data-set` and the CSS are untouched.
- **Guards, both new, both seen red first.**
  - `components/Checklists.test.tsx`: a new row sets and then clears County and Protocol on the real `Checklists` component. It asserts that the serialized `style` after the clear equals the same select's own first paint (structural equality with no hand-typed expectation), that the set state actually draws something different (non-vacuity), and that React logs no "conflicting property" warning.
  - `lib/inlineStyleShorthand.test.ts`: a repo-wide TypeScript AST scan over every `style={...}` in shipped `.tsx` files. It fails when a shorthand shares an inline style object with an overlapping key that can be removed (a conditional key, or a value that can be undefined, null, a boolean or empty). The overlap table is React's own `shorthandToLonghand`, parsed out of the installed react-dom dev build and never retyped, and it fails closed if React reshapes it. Guard-the-guard rows cover six shapes that must be flagged (both shipped ones included), six that must pass (both fixed forms, a static `border` + `borderTop` pair, and the defect written only in comments), and opaque expressions. Non-vacuity floors cover each resolution path, and a positive leg asserts that the three original sites stay within the scanner's reach.
- **Red on HEAD, measured by restoring each file from `git show HEAD:` and restoring from a hash-verified snapshot afterwards.**
  - HEAD `Checklists.tsx`: render row red on `County: cleared draws exactly as first painted`, and the scan is red.
  - Protocol-only mutation (a `border` re-added to that select alone): red on `Protocol: cleared ...`. County-only mutation: red on `County: cleared ...`. Each select's assertion is independently live.
  - Collision assertion alone, with the equality lines removed and run against HEAD source: red with `['Removing borderColor border', 'Removing borderColor border']`.
  - HEAD `SpeciesCombobox.tsx`: the scan is red.
  - Both components at HEAD: the scan reports exactly `Checklists.tsx:679 border + borderColor`, `Checklists.tsx:703 border + borderColor` and `SpeciesCombobox.tsx:189 border + borderBottomColor`. These are the Evaluator's three sites from an independent sweep.
  - Six analyser mutations all go red. `canBeEmpty` always false: 4 rows red. One-branch keys treated as always present: 4. Identifiers never followed: 3. Overlap always false: 7. Spread keys dropped: 3. File walk empty: 2.
- **Real engines (scratch probe, not shipped).** The built app was served with the synthetic demo CSV behind a stub backend and measured in Chromium and WebKit at 1280 and 390, in light and dark: 8 configurations. Fixed build: 80/80 checks pass. First paint, the set state, clear-back-to-first-paint for County and Protocol, the closed picker's bottom edge equal to its sides, and the open state (accent, transparent bottom) all match. Pre-fix build: 24 fail, which is 3 per configuration (County cleared, Protocol cleared, species picker closed bottom). Every first-paint, set and open reading is identical between the two builds.
- **One trap for anyone re-probing the picker.** While the input has focus, the global `input:focus-visible { border-color: var(--sr-accent) !important }` paints all four sides accent, in both builds. The open state's transparent bottom only shows when the list is opened without focusing the input (the chevron).
- **Bundle.** `dist/assets/index-*.css` is byte-identical to HEAD (sha256 `ccfb0ae4...`). Measured over two HEAD builds (determinism control) and two builds with the fix, so no comment word in the new files emitted a Tailwind rule.
- **Gates run.** Full frontend suite green (359 files, 7,449 tests). Also `npm run typecheck`, `npm run lint`, `npm run build`, and the four-file parity guard (`icloudKeysPublishedClaims.test.ts`).
- **Known limits.**
  - The scan cannot see a style built by a function call, a member access or an import. 30 of 1,989 style attributes are opaque when this was written. Nor can it judge whether an identifier value can be undefined. The file header says so.
  - It deliberately does not assert the neighbouring hazards: a shorthand that CHANGES over an unchanged overlapping longhand (React's "Updating ..." warning), and static key-order erasure. The tree has 41 steady overlapping pairs; the ones spot-checked are benign (e.g. `marginBottom: 12, margin: '0 0 12px'`). The Calendar hatch `backgroundColor`/`background` ordering is out of scope and is for the Chronicler to record on ROADMAP.
  - jsdom's serialization is not a browser's: it drops the whole `var()` border rather than only its colour. The render row's equality is an invariant in any engine, but the real-engine colours come from the probe above, not from the suite.
