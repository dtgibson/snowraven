## Edge Cases Tested
- Real-export comment shapes: eBird-collapsed single-line comments with prose
  before AND after the block; bare-name attribution ("Weather generated by
  RainCrow"); linked RainCrow attribution; moon-phase-emoji night blocks;
  attribution-less block (ends at last labeled value); emoji-less block whose
  bare condition segment is absorbed only when it isn't a finished sentence.
- Entity-encoded blocks (decode-first), prose emoji before a block (not
  mistaken for the header), prose lines starting with "Wind:" without a block
  (never stripped).
- Unknown completeness (`allObsReported` null) matches only an off filter.
- X-only counts (individualCount 0) hide the "birds" figure, not the row.

## Known Limitations
- A comment with a block AND separate user prose containing the literal
  phrase "weather generated by" would over-strip from that phrase; not
  observed in 308 real block-bearing comments — accepted.
- "Search matches what you see" means toggling re-runs searches; with blocks
  shown, block text is intentionally searchable.
- Filter state is session-local by design (house style; PRD out-of-scope).

## Convention Flags
- When a feature processes pasted/round-tripped text, verify against the REAL
  export early: eBird collapses newlines to spaces, which invalidated the
  natural line-based design. The real-formatter-fixture + real-data-sweep
  combination caught all three strip bugs and is worth repeating.
