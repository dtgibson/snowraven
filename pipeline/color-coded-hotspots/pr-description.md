# Color-Coded Hotspots

## What this does

Adds three opt-in color modes to the Map Explorer's Hotspots view, behind a new "Color pins by" control: **My species** (distinct countable species the user has personally reported at each hotspot), **My checklists** (distinct checklists there), and **Recent activity** (species reported by the whole eBird community at each hotspot in the last week or 30 days). The shipped visited / unvisited / personal coloring stays the default and is byte-identical when no mode is selected (a regression guard pins the layer's layout, filter, and feature properties). Values land on a new contrast-guarded five-class cyan-blue ramp with quantile breaks over the current result set; the legend auto-reveals with true class ranges and the off-ramp states in words; the popup and the keyboard "Hotspots in view" list carry every pin's number or state, so nothing depends on perceiving color.

Modes 1 and 2 are fully offline joins over the loaded backup (zero network, verified at the transport seam). Mode 3 adds one new dual-transport endpoint, `GET /map/hotspot-activity` (FastAPI + Tauri twin in lockstep, shared parity fixture), which reduces eBird's `data/obs/{locId}/recent?back=30` to one `(speciesCode, obsDt)` pair per species — one call answers both windows, so a Week / 30 days flip never refetches. Fetching is result-set-scoped (never viewport-driven), pool of 4, capped at 200 per search (in-view first, then nearest the search center, cache hits exempt), deduped in flight, and cached in a new durable storage-seam document (`hotspot-activity-v1`, 6h TTL, FIFO at 2,000 fixed-shape entries, per-entry validation on load, errors never cached, offline stale-reads with as-of wording). Failures classify into the app's three honest states with a retry that re-asks only the unanswered remainder.

## How to test

1. `cd backend && uvicorn main:app --reload --port 1620`, `cd frontend && npm run dev`, open http://localhost:5173 with an eBird backup loaded and an eBird key set.
2. Map Explorer → Hotspots → run a search. Confirm pins, legend, and popups look exactly as shipped (default mode).
3. Select **My species**: pins recolor instantly with no network (watch devtools); the legend flips to the mode legend; a hotspot you have birded shows its countable count in the popup and the in-view list; an unvisited hotspot shows the pale "Not birded by you" state.
4. Select **My checklists**: same, with checklist counts.
5. Select **Recent activity**: pins color progressively as answers arrive; the status line counts N of M with a progress bar; the Week / 30 days flip recolors with zero new requests; re-running the same search recolors from cache.
6. Kill the network (or remove the key) mid-pass: arrived pins keep their colors, the rest go dashed gray, the classified warn box appears with its supporting line, and Retry re-asks only what is missing.
7. Legend chips hide/show kinds while a mode is active; personal locations keep their orange star everywhere.
8. Full gates: `cd frontend && npm run typecheck && npm run build && npx eslint . --max-warnings 0 && npx vitest run`; `cd backend && python -m pytest tests/ -v`.
