SnowRaven · command-palette · design pass

Name the thing.
Go there.

One overlay, opened with Cmd‑K or Ctrl‑K and by a visible control at every navigation density, that searches two things a birder can already name: the eleven destinations and every species in their own eBird backup. It is a combobox, not a menu: the only tab stop inside it is the query field, and every result is an option driven by aria-activedescendant. That is what makes the focus trap correct by construction in WebKit's default tab mode, which is what the shipped Mac, iPhone and iPad apps run.

Every state, not just the happy one

The species half has four observable states and the result set has one more. None of them blocks, hides or delays the destinations: those come from an array the app has already built, so they render in the first commit and structurally cannot wait on a parse. Each specimen below is the real panel with the real copy.

Three entry points, one control

The control is a field, not a destination row. It reads as "typing happens here" rather than "a screen lives here", and it is the same object the palette's own query field turns into when it opens. It takes three sizes the way .sr-nav-item already does, and it never joins the role="tablist" group, which holds role="tab" children only.

The keyboard model

Arrows clamp, they do not wrap

ArrowDown at the last row and ArrowUp at the first leave the active option where it is. The shipped species picker clamps; wrapping here would make one key answer differently on two surfaces of the same app. Arrows cross the group boundary for free, because destinations and species are one flat array with one active index.

One tab stop, plus one button

The query field and the Close control, each carrying a literal tabIndex={0}. Result rows are role="option" divs with no tabindex at all, so they are in neither WebKit's tab order nor the focus trap's list, and the trap's prediction matches the engine exactly.

Enter takes the first row

With an active option, Enter opens it. With results and no active option, Enter opens row one. With no results Enter does nothing and the palette stays open. This differs from the species picker by one deliberate step: that control has a synthetic "All species" clearing row at index 0 and must skip it, and the palette has no such row.

Escape does exactly one thing

While the palette is open, one Escape closes the palette and nothing else: a fullscreen map stays expanded, a Map Explorer sidebar stays open, a share popup stays up. Closing restores the shipped Escape layering untouched. Focus returns to the control that opened it, or to a stated fallback where that control has unmounted.

The key hint is presentation only

Both chords are accepted on every platform whatever the hint says. Where the hint resolves to nothing (iOS, or any coarse primary pointer) the control renders its name and no key hint at all, and the footer legend goes with it. Nobody is shown a key they have no way to press. The button still carries aria-keyshortcuts="Meta+K Control+K", which is true everywhere.

One place a phone has no visible entry point

At phone density the app omits the whole navigation while a Map Explorer map is expanded to fullscreen. The chord still works if a keyboard is attached; a touch user leaves fullscreen first. This is stated and accepted, not solved: inventing a twelfth control for one transient state would cost more than it buys.

Motion

Nothing here is new. The entrance is the shipped species-picker listbox entrance, reused so the two surfaces cannot drift; the scrim fade is the shipped overlay fade. The one thing worth stating out loud is what is deliberately not animated.

What this costs the design system

No new token

Every colour resolves from a var(--sr-*) already defined in both themes: --sr-scrim for the backdrop, surface, border and shadow tokens for the panel, --sr-border-input for the field boundary, --sr-accent-bg-hover plus --sr-accent for the active option. No hex, no rgb().

One new pattern, one new control

A top-anchored modal search overlay is a shape the system does not have: the dialog shell is centred and is for confirmations, and the More sheet is a bottom navigation sheet. Both were borrowed from for behaviour, neither for its box.

The listbox vocabulary is reused, not forked

Active-option fill and inset outline, the row's flex proportions, the 40% cap on the scientific name and truncation on both spans all come from the shipped species picker. The one thing not carried over is BirdName: it composes a button and two anchors, which would nest controls inside role="option".

Rendered from the shipped tokens in frontend/src/globals.css, the shipped labels in lib/tabLayout.ts and the shipped glyphs in lib/tabIcons.tsx. The species list is a Bay Area birder's, including two Yellow-rumped Warbler forms, because the palette offers every distinct name the parse yields rather than only what Species Detail shows at its defaults. The stage is interactive: type in the field, use the arrow keys, press Enter, press Escape, or press Cmd‑K / Ctrl‑K anywhere on this page.
