SnowRaven · design direction

County Lines & Shading · first direction

Your county footprint, on the same map you already explore.

A Map Explorer overlay that draws US county boundaries over the current view and, optionally, shades each county by how many species you've recorded there — a "county life list" choropleth built entirely from your own loaded eBird data. It's the structural twin of the shipped Breeding Atlas overlay, so it reuses the same toggle group, popup, "in view" panel, and theme handling you already know. Flip the theme above — every surface below tracks both.

In context

The Map Explorer, overlay on

County lines on, shading on, species metric selected. The map chrome stays light in both themes (it's anchored to the always-light Positron basemap, exactly like the existing pins); the sidebar, popup, and panels follow your theme.

The one real choice

Which color ramp shades the counties?

A magnitude choropleth ("how many species here?") wants a single-hue sequential ramp. The plan as written says reuse the existing --sr-tier ramp — but that ramp is purple, because it's the Breeding Atlas ramp. My recommendation is a dedicated green ramp instead. Here's the tradeoff, side by side.

Option A — reuse the atlas ramp

Zero new tokens — literally what the PRD/schema specify. But purple is already the breeding ramp. A purple county choropleth reads as "breeding," and when both overlays are on the two purple polygon layers collide:

Atlas blocks (purple grid) + county shading (purple fill) — hard to tell apart.
Option B — a dedicated green ramp
--sr-county-1 … --sr-county-4 · green (new)
1–57 species
58–119
120–223
224+

One new AA-checked token family (logged in decisions.md). Green is SnowRaven's signature — "deep county lists" reads as a positive, active thing — it's the cartographically standard single-hue sequential ramp, and it stays instantly distinct from the purple atlas, so both overlays can be on at once and still read cleanly:

Atlas blocks (purple grid) + county shading (green fill) — clearly two things.
My recommendation: Option B (green). It's better cartography, more on-brand, and it future-proofs the day you want county shading and the atlas visible together. The cost is one new token family — a deliberate, logged extension, not silent drift. If you'd rather hold strictly to the written plan (zero new tokens), Option A is a one-line swap to --sr-tier. The whole mockup above is rendered in the green ramp so you can live with it.

Designed within SnowRaven's existing design system. Every value here comes from frontend/src/globals.css (:root + [data-theme="dark"]) and every component mirrors a shipped pattern — the 44×24 toggle switch, the SegControl metric pill, the maplibre popup chrome, and the atlas "blocks in view" panel. pipeline/design-system.md exists; this feature extends it, it doesn't reinvent it.

The single proposed addition is the --sr-county-1…4 green ramp (Option B) — a deliberate, AA-checked extension that would be logged in this feature's decisions.md. No new libraries, no new patterns.

What I'd love your read on:  1) Green ramp (recommended) vs. reusing the purple atlas ramp.  2) Should the popup also list a few top species for the county, or stay lean (just the two counts + region link)?
