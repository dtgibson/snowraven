Contract, live example, reference tables, and behavioral rules for Stage 5 implementation. All example values drawn from the production fixture in backend/tests/test_weather_router.py.

1 — Function Contract

// Input type
interface HourlyResponse {
  data: [{
    temp:        number   // °F
    humidity:    number   // %
    dew_point:   number   // °F
    wind_speed:  number   // mph
    wind_deg:    number   // meteorological degrees 0–360
    clouds:      number   // %
    weather: [{ id: number; description: string }]
    sunrise:     number   // Unix timestamp
    sunset:      number   // Unix timestamp
  }]
}

// Exported helpers
export function bankersRound(n: number): number
export function windDescription(mph: number): string
export function cardinal(degrees: number): string
export function conditionEmoji(owmId: number): string
export function formatRange(values: number[], unit: string): string
export function formatLocalTime(unixTs: number, tzName: string): string

// Main export — pure function, no side effects
export function formatWeather(
  responses: HourlyResponse[],
  tzName:    string           // IANA timezone, e.g. "America/New_York"
): string

4 — Behavioral Rules

Rule 1

Banker's Rounding

Python's built-in round() uses round-half-to-even. JavaScript's Math.round() uses round-half-away-from-zero. These differ at exactly the .5 boundary.

// Python
round(0.5)  → 0  (rounds to even)
round(1.5)  → 2  (rounds to even)
round(2.5)  → 2  (rounds to even)

// JavaScript Math.round — WRONG for this formatter
Math.round(0.5)  → 1
Math.round(2.5)  → 3

// Required TypeScript implementation
export function bankersRound(n: number): number {
  const floor = Math.floor(n)
  const diff  = n - floor
  if (diff === 0.5) return floor % 2 === 0 ? floor : floor + 1
  return Math.round(n)
}
⚠ cardinal(22.5) must return "N" (index 0, even) not "NE" — this is QA-03 and a required test case.
Rule 2

Wind Description Sort Order

Wind descriptions are collected across all hourly responses, deduplicated while preserving first-occurrence order, then sorted by Beaufort scale position (ascending, Calm first), then joined with " - ".

// Two responses: 9 mph (Gentle), 20 mph (Moderate)
collect: ["Gentle breeze", "Moderate breeze"]
dedup:   ["Gentle breeze", "Moderate breeze"]
sort:    ["Gentle breeze", "Moderate breeze"]  // already ascending
output:  "Gentle breeze - Moderate breeze"

// Two responses: 20 mph first, then 9 mph
collect: ["Moderate breeze", "Gentle breeze"]
dedup:   ["Moderate breeze", "Gentle breeze"]
sort:    ["Gentle breeze", "Moderate breeze"]  // sorted, not insertion order
output:  "Gentle breeze - Moderate breeze"
Rule 3

Wind Direction Insertion Order

Wind directions are collected across all hourly responses, deduplicated while preserving first-occurrence order, then joined with " - ". Not sorted — this is the intentional difference from wind descriptions.

// Two responses: 270° (W) then 180° (S)
collect: ["W", "S"]
dedup:   ["W", "S"]        // insertion order preserved
output:  "W - S"

// Two responses: 180° (S) then 270° (W)
collect: ["S", "W"]
output:  "S - W"           // order flipped — correct

// Two responses both 270° (W)
collect: ["W", "W"]
dedup:   ["W"]             // deduplicates to single value
output:  "W"
Rule 4

Capitalize Semantics

The condition description is taken from responses[0].data[0].weather[0].description and transformed with Python's str.capitalize() semantics: lowercase all characters, then uppercase the first character only.

// Python str.capitalize() behavior
"overcast clouds"   → "Overcast clouds"
"OVERCAST CLOUDS"   → "Overcast clouds"
"light Rain"        → "Light rain"

// TypeScript implementation
function capitalize(s: string): string {
  if (!s) return s
  const lower = s.toLowerCase()
  return lower[0].toUpperCase() + lower.slice(1)
}
⚠ Do not use .charAt(0).toUpperCase() + s.slice(1) — that preserves mixed-case in the rest of the string, which differs from Python.
