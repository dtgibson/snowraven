# Decisions: Family Rollups and Tree

Stages 1 to 3 (The Strategist, The Planner, The Architect) ran hands-off under Studio Style auto-advance: no question was put to the user, each builder proceeded on its defaults, and the user joins at Stage 4 (The Designer). Every entry below from those stages is therefore a builder's call, not a user's direction, and each carries what would reverse it.

Entries D-01 to D-12 are The Architect's (2026-11-21). Evidence, shapes and section numbers are in `schema.md`.

- **D-01. The path is Incremental.** One new bundled build-time asset with a generator leg and a CI equivalence check, and two new validated settings keys (`familyTreeRegion`, and in Slice B `familyTreeView`). Nothing derived is stored; `clearDerived.ts`, `cacheInventory.test.ts`, the CSP, `http:allow-fetch`, the backend and `PRIVACY_POLICY.md` are untouched. Reversal: none expected.

- **D-02. eBird marks extinct species, so FR-04's extinct clause stands (PRD Open Question 3).** One request to the generator's own URL on 2026-11-21 answered without a key: `extinct: true` with a numeric `extinctYear` on 193 rows, 173 of them species, both keys absent otherwise. The family and order fields are `order`, `familyCode`, `familyComName`, `familySciName`, present on all 11,201 species rows: 250 families, 45 orders, 2,379 genera, each contiguous. Cornell's 2026 taxonomy file on this Mac agrees on family, order, extinct and scientific name for every species. Reversal: a later response that drops the marker stops the generator (check G3 and F6), and the question returns to the Planner.

- **D-03. The family asset is written only by the existing generator, under its unchanged revision check, in both write modes; today that check stops the run, and it is raised, not worked around (Open Question 15).** Measured: the live taxonomy differs from the committed snapshot by one `reportAs` entry (`grnwhe1`, Great Nicobar White-eye (undescribed form), no longer reports as `indwhe1`); the four other maps are equal. Recommended route: refresh the snapshot first by the runbook's steps 3 to 9, as the user's own decision, then generate. Offered alternative, needing the user's explicit yes because it is what the PRD's default rules out: a one-time bootstrap of this one asset from the saved response through the same pure core and checks, on the measured ground that no field the asset reads differs across the drift. Slice A's first step waits on that choice. Reversal: not applicable; this is the fail-closed posture kept as it is.

- **D-04. The asset is keyed by lowercase common name and is self-sufficient.** Measured on a prototype built from the response: 433,991 bytes raw, 129,962 gzipped, against 300,622 and 107,894 keyed by species code. The code form would need the 1,786,735 byte snapshot (473,455 gzipped) loaded beside it, which the web/Pi frontend does not otherwise download. FR-06's "species-category code set" is held as the equal statement over the snapshot's `byCom` key set. Reversal: the app comes to load the snapshot on every platform anyway.

- **D-05. The world family and order totals count only taxa whose world species count is above zero.** FR-04's last clause counts every family in the asset. One family, Hawaiian Honeyeaters (`mohoid1`), is wholly extinct, so it would sit in the denominator of "families seen" where no birder can reach it. The rule adopted is FR-04's own species rule one level up: an extinct taxon counts on both sides exactly when the birder has it. This contradicts the PRD as written and is returned to the Planner as a scoped amendment of FR-04 and QA-36. Reversal: the user prefers all 250; the change is one predicate in `worldCounts`.

- **D-06. Reversal: a measured Year change over 100 ms on a real backup, which would argue for a per-year index.

- **D-07. Reversal, in order: a single pass over 200 ms in WebKit at the cap in the built app, or a live report of a frozen open; then a shared memo of the two Life Lists passes per observation array; then a one-shot worker returning packed columns.
