SnowRaven · Improve lane · Stage 2

Freezable label rows

Three open calls, answered against a real 320 px render rather than a description. Every screen below is an actual browser screenshot of the shipped globals.css at phone width, scrolled to the state a birder is genuinely in.

1 · Half A

Decline. Defaulting the pin on phones does not add a freeze, it swaps the frozen bird name for a frozen code header. Replace it with a reshape that freezes both.

2 · Multimedia

Repair, keep it always-on. Move the sticky from <tr> to <th>. No pill. The cost: no control-row symmetry with Breeding Codes.

3 · The cluster

It already fits, measured at 0 px overflow. Add the missing touch target and shorten the pin label to buy back slack.

01

The trade Half A is really making

The Breeding Codes matrix has two label axes, and a phone can only hold one of them still. Today it holds the species name. Half A would hold the code header instead. Scroll right and down on each of these and the difference stops being an argument.

Why decline the default even with the reshape in hand. The reshape fixes the trade; it does not fix landing there. Unbounded makes the whole page 306 px wider at 100% text and 419 px at 200% (629 px with all 23 codes present) — the tab strip and the filter pills drift off-screen with the table, and nothing on the opening screen signals that. And because mountedTabs only ever grows, useIsPhone() would seed the default exactly once: a desktop window narrowed below 640 px when the tab first opens stays pinned and Unbounded for the rest of the session after it is widened. A default that can be wrong and cannot self-correct is worse than no default. v0.5.81 already settled this as ratified policy: the pin is “never something a user can land in.”
An argument for pressing it, found while measuring. Pinned Unbounded shows more of the matrix than today's Normal default, because Normal's scrollport is the 286 px card while Unbounded's is the full 320 px viewport: 192 px vs 158 px of code columns at 100% text, and 80 px vs 46 px at 200%. At 200% today's Normal view is back to a one-and-a-half-column peephole. So the reshape makes the pill genuinely worth finding — which is the right way to win a user over to a mode, rather than starting them in it.
02

Multimedia: a pin that has never worked here

The sticky sits on the <tr>, which WKWebView does not honor — so the header pin is alive in Chromium and dead in the macOS and iOS apps. Moving it to the <th> fixes it for everyone and takes nothing from anyone, which is why it needs no toggle.

The losing side, named. Multimedia gets no “Pin labels” pill, so the two control rows are not symmetric. That is deliberate: Breeding Codes' pill exists because pinning changes your view (pinned implies Unbounded). Multimedia's sticky is already scoped to a view the user chose, where a band costs 36.5 px (6.4% of a 568 px viewport) and removes nothing. A toggle whose only job is to switch off something with no downside is a control that should not exist. Adding it was measured and would have fitted — 276.38 px in a 288 px box — so it is declined on interaction grounds, not space.
And no frozen name column here. Multimedia's name column measures 238 px at 100% text and 423 px at 200% on a 320 px screen — 74% and 132% of the viewport, because minWidth: 200 is a floor with no viewport clamp. A frozen column wider than the screen leaves nothing for the data. Breeding Codes' name column is clamped to clamp(7.5rem, 40vw, 220px) (128 px / 240 px), which is exactly why the reshape works there and cannot be ported here.

The control cluster fits

The v0.5.82 maxWidth: 100% repair is holding. Measured at 320 px, every configuration — including the three-control one — sits inside its row's content box with no page leak, at both text scales.

Two changes follow. Add .sr-touch-target to Multimedia's ↔ Unbounded button — it goes from 98 × 15 px to 98 × 44 px with the cluster's width unchanged, closing the parity gap with Breeding Codes. And rename the pin pill to “Pin labels”: it becomes accurate once the species column freezes too, it matches the saved idea's own words, and it returns 29.5 px (100%) / 53.6 px (200%) to the tightest cluster in the app.

Motion: the frozen band and frozen column get none, deliberately — sticky is continuous positioning, not a state change, and a shadow that fades in on stick would need a scroll listener this repo does not want. The only motion on either surface stays the existing pin-note entrance: opacity and a 2 px rise, 160 ms ease-out, rising out of the control row that triggered it, with an animation: none fallback under prefers-reduced-motion.
Still to settle on device, and the reason the ship gate needs a real phone: a <th> that is sticky on both axes at once under WKWebView with table-layout: fixed. Cell-level sticky is the recorded WKWebView-safe form and each single axis ships today, but the combination is new here. Second: keyboard focus moving rightward across a row can now land under the frozen name column, which wants scroll-margin-left on the focusables — verified by reading the computed value off the focusable, never the cell.
Method. Chromium via Playwright (already a dependency in website/tools/) at 320 × 568, at 100% and 200% in-app text scale, with the declarations parsed from the real frontend/src/globals.css — the sole substitution is the @import "tailwindcss" line, replaced by the two preflight declarations this layout depends on. Component inline styles are transcribed from the components' own JSX style objects at their shipped (1,0,0) specificity. Elements are measured against their container, never page scrollWidth alone; layering is settled with elementFromPoint inside the frozen bands. Content is hand-written realistic species and real eBird breeding codes — no real eBird export was read.
