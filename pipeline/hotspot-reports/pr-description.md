## Hotspot Reports

### What this does

Adds a **Hotspot Reports** tab (id `hotspot-reports`, between Breeding Codes and Checklists): a report for any one location in the user's own eBird backup, a public hotspot or a personal location, chosen from a searchable picker. Before a choice it shows how many locations the backup holds (split into hotspots and personal locations where eBird has answered) and two top-ten lists that open a report; after one it shows the place's life list (dated to the first record there, with how many of the place's checklists include each species), a plain map, checklists by eBird protocol and the complete share, the weather on the user's visits from the weather blocks in their own checklist comments, and first and latest visit, visits by month and year, time birded, the biggest checklist and media counts. Everything is derived in memory from the two files already loaded; nothing is stored, and no request, host or endpoint is added.

### How to test

1. `cd frontend && npx vitest run` (the full suite), `npm run typecheck`, `npm run build`, `npx eslint .`.
2. The feature's own suites: `npx vitest run src/lib/hotspotReports src/components/hotspotReports src/components/WeatherDistRow` (index, picker, kind, provenance, location, copy, linearity, stylesheet, network scan, published claims, demo-data row excepted; the component suites for the tab and the picker; the distribution row and its golden).
3. In the app (the guide below): open Hotspot Reports with the demo backup; check the overview's count block and both lists; type "jamaica" in the picker, press Enter; check the header (Hotspot eyebrow, the name linking to eBird, 143 species, 42 checklists, the rule sentence), the life list (newest first, "First here", "Of 42 checklists"), the plain map with one pin, the protocols, the weather (14 of 42 checklists carry a block, sky, temperature and wind with "Most common"), and visits and media. Narrow the window (or set Text size to 200% in Settings) until the report is one column and use the jump row. Choose Overview to return.
4. The More sheet on a phone-width window: every destination, Hotspot Reports fifth, with nothing to scroll.

### Seeing Hotspot Reports (the web preview, over the tailnet)

1. Open a terminal in the project folder.
2. Build the app: `cd frontend && npm run build`.
3. Make a scratch copy of the synthetic demo data (never the real backup): `mkdir -p /tmp/sr-demo && cp website/tools/demo-data/* /tmp/sr-demo/` (with the held tools patch applied the generator adds the weather blocks; `node website/tools/gen-demo-data.mjs` regenerates the folder).
4. Start a second backend on a spare port, never 1620: `cd backend && SR_DATA_DIR=/tmp/sr-demo .venv/bin/uvicorn main:app --host 127.0.0.1 --port 1631`.
5. Publish it on the tailnet on a fresh HTTPS port (leave 443 alone): `tailscale serve --https=<fresh port> http://127.0.0.1:1631`, using the Tailscale app bundle's CLI, and open the URL it prints.
6. Choose **Hotspot Reports** in the navigation (on a phone, under More). The overview shows the location count and two lists; pick a place from either list or from the picker. What working looks like: the report opens with the place's name as its heading, the life list on the left and the map, protocols, weather and visits on the right (one column with a jump row on a narrow window or at large text), and choosing Overview brings the lists back.
7. Stop the backend and the serve when done (`tailscale serve --https=<port> off`).

### Convention Flags
- A container threshold that decides whether a SECOND container shows its wide form is derived from that second threshold plus the fixed tracks between them (here 24rem rail + 16px gap + 2px border + the list's 28em), and measured with a classic scrollbar, or the two queries leave a band where one layout shows the other's narrow form (D-07).
- A view that hosts a long-lived map replays its entrance through the Web Animations API, gated on `prefersReducedMotion()`, rather than by re-keying (D-09).
- A per-location index built as typed columns and compressed row lists, held only by the tab's ready phase, with every file-keyed table a `Map` (schema 2.1; `lib/hotspotReports.ts`).
- A geometric fit probe checks ink against each GRID CELL as well as the card: a card-only detector certified widths at which a name overlapped its neighbour cell (D-07).
