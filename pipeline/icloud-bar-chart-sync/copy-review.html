Decisions to confirm

Each carries the default the plan is written to. Say the number and "yes", or the number and your answer.

D1

Should the Targets tab's day-by-day live answers sync too?

Recommended
Yes, as one copy per device that the others merge on read (the Architect's shape, D8).
Consequence
A county swept on one device shows its days as already checked on your others, saving 30 eBird requests per county per device. The container holds one snapshot per device (about 10 MB each). It is built last, so a "no" here costs nothing already built; items 2, 3, 27, 30, 31, 33, 35, 38, 39 and 44 then take their "if D1 = no" variant, and the privacy sentence "cached lookups are never synced" stays exactly as it is.
D2

Should Remove all bar-chart files confirm even when sync is off?

Recommended
Yes, always, on every platform.
Consequence
A row's Clear is instant with sync off because the row shows exactly what goes; this control shows nothing per file, so it confirms even locally. Reversing it is one branch in the Settings handler (skip the dialog when sync is off) and items 19 and 21 are then unused.
D3

The privacy sentence "You can delete your stored files and keys at any time from the Settings tab": revise it now?

Recommended
Yes, revise it in this build (item 35), because the new Settings control makes it true of bar-chart files for the first time and the recorded reversal condition is met.
Consequence
Leaving it as is would be tolerable (it does not say "only"), but the sentence would then be true by accident rather than by design, and the record says to revisit it here.
D4

When an old file's saved time cannot be written into a sync record, what happens?

Recommended
The record carries the time of the check that adopts it, and the file is still uploaded, never skipped.
Consequence
A file added before this version always reaches your other devices. The alternative strands it on one device with a "Could not sync" state. Reachable in practice only through a hand-edited manifest; specified so the rule has no gap.
D5

Clearing the eBird backup with sync on also removes the shared day-by-day copies from iCloud?

Recommended
Yes. (Moot if D1 is no.)
Consequence
Keeps the published sentence "clearing your eBird backup also removes the day-by-day eBird reports" true across devices, not only on the device that cleared. Reversing it removes one call; each device would still remove its own copy at its next check.
D6

No compatibility behavior for a device still on an older app version?

Recommended
Yes, no shim.
Consequence
An older device keeps syncing the two data files and ignores the new items; its Remove synced files leaves the bar-chart copies in place (a current device's Remove clears them). Nothing breaks either way.
D7

ACCESSIBILITY.md: leave it unchanged?

Recommended
Yes, unchanged.
Consequence
The statement's confirmation sentence is scoped to the Sync API keys switch and stays true. The new control and the two new confirmations follow the same patterns it already describes. If you would rather it name them, item 46 has the sentence, written as a property rather than a list.
D8

The Architect's change: the day cache syncs as one snapshot per device, merged on read, not one shared merged copy.

Recommended
Accept.
Consequence
The PRD's single merged copy cannot settle once two devices' answers exceed one device's budget (about 10 busy counties): the two would exchange a 10 MB write on every check forever. Per-device snapshots reach a fixed point within two checks. Cost: one snapshot per device in the container, and a device that leaves your account leaves its snapshot behind until Remove synced files from iCloud. No user-facing wording depends on which shape is chosen.
D9

Take the roadmap's eviction fix (the measured 0.8 s main-thread stall on a crafted document) in this build?

Recommended
Yes, take it now.
Consequence
With D1, a crafted snapshot from your own iCloud account could reach the same code path once per device, so the fix (build the per-county recency map once per eviction pass) closes a stall that sync makes easier to reach. Declining it is recorded as a written non-action with the measured number and its reversal condition, not a silence.
