# PR: iCloud Sync (v1.0.11)

## iCloud Sync

### What this does

Adds an opt-in, off-by-default iCloud Sync section to Settings on the macOS
and iOS/iPadOS apps (nothing renders or runs on Windows, web or Pi). With it
on, the eBird backup and the Macaulay Library export, plus a small shared
record per file (filename, upload time, origin device), are kept the same
across the user's own Apple devices through an iCloud Drive ubiquity
container tied to the user's Apple ID. The most recently uploaded copy wins,
whole; each Default Files row shows where its file came from, when, and one of
eight plain-text sync states; a synced arrival or synced clear invalidates the
parsed-file caches exactly as a manual upload does and reaches every tab
without a relaunch. The native side is `src-tauri/src/icloud.rs` (macOS +
iOS only): coordinated reads and writes, temp-then-rename in the container,
SHA-256 verification before a pull is applied, the CSV bytes never crossing
IPC, and an NSMetadataQuery over the two record files for change detection.
Packaging pairs release-only iCloud entitlements with an embedded Developer
ID provisioning profile through a `release.sh` overlay build, with a preflight
and a post-build check that refuse to publish a bundle missing either.

### How to test

1. Unit level (no device needed): `cd frontend && npm run build && npx eslint . && npx vitest run`; `cd src-tauri && cargo check && cargo check --target aarch64-apple-ios`.
2. Gate and UI in a dev build: `npm run desktop:dev`, open Settings. Below Default Files an "iCloud Sync" section appears with the switch disabled and the note "This build cannot use iCloud." (a dev binary has no bundle and no profile, by design). Windows, web and Pi show nothing.
3. Real iCloud behavior needs the signed overlay build (see `how-to-see.md`), which needs the Apple portal steps first (macOS App ID `com.snowraven`, the container `iCloud.com.dtgibson.snowraven` on both App IDs, the Developer ID Application profile at `~/.tauri/snowraven-developerid.provisionprofile`). Then walk QA-02 (sign out of iCloud: the note names signing in), QA-03 (a plain `npm run desktop:build` without the overlay says "build cannot use iCloud" and neither crashes nor writes to iCloud), QA-13 to QA-19 across the Mac and one iOS device (TestFlight build of the same version), QA-25 (evict with Finder "Remove Download"), QA-28 to QA-31.
4. The release itself: `zsh -lc ./release.sh` must print "iCloud profile OK ..." in the preflight and "iCloud entitlements and embedded profile verified" after the build; `codesign -d --entitlements - --xml <app>` on the published bundle lists the three iCloud keys and the container.

### Notes for reviewer

- **Change detection actually shipped: NSMetadataQuery (primary) plus the foreground/focus triggers and a 5-minute visible poll (fallback).** The query is scoped to `NSMetadataQueryUbiquitousDocumentsScope` with the predicate `NSMetadataItemFSNameKey LIKE '*.record.json'`, started on the main thread when sync is enabled and stopped on disable, batching interval 1 s, emitting `icloud-changed`; an observer on `NSUbiquityIdentityDidChangeNotification` emits `icloud-identity-changed`. Verify-item V6 (updates arrive in a Tauri process) stays with the Tester; if they never arrive on a device, the poll and foreground triggers still satisfy FR-20 at OQ-8's latency.
- **Native commands need no capability grant.** App-defined `#[tauri::command]`s in this project are invoked without permission entries (precedent: `get_location`, `get_timezone`, `get_api_key`); the capability files are untouched and the fs scope stays `$APPLOCALDATA/**`. `listen` for the two events is covered by `core:default`.
- **Cargo target blocks.** `objc2`, `objc2-foundation`, `block2` and `sha2` moved to a new `cfg(any(macos, ios))` block; `objc2-core-location` and `tokio` stay macOS-only; `objc2-ui-kit` (UIDevice) sits in its own `cfg(target_os = "ios")` block rather than the android|ios mobile block (it is an Apple-vendor crate). `objc2-foundation`'s default feature set already enables every framework module used; the features are listed explicitly for visibility. `Cargo.lock` gains three lines (the new direct deps were already in the graph).
- **macOS availability probe** uses `SecTaskCopyValueForEntitlement` (Security.framework, linked directly) AND the `Contents/embedded.provisionprofile` file check, per schema V5; either missing yields `build-cannot-use-icloud`. iOS skips the SecTask probe (schema).
- **Device label** on macOS comes from the deprecated-but-correct `NSHost.localizedName` (the user's Mac name); iOS from `UIDevice.name` on the main thread (generic "iPhone"/"iPad" on iOS 16+, which FR-13 allows). Truncated to 64 UTF-16 code units natively, and validated again in TypeScript.
- **Not-downloaded handling.** On a `download` decision the check starts the download natively and waits up to 5 s (polling the file status) before leaving the row at "In iCloud, not downloaded here" with Download now; Download now waits up to 90 s. The query watches only the record files, so a csv landing later is picked up by Download now, the poll, or the next foreground check.
- **Two small persisted additions inside the `icloud-sync` settings key**, both within the schema's "one object, one link" shape: `knownShared` (the last-known shared files, so a relaunch with sync off still renders "Sync off" and offers Remove without reading iCloud, which FR-07 forbids while off) and `pendingClears` (a synced clear whose marker could not be pushed is finished on the next check instead of pulling the cleared file back down; a newer shared file supersedes it, latest event wins).
- **`sharedExists` counts FILE records only**; a stale cleared marker alone does not offer Remove (there is nothing the user would recognise as a file to remove). Remove still deletes all four container files.
- **Origin on a re-push**: a file this device pulled from a peer keeps that peer as its origin when pushed again (after a Remove, say), so the row's "From <device>" stays true.
- **FR-34 network cache**: not cleared, matching today's Settings clear (schema decision 9).
- **Settings-side changes to existing rows**: the filename line now wraps (class `.sr-file-line`, the "Saved" span drops `nowrap`), and the existing Upload/Import and Clear buttons gain `.sr-touch-target` per the spec's phone posture. Byte-identical desktop rendering apart from that class (min-height only applies in the ≤640 tier).
- **`--sr-scrim`** is the one new token (both themes, recorded in `pipeline/design-system.md`); the shared dialog shell is `components/ui/ModalDialog.tsx` (focus trap re-queried per keydown, Escape, backdrop mousedown, origin-aware scale-in, focus return with a fallback for a trigger that has gone disabled). Calendar's inline scrim was left as is (the spec marked re-pointing it optional).
- **`mapFabCascade.test.ts`** gains `sr-dlg-actions` in its never-a-FAB-ancestor table (the dialog action row's `> *` rule is an ancestor-scoped competitor by that guard's construction; a dialog panel never wraps a map).
- **Privacy parity test** now pins 13 sections (the new `## iCloud Sync` after `## iOS App`) and asserts the four required statements on both sides.
- **Existing test mocks** of `../lib/platform` gained `isMacOS` (five files), since `showICloudSync` reaches it.
- **Release overlay path**: `release.sh` passes `--config "$(pwd)/src-tauri/tauri.icloud.conf.json"` (absolute, so the CLI's CWD-relative resolution cannot miss it) and copies the profile to the gitignored `src-tauri/embedded.provisionprofile` because the overlay's `files` source is resolved relative to `src-tauri/` like `entitlements`. Verify-item V1 (the profile is copied before signing, so `codesign --verify --deep --strict` passes) is checked by the script itself on the first overlay build.
- **Windows CI untouched**: `windows-build.yml` has no entitlement, profile or codesign reference; `icloud.rs` is behind the Apple cfg; the Windows target is not installed on this machine (`rustup target list --installed` shows no `windows` target), so the Windows path is stated, not checked: nothing reaches it except the version bump.
- **Known limitations**: a check's "nothing to transfer" outcome for the announcer treats a record rejected by the validator as absent (logged once); the enable-time "here" word reads "this device" until the controller has probed the platform; jsdom cannot verify the geometric and visual claims (320px/200%, AA contrast, the animations), which stay with the Tester's browser pass and the device pass.

### QA round 1 fixes (attempt 1 of 3)

- **Failure 1, `release.sh` profile preflight (QA-42):** `plutil -extract Entitlements.com.apple.application-identifier` read the dots in the key name as path separators and returned nothing, so the preflight died on the correct profile. The two dotted entitlement keys are now read with `/usr/libexec/PlistBuddy -c 'Print :Entitlements:...'` (the application identifier, and the ubiquity container list, which is now checked inside the profile's Entitlements rather than by a grep over the whole decoded plist); `ExpirationDate` is a top-level key and stays on `plutil ... raw`, whose ISO 8601 UTC form is now asserted by regex before the string comparison against `date -u`. Proved by running the exact block (release.sh lines 167 to 197, extracted with sed and sourced in a subshell with the script's helpers) against `~/.tauri/snowraven-developerid.provisionprofile`: it printed `==> iCloud profile OK: 8QKC3L2FKP.com.snowraven, container iCloud.com.dtgibson.snowraven, expires 2044-08-27T23:13:18Z` and exited 0. The post-build check uses only `codesign -d --entitlements` plus grep (no plist key paths), audited and unchanged.
- **Failure 2, the state label clipped at 320px / 200% (QA-39):** `.sr-sync-state { white-space: normal; align-items: flex-start }` plus a 0.2em top nudge on the glyph, inside the established ≤640 tier (desktop keeps nowrap); the glyph keeps its top-level `flex-shrink: 0`. `icloudSyncCss.test.ts` pins both declarations in the tier. Re-measured with a Playwright probe over the real rendered section (the Tester's faked-Tauri harness pattern, `scratchpad/label-wrap-probe.mjs`): all eight state labels, each with the three longest detail fragments (peer provenance with time, the FR-25 "Replaced by" line with a long device name, the mismatch reason), at 320px in Chromium 1234 and WebKit 2336 at 200% and 100%: 104 measurements, 0 failures; every label element and every text-ink rect sits inside the 279px row content box (worst case "In iCloud, not downloaded here" at 200%: label right 279.0, ink right 250.6, three lines), and no descendant of the row crosses the box. Non-vacuity: the longest label really wraps (3 lines) and the glyph stays 13px.
- **Flag 3, FR-05 "Waiting to upload" (implemented):** `NSURLUbiquitousItemIsUploadedKey` / `IsUploadingKey` are in objc2-foundation 0.3.2, so `csv_status` now reports `uploaded` (true only when BOTH the csv and its record report uploaded; a non-ubiquitous copy reads as uploaded so a missing key can never trap a row) and `uploading`, and `icloud_push` returns `uploaded` for the bytes it just wrote. The controller shows "Waiting to upload" after a push the daemon has not finished, and keeps it on an identical-both-sides check until the status reads uploaded; a native layer that omits the flag is read as uploaded. Three controller tests cover it.
- **Flag 4, NFR-04 10 s per check (implemented for the reads):** each check now has one 10 s budget (`CHECK_DEADLINE_MS`, injectable) covering the status probe, the two record reads and the in-check download wait; a read that would start past the deadline, or outlives it, is a timeout. If iCloud never answered the first read, rows keep their last state (FR-05); if it answered once and then ran out of budget, the undecided rows read "Could not sync" with "iCloud did not respond in time." and Retry, and the last check time is kept. Pushes and pulls are deliberately NOT raced: cutting a pull short could leave the csv and its metadata disagreeing, so transfers keep only the native per-command timeout (NFR-04 times the nothing-to-transfer case). Two controller tests cover the budget (a hanging second read bails in well under the 8 s command timeout; a hanging first read keeps state).
- Tidied the three em dashes the report noted in non-user-facing lines (the .gitignore comment, the globals.css scrim comment, the release.sh build echo).

### Security round fixes (Auditor pass with notes)

- **Finding 1 (Medium), size bound before the read:** `icloud_pull`'s coordinated read closure now takes `symlink_metadata(p)` first and refuses a non-regular file (`unavailable`), a length over 200 MB (`too-large`), or a length that differs from the record's claim (`mismatch`), before `fs::read`; the length is re-checked on the bytes actually read, then the digest. `icloud_push` bounds the local file the same way (`regular_file_len` before the load; `local-missing` for anything that is not a regular file). Covered natively by `regular_file_len_refuses_symlinks_and_directories` and, on the seam, by the existing mismatch test.
- **Finding 2 (Low), symlinks:** `item_present`, `ubiquity_flags`, `csv_status`'s length, the record read closure and the csv read closure all go through `symlink_metadata` and accept regular files only; `coordinated_delete` removes a symlink AS A LINK (never following it) and refuses a directory. A record file over 16 KB is not read at all (handed to the validator as an empty string, which it rejects). The module comment states that the container is untrusted at the file-type level too.
- **Finding 3 (Low), writer bounds:** `icloud_push` and `icloud_push_cleared` sanitize the filename and the device label at the command boundary (C0/C1/DEL stripped, `/` and `\` stripped from the filename, surrogate-safe truncation to 255 / 64 UTF-16 code units, a platform-word fallback for an empty label), and the identity probes use the same sanitizer. The TypeScript write chokepoint mirrors it (`sanitizeLabel` / `sanitizeFilename` in `icloudRecord.ts`, applied in the controller's `pushLocal`, `thisDevice` and the origin it records), so a record this device writes always validates on every reader, itself included. Tests: five Rust unit tests in a `#[cfg(test)]` module (`cargo test --lib icloud`), three validator-side tests in `icloudRecord.test.ts`, and a controller test that a filename and a probe label carrying control characters push a record the validator accepts and that the next check is idempotent (one push). The parity test pins the bounds and the device-id shape on both sides.
- **Finding 4 (Low), staging device id:** `valid_device_id` (32 lowercase hex, a byte scan) is checked in `icloud_push`, `icloud_push_cleared` and `atomic_container_write`; a miss returns the typed `unknown`. `storage.ts`'s `readMeta` now normalizes every entry: an `origin` whose `deviceId` fails `/^[0-9a-f]{32}$/`, whose label is not a string, or whose platform is unknown is dropped (the entry reads as "local, no origin"), and an entry lacking its two required strings reads as absent. Three storage tests cover it.
- **Finding 5 (Low), `.tmp/` residue:** `clear_staging` removes every entry of `Documents/.tmp/` (or only this device's `<deviceId>-*` entries); each push clears this device's stale entries before staging, and `icloud_remove_all` clears the whole directory and removes it, counting the entries in `removed`. Two Rust unit tests cover the scoping and the never-follow rule.
- **Finding 6 (Informational), wording:** the enable note's first item now reads "which device it came from (its name), its size and a checksum" (the Settings tests read the copy module, so they follow); `docs/HELP.md` says the same, and gains the one-sentence Apple ID note from Finding 8; the "What is stored" bullet in `PRIVACY_POLICY.md` and `website/privacy.html` now lists "its size and a checksum of its contents" (parity test green, 13 sections); the quoted note in `design-spec.md` updated to match.
- **Finding 7 (Informational), release preflight temp file:** the decoded profile goes to `mktemp -t snowraven-profile` and the single EXIT trap (now installed in the config section, covering both the temp plist and the `src-tauri/embedded.provisionprofile` copy) removes it. Proved by sourcing the trap and the preflight block verbatim in a subshell against the real profile: the OK line printed with `8QKC3L2FKP.com.snowraven`, the temp file existed inside the run and was gone afterwards (0 `snowraven-profile*` entries in `$TMPDIR`); the Tester's stale fixed-name `/tmp/snowraven-developerid-profile.plist` from the earlier run was removed by hand.
- Finding 8 (accepted) needed no code change; the HELP sentence about a second Apple ID on one device was added.

## Convention Flags

- A `position: fixed` modal shell lives in `components/ui/ModalDialog.tsx` and `.sr-dlg-*`; new confirmations reuse it (trigger getter for the origin, `fallbackFocus` for a trigger that goes disabled) rather than re-inlining the Calendar overlay.
- The data-file change signal is `lib/filesChanged.ts` + `useFilesEpoch()`; a tab that loads a stored file puts the epoch in its load effect's deps instead of loading on mount only.
- An entry-safe store plus a dynamic-imported controller (`lib/icloud/icloudState.ts` / `icloudSync.ts`) is the shape for a feature whose native half must stay off the entry chunk: components read the store and call an `actions` slot the controller installs.
- The `icloud-sync` settings key is the one place sync state lives; anything new about sync joins that object (one link per save), not a new document.
- `objc2-ui-kit` (or any Apple-vendor crate needed only on iOS) goes in a `cfg(target_os = "ios")` block, not the android|ios mobile block.
