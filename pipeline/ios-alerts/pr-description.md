## iOS Alerts (new lifer nearby)

### What this does
On iPhone and iPad, Settings gains an Alerts section, off by default, that tells the user when eBird reports a species they have never recorded near a place they choose. The check runs about hourly or about daily (iOS decides the exact time) and whenever the app is opened after the interval; quiet hours defer the one summary notification to the end of the window; an inbox keeps 30 days / 200 alerts on the device, and a notification or inbox tap opens Map Explorer's Nearby Lifers view at the alert's own point. The Mac, Windows and web/Pi versions get nothing: the section is gated out, not hidden.

### How it is built
- **Native, because a background launch never boots the webview.** The check, the schedule, the notifications and the three documents (`alerts/settings.json`, `state.json`, `inbox.json` in the App Group container) are Swift in the app target behind one actor (`Sources/snowraven/AlertsLogic/` pure and tested; `Sources/snowraven/Alerts/` the UIKit, BackgroundTasks, UserNotifications and CoreLocation seams). It reuses the widget's `Logic/` (hand-over reader, request, client, reducer, fold, distance, dates, Retry-After) unchanged but for two defaulted request parameters.
- **Rust** (`src-tauri/src/alerts.rs`): five async commands on the blocking pool, a `setup`-only plugin that hands Swift two C callbacks (the poke, and a notification tap that goes through the widget hook's own filter and parking path, now `widgets::park_link` / `park_raw_link`), and three `-Wl,-U` link allowances. No `on_event`; the single-webview keeper is byte-unchanged.
- **Webview** (`lib/alerts/`): an entry-safe store, a lazy controller and native wrapper that shape-check every reply, a lazy purge for the clear registry, the pure TypeScript twin of the rules (the parity fixture is generated from it), and the copy module. `components/settingsSections/AlertsSection.tsx` is a lazy section rendered only when `alertsSupported()`.
- **The hand-over** carries eBird's two countability exception lists, so Swift applies `isNonCountableForm`'s rule with the app's data (the three-clause shape rule is twinned; the lists are not copied).
- **The deep link** gains one anchored alert form carrying the check's point and radius (`LINK_MAX_LENGTH` 96 -> 128 on both sides); Map Explorer's link effect searches from that point with no location read, and the focus gains a `center` mode (every lifer shown, no pill) beside the shipped `only`.
- **The clear registry** gains a third row class, `native`, for the App Group inbox.
- **Plists**: `UIBackgroundModes: [fetch]` and the one BGTask identifier, identical in all three sources; no location background mode, no push entitlement.
