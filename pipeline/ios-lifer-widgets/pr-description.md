## iOS Lifer Widgets (ios-lifer-widgets)

### What this does

Adds two iPhone and iPad home-screen widgets, **Nearby Lifers** and **Media Targets**. Each lists the nearest recent eBird reports, within 25 miles of where you are, of birds you still need: species not in your eBird backup, or recorded species you still lack a photo, audio or video of. Each widget comes in small, medium and large, has a Time range setting (Day, Week, 30 days), and Media Targets also has a Media setting (Photo, Audio, Video, Any). Tapping a widget opens Map Explorer on the matching view with that window, the matching Filter by Type chip, a 25 mile session radius, and a search from the current location. The widget extension targets iOS 17; the app stays on iOS 16.

### How it is built

- **App side (TypeScript, entry-safe gate plus lazy controllers).** `lib/widgets/widgetHandover.ts` builds a small hand-over document (folded recorded names, three per-type target sets, the eBird key or null, the Default Location). `widgetHandoverController.ts` regenerates it whole, debounced, on boot and on every `filesChanged`, `keysChanged` and new `mapDefaultsChanged` epoch. A failed read does not rebuild the name sets (unknown, never empty). A removal is never left behind, though: if the whole rewrite cannot finish after the key is removed or replaced, or a file is removed, the controller writes a no-key document (the widget shows S2), falls back to `widgets_remove_handover`, and returns and retries whatever it could not do (security review M1). A backup name the per-name check refuses is skipped, not a reason to refuse the document. `lib/links/` holds a fifteen-string allowlist parser, the pending-link store, and the controller that takes URLs from native. App switches to Map Explorer per link id; MapExplorer applies view, window, chips and radius, then runs Use my location and that view's search.
- **Native (Rust, iOS only).** `src-tauri/src/widgets.rs`: `widgets_write_handover` bounds and strictly parses the body, then writes it atomically into the App Group `group.com.dtgibson.snowraven`, refusing symlinks and directories at the fixed name, and calls a one-function Swift shim (`WidgetReload.swift`) that reloads widget timelines. `widgets_take_pending_link` and a plugin `on_event` hook park the last `snowraven://` URL. The single-webview keeper in `lib.rs` is unchanged.
- **Vendored tao, second change.** `scene.rs` now forwards a LAUNCHING URL from `scene:willConnectToSession:options:` as `Event::Opened`, which upstream drops. This is what makes a widget tap work from a cold start. See `VENDORED.md`.
- **Widget extension (Swift).** `gen/apple/snowraven_widgets/`: `Logic/` is pure Foundation (hand-over and cache validators, the eBird reducer, the name, date, distance and `toFixed` twins, the row builder, the state machine, copy, presentation and VoiceOver labels, and a `RefreshEngine` actor over injected seams). `Widget/` holds App Intents, providers, the App Group store, a URLSession client (one host, no redirects, 2 MB body cap), CoreLocation with a 10 s bound, and SwiftUI views. `snowraven_widgetsTests/` runs its XCTests over the same parity fixture the TypeScript twin generates, plus a dense-body memory and cap suite (`DenseBodyTests`).
- **Project.** Two new targets in `project.yml`, regenerated with xcodegen. Both entitlement files carry the App Group. The URL scheme and the widened location usage string are identical across the three iOS plist sources.

### Stage 8: a bird tap shows only that bird (1.0.36 build 2)

The device pass on TestFlight 1.0.36 (1) found that a row tap opened the right view with every nearby bird on it. Now a bird tap (a row on medium and large, the one-bird card on small) carries `&sp=<speciesCode>&loc=<locId>` after the unchanged view link. Map Explorer runs the same search, then shows only that species with the listed sighting selected, its popup open, and the map centered on it. A pill in the FAB cluster, "Only {name} · Show all", brings everything back with no new request. A header tap is the view link, as before.

- **Grammar** (`lib/links/deepLink.ts`): fifteen exact view links plus one anchored, bounded suffix pattern (`BIRD_SUFFIX_RE`, built from the two id patterns). `LINK_MAX_LENGTH` is 96 (the longest link is 88). A malformed suffix DEGRADES to the view link; an inexact view part is still rejected whole. The species-code class is the app's own `SPECIES_CODE_RE` (`/^[a-z0-9-]{2,16}$/`), now defined once in `lib/speciesCode.ts` and imported by `SpeciesLinks` and the parser. The Swift builder spells the same text, and the parity guard compares them.
- **Swift** (`DeepLink.swift`, `WidgetPresentation`): `rowLinks` gives one bird link per shown row; `widgetLink` is the bird link on small and the view link on medium, large and every state. An id outside its pattern yields the view link, never an out-of-pattern link.
- **Map Explorer** (`lib/links/linkFocus.ts` + `MapExplorer.tsx`): `linkFocus` is session state bound to the `searchId` of the search its link started (a `searchSeq` ref and a per-view `resultSeq`). The focus is a pure derivation over the displayed arrays. It is cleared by Show all, a view switch, a window change, a media chip change, and any new search. If the species is not in the results, everything shows, with the statement line "{name} was not found within 25 miles. Showing all lifers." The name comes from the app's own name-to-code map; with no name the line reads "The bird you tapped".
- **Pill CSS**: the name ellipsizes before "Show all", which never truncates. `min-width: 0` is needed on the row as well as the button and the name. Without it, a long name at 320px / 200% text hung off the left edge of the viewport, with page scrollWidth still reading 320.

### Notes for reviewer

- **Caught by a screenshot, not a test.** The first cold-start forward called objc2's generated `URLContexts()`, which is declared non-optional. UIKit returns nil on an ordinary launch, so the app aborted on EVERY launch; the launch screenshot showed the home screen. It now reads through an `Option`-typed `msg_send!`, and `iosWidgetManifest.test.ts` forbids the binding.
- **xcodegen emptied the app's entitlements.** An `entitlements: path:` key makes xcodegen rewrite that file from its (absent) properties. Both targets now name their files through `CODE_SIGN_ENTITLEMENTS`, `DEVELOPMENT_TEAM` moved into `project.yml` (xcodegen dropped it from the pbxproj), and the guard asserts no target uses the key.
- **Deviations from the schema, each measured:**
  - The extension's version is stamped by a build phase that copies both keys from the app plist, not by environment variables. Tauri scrubs the xcodebuild environment, and it also writes `CFBundleVersion` into the extension plist itself. The guard accepts either form.
  - The link controller answers every native poke by TAKING the parked URL, not by applying the event payload, so a URL is applied once however the cold and warm paths interleave.
  - The reducer moved to `lib/recentObsReduce.ts`, shared by `mapService.ts` and the twin, rather than into `widgetRows.ts`.
  - The plist readers moved to `src/test/appleManifest.ts` rather than being imported from a test file (which would run that file's suites twice).
  - `deepLink.ts` is not on the entry graph (only its type is); the guard asserts it is dependency-free instead.
  - The widget copy table is `Logic/WidgetCopy.swift`.
  - `contentMarginsDisabled()` with the mockup's insets taken as a CAP on the system margins, plus tight leading. With the default 16 pt margins a 158 pt medium tile measured room for two rows, not three.
  - The small family is capped at `.xLarge` Dynamic Type; at `.xxLarge` its header and glyph line clipped.
  - On the small Any card, a 158 pt tile cannot hold the distance, the recency and two or three glyphs on one line for an ordinary row. The glyphs stay at the end of the distance line and the recency drops under the distance. Only when even that does not fit do the glyphs wrap under, right-aligned as in the mockup. See `OneBirdCard.swift`.
  - The S12 placeholder keeps its header readable (`.unredacted()`, which also beats WidgetKit's own outer redaction), and VoiceOver reads only the header while it shows. `placeholder(in:)` receives no configuration, so the placeholder header shows a new widget's default window (Week).
- **Two schema claims corrected by measurement.** JS `toFixed` and C `%.1f` do NOT agree on exact binary ties (0.25 gives "0.3" vs "0.2"), so Swift carries an exact `toFixed` twin and the fixture pins the ties. The symmetric-difference examples ` 2026-09-01` and `2026-09-01T00:00` are refused by the app too; the corpus test lists what the app actually admits.
- **Declared differences from Map Explorer**, each asserted in `widgetRows.parity.test.ts`:
  - The widget drops a record with no species code, a date the strict parse refuses, or coordinates out of range.
  - It counts CALENDAR days. The app's `isWithinWindow` is one day short on the day after a spring-forward transition; proposed for ROADMAP, not fixed here.
- **Not verified here:** anything that needs a device or an eBird key. The simulator sandbox had the synthetic demo files and no key, so the live widget showed S2, and rows were verified through the fixture and XCTest fakes. The dense-body memory bound is measured in-process by `DenseBodyTests` (a 1.8 MB, 5,400-record body through the real engine grows the footprint by 7.6 MB by the kernel's own peak, against a 15 MB budget), but not in the extension process on a device (NFR-02). Also unmeasured: a cold location fix against the 10 s bound (OQ-07), `--validate-app` on the split deployment target (V4), and the portal steps.
- **Mutation checks:** six of seven designed mutations went red. The seventh (drop the "unloadable backup" early return) stays green because the null dereference throws, and a build that throws is treated exactly like one that refused (it goes to the same revocation decision). The explicit line is kept for intent. The M1 revocation rows were checked separately. Each of seven mutations turned its own rows red: no revocation, refusing bad names, no removal fallback, no pending retry, the two boot rules, and an uncaught build throw.
