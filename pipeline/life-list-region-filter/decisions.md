# Decisions: life-list-region-filter

- **D-01 (2026-11-09, Case 1 cascade from the Architect's flag).** FR-02 said a county is offered whenever the County cell is non-empty, while its own last clause and QA-02 require a hyphenated State/Province cell. FR-02 now reads the QA-02 way: a county needs both a non-empty County cell and a hyphenated State/Province cell. Also folded in the schema's declared bound: a State/Province cell over 16 characters or a County cell over 96 is not offered at any level, so every offered region is savable and no unbounded label reaches the DOM. No real backup is affected; the PRD governs and now agrees with the schema.
- **D-02 (2026-11-09, The Designer).** The Region control is designed within `pipeline/design-system.md`, with no new token and no new pattern: it is the Targets county picker's `aria-activedescendant` combobox at the Life Lists strip's own 30px control register (the `sm` species-picker size), first in the strip because it narrows what the switches act on (OQ-4's default). Three choices worth recording. (1) The `SectionCard` around the tab releases its `overflow: hidden` for this tab (`style={{ overflow: 'visible' }}`), and the control strip carries the card's top radius itself, because the listbox hangs below the strip and a short list would clip it; nothing below the strip has a fill, so the corners still read as the card's. Reversal: if a second overlay or a fill below the strip ever needs the clip back, render the listbox in a portal instead. (2) The count sentence sets the region's label in `--sr-text` at 600, one step under N's 700, because under a region the place is what changed; `countSentenceParts` therefore returns the sentence in parts around the label (schema 4.5 is amended by the Engineer to a four-part return with the label kept as text, never markup). (3) No per-choice species count in the list (FR-04 permits one, Out of Scope lists it): the count before the switches would disagree with the sentence's figure after them, which invites a question the control cannot answer. A country shows a muted "country" word beside its code in the closed field only, because the backup spells Canada "CA" and no country-name table exists (OQ-2); the sentence still reads "in CA", which is flagged in the spec for the user's call.

- **D-03 (2026-11-09, design review direction; re-entry as scoped errands).** At the Designer's review the user approved the grouped type-to-find picker and asked for country NAMES instead of codes. The brief stands (it never fixed the label). The PRD's FR-04 default ("a country shows its code"), its Out of Scope line "no country-name table" and Open Question 2 change: a country is shown by its English name wherever the app can resolve one from the engine's own locale data, and by its code where it cannot, with identity, matching and the stored value staying the code. The Designer updates the mockup and spec. Each builder amends its own artifact and leaves the rest standing.

  Pass 1R at the realistic cap reads 87.3 ms first call, under the schema's 150 ms line, so it stays a pass of its own and pass 1 is untouched (the fold is not taken). The tab's whole load at the cap is about 185 ms of main-thread CPU on the first call (pass 1 41 ms, pass 1R 87 ms, pass 2R 51 ms, pass 2 about 5 ms), inside the schema's 200 to 250 ms expectation, all in the load effect after the awaited parse. Pass 2R reads above the schema's "under 10 ms" (20 ms best, 51 ms first): it inserts every joined asset under up to three regions, three Map writes per row where pass 2 makes one. A region press costs at most a few milliseconds at the realistic cap. **The worst case is a residual, recorded rather than fixed:** a file whose every row names its own country, state and county (which no eBird export can produce, since eBird's subnational codes are a closed set) costs about 0.9 s of main thread and 187 MB at the 150k-row cap. The sort is not the cost (150,000 labels sort in 18 ms with `localeCompare`; V8 takes its ASCII fast path); it is allocating 450,000 one-species inner Maps and their choices. - **D-05 (2026-11-09, The Engineer). Build choices that depart from or add to the schema and design, each with its reason.**
  - **The component is `LifeListsRegionPicker.tsx`**, the design spec's name; schema 4.4 named it `LifeListsRegionControl.tsx` and left the name to the Designer.
  - **A country is named only when its code is two capital letters A to Z**, before `Intl.DisplayNames` is asked. eBird's country codes have that shape; anything else labels as itself, so a lowercase "us" (which the engine canonicalizes to "United States") can never borrow the name of "US", and the memo is bounded at 26 x 26 entries for the module's life rather than by the distinct cells. A malformed code therefore never reaches `.of`; the `try/catch` stays for an engine whose `.of` throws on a well-formed one, and a test stubs that.
  - **A State/Province cell whose country part is empty ("-CA") belongs to no region**, as an empty cell does (FR-03): it could not be saved (the validator needs a code of at least one character) and its country would label as blank. No eBird export has one.
  - **`regionName`'s bare-key table lookup is guarded at this call site**: a hostile "US-constructor" cell returns an inherited member there, so `regionLabel` uses the result only when it is a non-empty string and labels as the code otherwise (security.md's v0.5.81 lookup-table rule). `regionNames.ts` is unchanged, as schema 4 lists it; its other callers carry the same latent read, recorded as a follow-up.
  - **The saved region's read is bounded**: it rides the load's `Promise.all` through a small wrapper that never rejects (a rejection reads as nothing saved) and settles after 10 s at the latest, so the one dependency this feature adds to the load effect cannot hold the tab on its loading state (CLAUDE.md, promise boundaries). On a healthy server it has as long as the two file loads take.
  - **Region writes run one at a time, in press order**, on a per-tab promise chain, so a quick change of mind cannot land out of order on the web/Pi route (a POST and a DELETE are separate requests). Each stays best-effort and silent (FR-22). Choosing the region already shown is a no-op: no press, no write.
  - **`aria-controls` is set only while the list is open** (ARIA 1.2: the popup's id only needs to be referenced while it is displayed), so every IDREF the control mints resolves, which the tab's existing every-IDREF-resolves row asserts.
  - **The input draws no focus ring of its own; the field draws it** (the accent border and the global input ring's halo on `:focus-within`), with `.sr-lfl-region-input:focus-visible { outline: none; box-shadow: none }` placed after the global ring block, which it out-ranks at (0,2,0) against (0,1,1). Without it the global `input:focus-visible` outline would draw a second ring inside the field.
  - **The strip's top radius is 11px, not the spec's 12px**: the card is 12px with a 1px border, so its inner curve is 11px and the faint fill meets it exactly; 12px would leave a sliver of the card surface at each top corner.
  - **The chevron's glyph rotates through its own class** (`.sr-lfl-region-chev-glyph`), never a `.x svg` selector (ui.md v1.0.42); the search and check glyphs have their own classes too.
  - **The listbox owns the one mousedown handler** and reads the option's index back from `data-i`, so options carry no handler at all (the design spec's "no per-option handler"); the Targets picker binds one per option.
  - **`countSentenceParts(n, formats, region = null, order, copy)` returns `{ count, before, region, after }`** (D-02's four-part return; `rest` is gone). Unfiltered, the whole sentence is in `before` and `after` is empty, so the tab renders the same two text nodes it rendered before. Two existing copy-suite call sites passed `order` third and now pass `null` before it.
  - **`buildRegionChoices` is exported** so the C log C linearity row can time the choice build on its own.
  - **Two existing tab rows queried `{ name: /Show/ }`** to assert the paging buttons were gone; the Region chevron is named "Show regions", so they now query `/^Show (next|all)/`, which asserts the same thing.

- **D-06 (2026-11-09, The Engineer). Known limitations, recorded.**
  - **The open list renders every shown choice.** A real backup offers tens to a few thousand regions, which render at once with no lag; a hostile file with hundreds of thousands of distinct places (D-04's worst case) would render that many options when the list opens. Typing narrows the list first. Reversal: windowing the listbox, if a real export is ever measured past a few thousand choices.
  - **QA-28's "on both transports" and QA-34 rest on structure, not a two-seam run:** `lifeListsRegion.ts` imports no seam, transport, platform or React (its own suite pins the import list, and `exoticProvenanceGraph.test.ts` asserts it reaches no network module), so its outputs are the same on every platform by construction, and a region press reaches the storage seam only for its one setting write. The tab suite asserts zero requests on a press with the transport mocked.
  - **Glyphs stay at their pixel sizes at 200% text** (13 and 14px), as every lucide glyph in the app does; the field, options and touch targets scale.

- **D-07 (2026-11-09, The Engineer, at the Tester's QA attempt 1 finding on QA-34).** D-06's second limitation argued QA-34 and QA-28's "on both transports" from structure ("`lifeListsRegion.ts` imports no seam"). The Tester did not accept that as a substitute for the PRD's committed two-seam row, and every Region row in `LifeListsTab.test.tsx` mocks `storage` whole, so the read-back claims of FR-22 to FR-24 had not run through the real `storage.ts` (testing.md v1.0.64). That argument is replaced by `frontend/src/lib/lifeListsRegionConvergence.test.ts`, in the shape of `exoticProvenanceConvergence.test.tsx`: a `describe.each(['tauri', 'web'])` with `vi.resetModules` per seam, the real `storage.ts`, a mocked plugin-fs for the Tauri seam, a mocked `/settings/{key}` route for the web/Pi seam and a mocked `platform`. Each seam writes the matched choice's `RegionRef` with `storage.setSetting('lifeListsRegion', ...)`, reads it back through `parseStoredRegion` and `findChoice` and gets the same choice object, derives the region's rows (`regionFirsts`, `regionAssets`, `selectRows` with the world asset map as presence, for no format and for Photo), and after `deleteSetting` reads `null` with the key absent from `data/settings.json` (Tauri) and from the route (web/Pi), a neighbouring key untouched and, on web/Pi, both writes carrying `APP_REQUEST_HEADERS`. A last row asserts the two seams' rows are identical. The rows are module-level; mounting the tab under both seams would also need the two file caches over each seam's file reads, which is not this suite's shape. Behaviour was already right (the Tester's temporary two-seam check passed); this is the missing guard. D-06 stands as written otherwise.
