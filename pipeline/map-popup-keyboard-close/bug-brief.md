# Bug Brief — Map Popup Keyboard Close

## What is broken
- Five map popups still render maplibre's own injected close button. It carries no `tabIndex`, and WebKit's default tab mode (what the shipped Mac, iPhone and iPad apps run) skips a plain `<button>` entirely, so that control is not reachable by keyboard on those platforms.
- Verified per popup, not generalized. **No keyboard close at all:** `AtlasLayer.tsx:221` (atlas block), `CountyLayer.tsx:421` (county), `SightingsMap.tsx:160` (Sighting Locations pin). **Close only via a sidebar row, never from the popup or the marker:** `TargetMarkers.tsx:110`, `NearbyLiferMarkers.tsx:94` — their markers are real focusable buttons but call `onSelect(id)`, a set, so re-pressing the marker that opened the popup does nothing.
- The idea's claim holds, with one refinement: the clearing path already exists everywhere. `setSel(null)` / `setSelectedCoord(null)` / `onSelect(null)` is wired on each popup's own `onClose`; it is simply unreachable, so the fix is the close button and NOT the list rows.
- No Escape handler in any of the five (`grep -c Escape` is 0 in all five files; maplibre-gl 5.24.0 has no popup Escape anywhere). No map popup traps focus. This is WCAG 2.1.1 operability and dismissibility, not a 2.1.2 keyboard trap.
- Two adjacent popups are already app-owned and out of scope: `BirdingStats.tsx:1221` and `map/SharePopup.tsx:184`. Two more, `SightingMarkers.tsx:128` and `HotspotMarkers.tsx:264`, pass `closeButton={false}` with no replacement button at all and close only by empty-map click or the sidebar row toggle; that is a separate observation, not this fix (see Blast radius).

## Steps to reproduce
1. Build and run the desktop app (or Safari with macOS "Keyboard navigation" off, which is the default and what WKWebView follows). Load a backup.
2. Map Explorer, My Sightings: turn on **California atlas blocks**, Tab to the **Atlas blocks in view** panel, activate a row with Enter. The block popup opens.
3. Press Tab repeatedly. Focus passes through the popup's own eBird link and straight out into the rest of the page; the × is never reached. Press Escape: nothing (it exits fullscreen or closes the mobile filters instead, per the two handlers at `MapExplorer.tsx:583` and `:617`). The popup stays open.
4. Repeat with **County lines** on and a **Counties in view** row (`CountyLayer.tsx:421`), and on Species Detail's **Sighting Locations** map in Pins mode by tabbing to a pin button and pressing Enter (`SightingsMap.tsx:160`). Same outcome at all three.
5. For the other two, open a Media Targets or Nearby Lifers popup from the marker chip rather than the sidebar: pressing Enter again on the same chip re-selects rather than closing, and the only close is to leave the popup, find the sidebar row and re-activate it (behind the Filters overlay at phone widths).

## Expected behavior
- Every map popup the app renders carries a close control that is reachable by Tab and activatable by Enter or Space on every platform, drawn in SnowRaven's own markup rather than by the library.
- Each of the five keeps the exact dismissal semantics it has today: only the close control changes owner. `closeOnClick` stays `false` on `AtlasLayer`, `CountyLayer` and `NearbyLiferMarkers`, and stays at maplibre's default `true` on `SightingsMap` and `TargetMarkers`.
- The button is styled and named as maplibre's is (`className="maplibregl-popup-close-button"`, a literal `tabIndex={0}`, `type="button"`, an `aria-label`), so it inherits the existing theming and the ~44px coarse-pointer target already in `globals.css:3062-3077` and nothing moves for a mouse user.
- The four sidebar in-view lists keep toggle-to-close exactly as published; the atlas and county panel rows keep opening without closing, because the popup now carries its own dismissal.
- `ACCESSIBILITY.md` stops publishing "Three popups have no keyboard close at all" and says what is now true.

## What done looks like
- **Per popup, from the keyboard, on a WebKit build:** atlas block (`AtlasLayer`), county (`CountyLayer`) and Sighting Locations pin (`SightingsMap`) each gain a Tab-reachable × that closes them, which they had no route to at all; Media Targets (`TargetMarkers`) and Nearby Lifers (`NearbyLiferMarkers`) gain a close inside the popup, so a marker-opened popup no longer has to be dismissed from a sidebar row. All five still close by their existing pointer routes, unchanged.
- **The five new buttons are inside the guard:** `lib/tabOrderCoverage.test.ts` sees them as ordinary intrinsic `<button>` sites carrying a literal `tabIndex={0}`, with no new `EXCLUSIONS` row, and `SightingsMap.test.tsx` asserts the app-owned button rather than maplibre's. Green `npm run build`, `npm run typecheck` and the full frontend suite; `entryChunk.test.ts` still green.
- **Library DOM untouched:** no `setAttribute('tabindex', …)`, no `querySelector` into `.maplibregl-*`, no imperative patching anywhere. Every new control is JSX in the app's own sources, which is what keeps the published claim checkable from source.
- **Published prose is true again:** `ACCESSIBILITY.md`'s three affected paragraphs rewritten at paragraph scope, with **no em dashes (U+2014)** in any published prose, and the claim stated as a property rather than a count. `docs/HELP.md`, `README.md` and `website/` need no edit: neither describes closing an atlas, county or sighting-locations popup, and nothing changes visually for a mouse user.
- **Website shots unaffected:** `website/tools/capture.mjs` captures `map-light.png` / `map-dark.png` through the generic `tab()` helper with no `prep` hook and no pin click, so no popup is open in any captured frame; no recapture needed.
