## Map Explorer recency colors at daylight-saving changes (map-recency-dst-colors)

### What this does
The Map Explorer colors each Media Targets and Nearby Lifers report by how many calendar days ago it was made: the past 7 days, 8 to 15 days, or 16 to 30 days. `recencyTier` floored the hours between two local midnights, so in any zone with daylight saving it counted one day short whenever the span held the 23-hour spring-forward day: for the 8 days after the change an 8-day-old report took the "past 7 days" color, and for 16 days a 16-day-old report took the middle color. It now rounds, the same fix `isWithinWindow` took at 1.0.39. The two screen-reader tier labels in the Targets in view and Nearby lifers in view lists also said "8–14" and "15–30" days; they now say "8–15" and "16–30", matching the function, the Media Targets popup and Help.

### How to test
1. `cd frontend && npx vitest run src/lib/mapExplorerFormat.test.ts src/lib/nearbyLifers.test.ts`. Expect 2 files and 32 tests passing.
2. In `src/lib/mapExplorerFormat.ts`, change `Math.round` back to `Math.floor` in `recencyTier` and run the first file again. Expect 3 red rows: the day after spring-forward, 16 days after spring-forward, and the 2026 corpus row. Put `Math.round` back.
3. On screen the fix shows only in the 8 days (fresh/mid edge) and 16 days (mid/old edge) after a spring-forward date, so the tests are the practical check. `how-to-see.md` has the steps for a manual look.

### Notes for reviewer
- **The fix is one call.** `Math.floor` becomes `Math.round` in `recencyTier` (`frontend/src/lib/mapExplorerFormat.ts`), and the function gained a doc comment saying why rounding is correct: a span with no DST change is a whole multiple of 24 hours, so round and floor agree exactly there; across a change the span is N days plus or minus one hour (the spring-forward day is 23 hours, fall-back 25), which rounds to N; a malformed date still yields NaN, fails both comparisons and falls to 'old'. No boundary, color token or visible label moves.
- **Blast radius is the brief's nine call sites, all Map Explorer** (the windowed lifer tier and the Targets in view dot in `MapExplorer.tsx`, the popup dot in `map/NearbyLiferMarkers.tsx`, the chip color and popup label in `map/TargetMarkers.tsx`, the lifer pin color and Lifers in view dot through `nearbyLifers.ts`, and the widget bird-tap focus in `links/linkFocus.ts`). All inherit the fix; none was edited.
- **Labels.** Only the numbers changed in `MapExplorer.tsx`; the en-dash range form is kept because the visible popup uses the same form ("8–15 days"). `docs/HELP.md` already says 8 to 15 and 16 to 30 and stays true, so it is not edited.
- **No shared helper was extracted.** `recencyTier` and `isWithinWindow` now use the same rounding, but extracting the day count would have touched `nearbyLifers.ts` too, which the fix did not need.
