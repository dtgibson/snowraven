# Decisions: map-scroll-on-phones

Improve lane with a design pass (7 steps). The Family Tree run referred to below is `family-rollups-and-tree`, in the main `snowraven` folder; its record is `pipeline/family-rollups-and-tree/decisions.md` there, read from here and never edited.

- **D-01. User direction (2026-11-21): this build runs on Autopilot.** Asked how involved to be, the user said to go with whatever the session that started this build said, guessing Autopilot. The Family Tree run's D-18 names this build and the one-release plan and states no mode, so the user's guess stands. The run stops for the deploy sign-off and for a genuine blocker only.

- **D-02. User direction (Family Tree D-18, restated in this build's seed): one combined release, no rush.** This build does not bump the version, write a changelog entry, tag or ship alone. It holds at its deploy sign-off, the two builds are brought together, and one version goes to every platform.

- **D-03. The phone form is taken from the Family Tree design review and is open until the user chooses there.** As of 2026-11-21 the Family Tree session reports the revised mockup shows the phone tree as a still in the page with an "Open the tree" button that opens it full screen on the map pattern, and the user has not yet chosen between that and the outline flowing with the page. The map tabs are not designed against either form until that session sends the decision number and file. This is the one thing the design step waits on.

  **Settled 2026-11-21 (Family Tree D-20, the user's words on the revised mockup: "Phone tree is good").** On the phone tier nothing half-visible can be scrolled in the page, and the scrolling surface is used full screen: the tree sits in the page as a non-scrolling, inert still with an "Open the tree" button; pressing the still or the button opens it full screen on the map full-screen pattern (a class swap on its own container), where its box is the only scroller; Exit and Escape leave it, and zoom, place, expansion and selection are kept. The alternative (the content flowing with the page) was offered and not taken. Above the phone tier the box stays live in the page, is never taller than the window, and a press or focus on a half-visible box first brings all of it into view; the full-screen toggle is in the toolbar on every tier. The mockup is `pipeline/family-rollups-and-tree/design.html` in the main folder (`?viewport=390&view=tree`). This is the form the map tabs take; The Designer applies it to the six surfaces.

- **D-04. Agreed with the Family Tree session (2026-11-21): this build owns any change to the shared full-screen code.** `lib/useMapFullscreen.ts`, `.sr-map-fs-panel` and its styles, and the bottom bar's handling while a panel is expanded are edited here; the Family Tree build consumes the result, landing after this build or on top of it. Each session tells the other before building a change to that code.

- **D-06. Scope addition from the user's question (2026-11-21): the in-page dropdown lists join this build.** The user asked whether any other tab has the scroll-within-scroll behavior, "while we are at it". Read from the code and then measured (`baseline-measurements.md`, section 5): the five dropdown lists (Hotspot Reports' hotspot picker, Life Lists' region picker, Targets' county picker and its distance popover, the shared species picker) are the only other in-page vertical scrollers; a sweep of 14 tabs found none besides them. They are whole at 390x844 with no keyboard and 32% to 55% hidden at 320x568, and the Targets popover runs under the bar at 320x568 from any position. The Guide told the user a fix would be folded in if a list measured off screen unless the user asked for maps only; it did, so it is in. Not measured: the on-screen keyboard, which shortens the visible area for the four lists that belong to text fields. Reversal: the user asks to keep this build to maps, and the lists are saved as their own idea.

- **D-05. Open, shared with the Family Tree run (its D-19): what sits above what while a panel is full screen on a phone.** The embedded map panels and the bottom bar are both at `z-index: 1200`, and the tree mockup's 1250 is a mockup number only. This build measures whether the bar paints over an expanded embedded map (`baseline-measurements.md`), then proposes one answer for both builds: raise the embedded panels above the bar, or remove the bar while one is expanded as the Map Explorer's own full screen does (v1.0.17). What would decide it: the measurement, and whether a raised panel still sits correctly under the More sheet (1260) and Search.

  **Measured 2026-11-21: the bar does paint over the expanded embedded map and takes the taps meant for exit and share, in both engines at both sizes** (`baseline-measurements.md`, section 3). **Proposed to the Family Tree session, to be confirmed by The Designer's pass here: remove the bar while any panel is expanded, as the Map Explorer's own full screen does (v1.0.17), driven from the shared hook so every consumer gets it, with the panel left at 1200.** Reasons: the app keeps one full-screen geometry (v1.0.15); a bar that is not in the page cannot take a tap, keyboard focus or a screen reader's cursor under the panel, where a raised panel would still leave it reachable; the bar's two heights (56.5 px, and 68 px when a label wraps) stop mattering; and the More sheet and Search keep their place above. What it costs: the hook must tell `App.tsx` a panel is open through an entry-safe signal, since the hook is on the entry chunk and the hosts are not. Reversal: The Designer or The Engineer finds the signal cannot be made entry-safe, and the panels are raised above the bar instead with the bar made inert.

## The Designer's pass (2026-11-21, Stage 2, hands-off)

The mockup is `design.html`, the spec `design-refinement.md`, the pictures `design-shots/`. Designed inside `pipeline/design-system.md`; the two places it deviates from that file are D-10 and D-12, each scoped to the phone tier. "The phone tier" below is the media query `(max-width: 640px)`.

- **D-07. D-05 stands: the bottom bar is removed from use while any panel is expanded, and the panel stays at `z-index: 1200`.** How: the shared hook sets `data-sr-fs-open` on `<html>` in a layout effect while `expanded` (counted, so two consumers cannot clear each other's), and one rule does the rest, `:root[data-sr-fs-open] .sr-navbar { visibility: hidden; }`. The hook only says a panel is open; the stylesheet decides whether there is a bar to hide, and no script tests a width for it (the Family Tree session's request, since its narrow form also shows on desktop at large text). `visibility: hidden` rather than not rendering the bar: it stops paint, hit-testing, focus and the accessibility tree, which is everything D-05 wanted from removal, and the bar keeps its box, so `--sr-navbar-h`, the page's bottom padding and the page's scroll position do not move behind the panel (the Android keyboard rule already hides this bar while keeping its box). A layout effect rather than an effect, so no frame paints the bar over the panel. Checked against: the More sheet (1260), which cannot be opened while a panel is expanded because its button is in the bar, and keeps its level; Search, which opens above the panel as today and whose route to another tab collapses the map and so brings the bar back; the safe-area insets, where the panel's top and side padding are unchanged and the corner row carries the bottom inset. The entry-chunk constraint is met with no new import and no store. The Map Explorer's own fullscreen keeps its shipped mechanism (the bar is not rendered). Considered and not taken: `:root:has(.sr-map-fs-panel) .sr-navbar`, which needs no script at all and cannot go out of step with the class, because where `:has()` is unsupported (an old browser on a web/Pi install, which this app does not choose) the failure is the defect itself. Reversal: a measured frame with the bar over the panel, or a guard that cannot pin the attribute; then the fallback in D-05 (raise the panel, make the bar inert).

- **D-08. The still: on the phone tier every map in a page is the same live map made non-interactive, and a press on it opens it.** The host wraps its map subtree in one element that is `inert` and takes no pointer while still; nothing is remounted, portaled or replaced by a picture, and fullscreen stays the class swap on the host's own container with no animation or transform on the panel. Not drawn on the still: zoom, the base map switcher, the corner row, the cooperative-gestures hint (a control drawn where it cannot be pressed reads as broken, and the Family Tree's still hides its tools for the same reason). Drawn: the map and its credits. A press anywhere on the still opens the map; **a press on a pin opens the map and does not also choose the pin**, because the still cannot tell which pin was pressed without becoming interactive again, and an open-and-select in one press would pick the wrong pin at the edges. Evidence: none measured; it is one extra tap. Reversal: the user finds the second tap a nuisance at the live look; the fix is to hand the press's point to the map after opening (in the host's `open` path, `queryRenderedFeatures` or the marker under the point) and select what is there. An open popup and a dropped share pin stay drawn on the still as part of the map as left; they are pressable in fullscreen.

- **D-09. The opener is one register for the maps and the Family Tree: a full-width accent button under the still, `Maximize2` and a label, with one helper line.** Classes `.sr-fs-open-row`, `.sr-fs-open-btn`, `.sr-fs-open-note`, declared once in `globals.css` by this build with the values the user approved on the Family Tree mockup (radius 8 px, 0.875rem / 600, 44 px tall on the tier). The maps say `Open the map` and `It opens in fullscreen, where it pans and zooms.`; the tree says `Open the tree` and its own line. The button sits under the map and outside the box that expands, never on the map: on the map it would cover the credits or the data, and under it there is always room. The accent is spent here on purpose: on a phone it is the only way to use the map. What it costs: each surface is taller by the row (about 70 px at 100% text).

- **D-10. On the phone tier the exit carries its word, the corner row stands above the credits, and the card's compact discs take the standard size while expanded. This narrows a clause of `pipeline/design-system.md`.** That file says the fullscreen toggle "does not gain a label, and does not change size on expanding", for two reasons it gives: a toggle whose exit differs is two controls under one name, and a control should not grow under the finger that pressed it. On the phone tier neither reason applies, because the control that opened the map is the button under the still and the corner row is not drawn until the map is open. So there Exit is the same button and glyph with the word "Exit" (accessible name unchanged, "Exit fullscreen"), matching the Family Tree's phone exit, and it is 44 px tall on every surface, the Named Birds card included (its 40 px density is for the 220 px card). The row moves from `bottom: 20px` to `calc(20px + 3rem)` plus the inset so the open credits and the buttons never share a band: at HEAD the share disc already covers the end of the credits at 390 px, and a wider Exit would cover more. Above the tier the toggle is byte-identical to HEAD. **Not acted on: the Map Explorer's own exit stays the icon-only disc.** Evidence: its three discs have 4.00 px of slack at 320 px and 200% text (v0.5.84), so a labelled exit does not fit, and its toggle is the control pressed to expand whenever the map is live in the page, so the design-system clause holds there in full. Reversal: the user asks for one exit everywhere; the fix is a labelled exit in the cluster's full-width row slot (the v0.5.91 row), measured at all four text scales.

- **D-11. The shared hook grows by addition only; nothing is renamed.** Kept exactly: `useMapFullscreen`, `MAP_FS_PANEL_CLASS`, `className`, `expanded`, `toggle`, `collapse`, `registerToggle`, and the `.sr-map-fullscreen-btn` selector as an optional last resort in `focusToggle`. Added: `stillTier`, `still`, `open()` (idempotent), `registerOpener`, `hostClassName` (the base class list plus `MAP_STILL_CLASS` while still, so `className` stays what the Family Tree already imports), the bar attribute (D-07), focus to the toggle on open when focus is outside the container, focus to the opener (else the toggle, else the fallback) after a user exit with each attempt read back, and the page's scroll offset recorded on lock and restored after a user exit. The tier is read inside the hook through `lib/useIsPhone.ts`, the same query the stylesheet block opens at, which adds one dependency-free import to an entry-chunk module and one line to `mapFullscreenEntrySafe.test.ts`; if that import is refused, the host passes the tier in and the returned API is unchanged. `containOutsideFocus` stays armed on `expanded`, which is the condition that makes the surface modal on every tier.

- **D-12. The Weather picker: the still shows the place chosen, and the pin is placed in fullscreen.** On the phone tier a tap in the page no longer drops the pin; opening the map is where it is dropped and dragged, exactly as today's gestures. The place search and the Latitude and Longitude fields stay on the page and complete the picker with no map, so keyboard and screen-reader users lose nothing. The page's line becomes `Open the map to drop a pin, or type coordinates below.`, and fullscreen shows one statement at the top centre (`Tap the map to drop a pin.`, then `Drag the pin to fine-tune. Exit when it is in place.`). The inline size is lifted to `.sr-wx-pick-map` with the same values, on the placeholder twin too, so the panel can size it (maps.md trap c). This narrows the design system's "a map that is a location input gets no row at all" to "no row in the page; Exit alone while expanded on the phone tier". Considered and not taken: a Done button instead of Exit, which would be a second word for the same act on one surface. Above the tier the picker is HEAD.

- **D-13. Hotspot Reports' map gains the opener and fullscreen on the phone tier only. This touches hotspot-reports D-01 (accepted at its D-03 design review): a plain map with no corner controls.** Reason: the user's later direction (this run's D-03) is that nothing half-visible is interactive in the page, so on a phone this map must be a still, and a still with no opener would take panning and zooming away from phone users altogether. What is kept of D-01: above the tier it is unchanged, with no corner row and no fullscreen; on the tier its fullscreen holds Exit, zoom and the credits only, with no share pin, switcher or popup. Reversal: the user would rather this map be a plain picture on a phone; then the opener and the hook call are removed and the still stays.

- **D-14. The Map Explorer stays live in the page wherever its panel fits, and takes the still where it cannot.** Two changes. The panel's floor on the phone tier becomes 300 px on every platform (it is 340 px outside the iPhone app): at 320 x 568 the window leaves 305 px, so the measured 35 px of page scroll under the live map goes. And where the window still cannot hold the panel (the panel is on its floor; small phones at large text, where v0.5.91 accepted a 24 px overflow by design), the map is a still with the same opener inside the panel, opening the tab's own fullscreen. So "the page never scrolls under a live map on the phone tier" holds at every text size, not only at the measured ones. This modifies v0.5.91's floor for the phone tier and keeps its scrollport decision. What it costs: 40 px of map height on a 320 x 568 browser, where the map was scrolling anyway. Not measured: text scales above 100%, which the Tester reads. Reversal: the Tester finds the floor-bound case unreachable at every shipped scale and size, in which case the still is dropped and only the floor changes.

- **D-15. The five dropdown lists keep to the room that is visible, by measurement.** On the phone tier each list's height is the smaller of its own cap and the room under its field down to the bar, or to the on-screen keyboard (`visualViewport`), less 8 px; when that is short, opening first brings the field to the top of the visible area with an instant scroll; when there is not enough either way, the floor is one and a half option rows. The Targets chooser becomes one scroller with its inner list released, which removes its second scroller as well as its 465.5 px height. `.sr-tg-combo-list` and `.sr-combobox-list` gain `overscroll-behavior: contain` on the phone tier only (above it they match HEAD). The species picker's inline `maxHeight` moves to its class so a rule can reach it. A stylesheet cannot do this alone: the room under a field depends on where the page is scrolled and on the keyboard. Considered and not taken: turning the lists into bottom sheets on a phone (a larger change, and a sheet fixed to the bottom is behind the iOS keyboard), and locking the page while a list is open (the page is every tab's scrollport, and four of these lists belong to fields the user may want to move). Not measured: the keyboard, in any engine; it is the Tester's first item on the lists.

- **D-16. Decision not to act: a phone in landscape, and any window wider than 640 px, keeps HEAD.** There the maps are live in the page with the corner toggle, there is no bottom bar, and fullscreen and its exit already work (the defect in D-05 needs the bar). Evidence: nothing was measured in landscape; read from the stylesheet, a 380 px map in a 375 to 430 px tall window cannot be wholly in view once any chrome is on screen, so the user's principle is not met there. Why it is left: the user's report and the settled form (Family Tree D-20) are about phones in the phone tier, "640 px is the established phone boundary", and the brief holds everything above it to HEAD. What would reverse it: the user reports the same on a landscape phone, or the Tester's landscape reading is judged worth acting on. The exact fix: the still's condition is declared in one place, the query `lib/useIsPhone.ts` reads; widen what the hook reads for `stillTier` to `(max-width: 640px), (max-height: 500px) and (pointer: coarse)` through a second store beside `useIsPhone`, and move the still's and the opener's rules to a media block with the same condition. The bar rule needs nothing, since it is keyed on a panel being open. A map opened in portrait stays open through a rotation and exits to the live in-page map.

- **D-17. The map credits stay legible in every state.** On the still they are drawn open, in whatever state the control was left, because the "i" that would open them cannot be pressed there; the rule that does it must out-rank `maplibre-gl.css`, which loads after the app's sheet (maps.md v1.0.5), and is verified by reading computed values. In fullscreen on the tier the corner row stands above them (D-10). In the apps the credits in an expanded panel take the bottom inset, conditionally: read from the stylesheets and not measured, at HEAD the panel pads top and sides only, which would put the credits 10 px from the bottom edge, inside the home-indicator band; no inset was measured at baseline, so the rule is added only if the simulator shows them in that band, and the reading is recorded either way. The Map Explorer's own panel has the same position and is not changed here; if the simulator shows its credits obscured, that goes to the user as a finding.

- **D-18. The still has a name and no tab stop.** While still, the container is `role="img"` with a short name in the family Hotspot Reports already uses (`Map showing sighting locations`, `Map showing Geographic Stats`, `Map showing this bird's sightings`, `Map showing the chosen place`, `Map showing {name}`, `Map`), its contents are out of the tab order and the accessibility tree, and the opener under it is the one control, described by its helper line. The still's own press handler has no keyboard twin because the button beside it does the same thing; making the still a second button would put two stops with one function on every map page.

- **D-19. Not designed here, recorded so their absence is not read as an oversight.** The Android back gesture with a map open (a search of `App.tsx` and `lib/` found no handler for it at HEAD, for the Map Explorer's fullscreen either; the Tester records what happens). The Map Explorer's filter sheet at 320 px and 200% on short viewports, the tab-switch scroll offset, and the fullscreen disc over the setup card on My Sightings, all of which the brief lists as adjacent and out of scope. The `flyTo` after a Weather pick, which is a GL animation that does not read the reduced-motion preference (maps.md, v0.5.91): unchanged by this design and worth its own look.

## The Engineer's build (2026-11-21, Stage 3, hands-off)

Deviations from `design-refinement.md`, each the smallest correct change, with the evidence and what would reverse it. The build is otherwise the spec.

- **D-20. The credits on a still are opened through maplibre's own state, not by a stylesheet rule (D-17 as written cannot be built).** maplibre-gl 6.8 draws the compact credits as a `<details class="maplibregl-ctrl-attrib maplibregl-compact">`, and its "i" toggles both the `open` attribute and the `maplibregl-compact-show` class (read from `maplibre-gl-dev.mjs`, `AttributionControl._toggleAttribution`). Once a user has collapsed the credits the `<details>` is closed, and a closed `<details>` renders none of its content, whatever author rule targets `.maplibregl-ctrl-attrib-inner`. So `components/map/StillCredits.tsx`, a `<SnowMap>` child mounted by `MapCornerControls` (and by the Map Explorer), puts the control into maplibre's own shown state (both halves, exactly as its toggle leaves them) while the map is a still; maplibre's toggle keeps working on it in fullscreen. Measured in the built app: credits open and inked on all five stills in Chromium and WebKit at both sizes. Reversal: a maplibre release that draws the credits without `<details>`, in which case a rule that out-ranks `maplibre-gl.css` does the job and the component goes.

- **D-21. The still's hide lists are written one selector per control, and the Map Explorer's still has two boxes.** The spec's `.sr-map-still :is(...)` list and the Map Explorer's `.sr-map-fab-cluster > :not(.sr-map-geo-error)` are equivalent to what shipped but each tripped a standing guard for a reason that is about the guard's reach, not the rule: a pseudo-only rightmost compound matches every element as far as `mapFabCascade.test.ts` can tell, and `mapFabClusterCss.test.ts`'s live-region scan reads any rule naming `.sr-map-geo-error` with `display: none` as hiding it. The shipped rules name each hidden control by class, and the cluster's location-failure note is simply not in the list. The Map Explorer still is an outer box that carries `role="img"`, the name and the press, around the one inert body: an inert element leaves the accessibility tree itself, so the name cannot sit on it, and the map area cannot be the picture because its live regions (the search outcome, the landing announcer, the load failure) must stay in the tree. Both boxes are 100% high and nothing else. Reversal: none needed; a guard that learns `:is()` changes nothing here.

- **D-22. The species picker's phone-tier list rule lives in its own `@media (max-width: 640px)` block, after its base rule.** `.sr-combobox-list` is declared after the established phone block, at the same weight, so inside that block the lifted 260px cap would win on source order. Caught by the new resolved-cascade row in `mapFullscreenPanelCss.test.ts` before it reached an engine. The new block is after the established one, which is what ui.md's v1.0.10 rule requires. Reversal: the base rule moves above the established block.

- **D-23. The Hotspot Reports map's box, and its name, moved from `HotspotReportMap.tsx` to its host `HotspotReport.tsx`, and `.sr-hsr-map` is scoped `:not(.sr-map-fs-panel)`.** The host has to own the container through the lazy map chunk so the opener is in the layout from the first frame (spec, "The opener row"), and `.sr-hsr-map` is one class deep and BELOW `.sr-map-fs-panel` in source, so unscoped it would have won the expanded panel's height and position (maps.md traps a and b). The box keeps `role="group"` and `mapLabel(name)` above the tier, exactly as before; the Suspense fallback is now nothing inside that box rather than a second box. `HotspotReportMap` no longer takes `name`.

- **D-24. The scroll margin for "bring the field to the top" is set by `useListFit` for that one call, not by a class on each field.** The spec's `scroll-margin-top` on the anchor needed a class on five field wrappers, and the species picker's root is inside the Statistics Weather section whose markup `WeatherDistRow.golden.test.tsx` holds byte for byte. The hook sets `scroll-margin-top: var(--sr-list-fit-margin, 8px)` on the field for the one `scrollIntoView` and restores it, and the stylesheet gives the variable the top inset under `.sr-ios-app` and `.sr-android-app`. No picker's markup changes. Reversal: none needed.

- **D-25. The Map Explorer's fullscreen toggle carries the `fullscreenButtonRef` its Escape handler was already focusing.** At HEAD the ref was declared and focused and never attached, so Escape left focus where it was. It is attached now because opening from the still must land focus on the exit. Above the tier this makes the shipped behaviour match its own comment and `ACCESSIBILITY.md` ("returns focus to the fullscreen toggle"); it changes no pixel.

- **D-26. Statistics renders the opener under its idle-deferred placeholder too.** The spec says the row is in the layout from the first frame the container is; the Geographic Stats box is a placeholder twin until `mapReady`, so the row is rendered in both branches. A press during that window is held by the hook (`active` gates `expanded`) and the map opens as it arrives, usually within the same idle callback.

- **D-27. Not added: the bottom inset on the expanded panel's credits in the apps (D-17's conditional rule).** It was to be added only if the iOS simulator shows the credits inside the home-indicator band at HEAD. No simulator reading was taken at this stage (the simulator and emulator are the Tester's), so the rule is not added; the Tester reads it, and the fix is one `.sr-ios-app .sr-map-fs-panel .maplibregl-ctrl-bottom-left` rule with its `.sr-android-app` twin, inside the phone block.

- **D-28. While the Map Explorer's map is a still, its panel's floor grows by the opener row (`calc(322px + 2.75rem)`), so the row is never clipped.** Measured in the built app at 320 x 568: the view-mode pills wrap to 226px at 150% text and 265px at 200%, so on the 300px floor the map area was already 0px and the opener row, which the spec puts inside the panel's fixed height, overflowed the panel's `overflow: hidden` by 14px and 75px (at 200% most of the button was cut off). The rule is `.sr-map-explorer-panel:has(.sr-mx-still-host.sr-map-still)` in the phone block. It cannot move the reading that decides the still (the panel's height equals its computed floor, which stays true at the larger floor), and the panel goes live again once the window less the chrome exceeds it, so the still holds a little longer on the way out than on the way in, in the safe direction. Measured after: the row's bottom equals the panel's bottom at 125%, 150% and 200% in both engines, with 142px, 74px and 35px of still map (35px is HEAD's live map height at 200%). `:has()` is in every engine the apps ship on (Android WebView floor Chromium 111). Reversal: a smaller view-mode bar at large text, which would let the 300px floor hold the row.
