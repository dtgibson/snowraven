# Decisions — ml-media-links

## D1. The user's answers at The Designer, round 1 (2026-10-08)

The Strategist, Planner and Architect ran hands-off (Studio Style, the user participates at The Designer only). At the first mockup review the user settled the open questions:

- **OQ-01, named birds: per-item links, not a species-level catalog link.** Macaulay Library's catalog URL has no filter for a named individual, so a format-filtered link from a named bird could only open all of the user's own media of that species. The user's direction: "If we can't do one link for each media type for named birds, lets do a compact list of clickable links." So each named bird's section gets a compact list of links, one per media item of that bird, grouped by format, each opening that asset's Macaulay Library page with the URL the gallery tile already uses. This changes the PRD's and schema's Named Birds requirements (the species-level row and its dependence on the contributor id), which are amended to match once the design is approved.
- **OQ-02, Species Detail: in scope.** The Recent Media card keeps the species-level Photos / Audio / Video row as designed.
- **OQ-03, no contributor id: no row.** Applies to the Species Detail catalog links. Per-item links do not need the contributor id.
- **OQ-04, wording:** option A ("All your media of {species} on Macaulay Library:") for the Species Detail row. The optional helper line is dropped; the user did not find it useful once named birds link per item.
- **Mockup usability:** the review controls must stay on screen while scrolling, so a toggle's effect is visible.

## D2. The user's answers at The Designer, round 2 (2026-10-08): Species Detail dropped, direction approved

- **OQ-02 reversed: no Species Detail row.** The user: "since the media link and the link in recent media are the same, lets remove the redundant one from recent media." The Recent Media row would have repeated the Media card's count links URL for URL (the PRD required them byte-identical), so it is removed and Species Detail is unchanged by this build. The PRD's Group C and the schema's Species Detail work move to Out of Scope.
- **OQ-03 is moot.** With Species Detail gone, nothing in this build uses the contributor id: the named-bird list links each item by its catalog number, so it shows whatever the export's filename says. The schema's contributor-id plumbing on Named Birds is removed.
- **Approved direction:** each named bird's media section gets the compact per-item list from the round 2 mockup ("{name} on Macaulay Library, newest first:", one row per format in Photo, Audio, Video order, numbered in the gallery's newest-first order, every item including those behind "Show more", each number opening the same URL as that tile's existing per-item link; 24px targets on desktop, 44px on phone; accessible name "Photo 3 of 24 of Winky, Jan 18, 2026, on Macaulay Library (opens in a new tab)"; ids from index numbers only). "The rest looks good."
- **The PRD and schema are amended to match** before The Engineer starts, as scoped revisions rather than stage re-runs, since the user settled the direction here.

## D3. The Designer's decisions for the approved design (2026-10-08)

Recorded so the Engineer, QA and the Chronicler inherit the reasons, not only the values. Full detail is in `design-spec.md`.

- **Designed within `pipeline/design-system.md`; no new tokens, colors or type sizes.** Every value in the list already exists in the section around it: the lead in the meta-row voice, the labels in the tile format-marker voice, the numbers in the accent link voice, and the hover box in `--sr-accent-bg`.
- **One local override of the global focus ring: `outline-offset: 1px` and no halo on `.sr-mli-link:focus-visible`.** In a run of 24px boxes 2px apart, the house ring's 3px offset and 6px halo sit over the neighboring numbers. The ring stays the house 3px `--sr-accent` outline, plus the box fill. Precedent for a local offset: `.sr-segbar-btn:focus-visible`. This is a deliberate deviation, measured visible in the mockup.
- **Targets: 24px on desktop (WCAG 2.5.8 size), 44px on phone (the app's `.sr-touch-target` posture), rem-based so both grow with text size.** On desktop the box shows only on hover and focus, so the list stays compact. On phone the boxes abut with no gap. A rem-based negative margin that pulled the phone list left was tried and removed: at 150% and 200% text it grew past the section's fixed 14px padding, and the tap boxes left the card. It overflowed in 32 configurations per engine, then in zero once removed.
- **The accessible name leads with the format word, not the visible number** ("Photo 3 of 24 of Winky, Jan 18, 2026, on Macaulay Library (opens in a new tab)"). It still contains the visible number (WCAG 2.5.3 Label in Name), and each link stands on its own in a screen reader's links list. The PRD's FR-06 "begins with its visible text" was written for the dropped species-level row and is superseded here. The date is in the name and in a `title` tooltip so items can be told apart. When there is no date it is omitted, not shown as a placeholder.
- **Numbering follows the gallery's own newest-first order**, and the lead says "newest first", so number 1 is always the first tile of that format. The count and numbering run over items with a valid catalog number only, so the numbers stay contiguous when one is skipped.
- **One Tab stop per item is an accepted trade-off.** A bird with many items puts that many links before its gallery; the gallery already adds two per visible tile. Each list is labelled by its format (`aria-labelledby` to the label, ids from `useId()` plus the format index), so screen-reader users can skip a whole list. There is no cap, because the user asked for every item.
- **No `<BirdName>` question remains.** The lead names the individual (`birdName`), not a species, so `.claude/rules/bird-names.md`'s rule does not apply. The round 1 species name in plain text went with the species-level row.
- **Species Detail is unchanged and nothing uses the contributor id** (D2). The list's hrefs are exactly `mlAssetUrl(catalogId)`, the tile's own builder: no catalog-search link, no new host.
- **Rule-file gating:** the suggested file name `components/NamedBirdMediaLinks.tsx` falls inside `.claude/rules/media-embeds.md`'s existing `NamedBirdMedia*.tsx` glob. The build adds `frontend/src/components/NamedBirdMedia*.tsx` to `.claude/rules/security.md`'s `paths`, because the file renders hrefs.
- **Measured on the mockup before hand-back**, in Chromium and WebKit: 48 list configurations per engine (320, 390, 744 and 900px; 100%, 150% and 200% text; four birds with media) with no text ink or link box outside the section and no page scroll. A control with wrapping disabled overflowed by 1,827px, so the measurement can fail. `weft-design-lint` reported nothing to fix. QA re-measures this in the built app, since the mockup's ancestors above the section are not the app's.
