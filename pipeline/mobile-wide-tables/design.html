SnowRaven · Design direction

Breeding Codes, comfortable on a phone

Narrow each code column from 44px to ~30px so a full species row is scannable at a glance, and lean on native pinch-zoom to magnify. Everything below uses the app's real --sr-* tokens — a reviewer shouldn't be able to tell it from the running tab.

The species name column stays frozen while you scroll the codes. The colored dot (tier-purple, unchanged) stays the tappable, legible unit. Nothing about the desktop/tablet view changes — this is the ≤640 phone tier only.

The bird never scrolls away

The species name column stays pinned (clamp(7.5rem, 40vw, 220px), unchanged) so you always know which bird a row belongs to while the codes scroll or pan.

Primary gesture

Pinch to magnify & pan

Any dot too small to read? Pinch with the same native iOS gesture you use everywhere else — the whole matrix (frozen column included) scales together. No custom zoom UI ships by default.

Untouched

Dot, sort, filters, legend

The 28px count dot, per-column sort, code/category/county/date filters, the tier legend, and the species links to Species Detail all behave exactly as today.

The magnify feel — pinch first, control as fallback

Native pinch-zoom is the whole bet: it magnifies the entire page (frozen column and all) with no custom code, exactly like pinching any web page in Safari. The −/Fit/+ control below is a designed-but-dormant fallback — it ships only if the on-device check proves the WebView declines native pinch, and only on iOS. It calls Tauri's native setZoom (not CSS zoom, which failed before).

Why pinch

The platform already does this well

Native viewport pinch is categorically different from the CSS zoom / transform: scale that broke the frozen column last time. Under native zoom, position: sticky scales correctly with the page.

Fallback shape

− / Fit / +

Three ≥44px buttons, keyboard-reachable, calling native setZoom(). Dashed here to signal it's not part of the default build — a conscious re-scope only if the device declines pinch.

Your call

Show the control by default?

My recommendation: no — keep it hidden unless the on-device test shows pinch fails. A visible zoom control on a page that already pinches invites confusion. But it's a one-line flip if you'd rather always show it on iOS.

Fidelity: all colors are the exact --sr-* values from frontend/src/globals.css (light + dark). Dots use the real purple tier ramp (tier 4 #3B0764 → tier 1 #C084FC in light); the green accent is reserved for links/active state.
