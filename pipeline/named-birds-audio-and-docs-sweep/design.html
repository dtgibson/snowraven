The phone tier, at or below 640px

One column means the tile gets wider, not narrower.

The grid collapses to one column at 640px, so a tile can run the full width of the panel. At the top of that tier a tile is wider than the desktop three-across tile, and the spectrogram scales with width. That is why the phone value is 280px and not 230px: the player it has to hold is taller there, not shorter. Set the viewport to 620px above and watch the readout under the hero tiles grow.

Every state, one footprint

Nothing moves when the tile changes its mind.

The frame carries the height, so the loading sweep, the live player, the offline placeholder, and the disabled notice all occupy exactly the same box. The meta row underneath never shifts. The one thing that does change is the placeholder's density: at 116px there was no room for a sentence, so audio dropped it. At 230px there is, and an icon alone in a tall box reads as unfinished.

What this settles

Three values, three reasons.

Audio tile, desktop230px
Species Detail proved this height in live review at the same grid and the same tile width, so it is the one number we know clears the player chrome. A smaller purpose-built height would be a guess, and a guess that lands a few pixels short ships the same bug in a quieter form. It also fixes the ragged rows: matching photo and video means every row in the grid lines up, meta rows included.
Audio tile, at or below 640px280px
One column, so nothing sits beside anything and uniformity buys nothing. Safety does. A single-column tile can be wider than the desktop three-across tile at the top of the tier, the spectrogram grows with width, and 280px is the value already proven at that width. If live review on a real phone shows audio needs less, it is a one-line tune in the same rule.
Offline and failed-load fallbackFull, not compact
The compact fallback exists because 116px had no room for a message. At 230px an icon and a button floating in a tall empty box reads as broken rather than as a considered offline state. Audio joins photo and video on the full fallback: the sentence, the icon, and the link. The date, the checklist link, and the Macaulay Library link sit outside the frame and never move either way.
Photo and videoUnchanged
230px desktop, 280px phone, exactly as shipped. Nothing about those two formats was wrong.

Two files.

frontend/src/globals.css — line 719, .sr-media-iframe--audio goes from 116px to 230px; line 1343, the same class inside the 640px block goes from 130px to 280px. The class stays. Named Birds keeps the per-format classes rather than borrowing --recent, so the two surfaces can still be tuned apart. Species Detail's --recent is untouched.

frontend/src/components/NamedBirdMedia.tsx — two call sites, not one. Line 223 passes compact={asset.format === 'Audio'} to the offline placeholder and becomes compact={false}. Line 229 passes no compact at all, and the shared frame defaults it to format === 'Audio', so the give-up overlay would stay compact unless that call site also passes compact={false}. Miss the second one and the offline state gets its message while the failed-load state quietly does not.

Optional, for The Engineer to weigh: with all four call sites now explicit, the compact = format === 'Audio' default in MediaEmbed.tsx is dead and is a trap for the next caller. Removing it is a clean-up, not part of this change.

The player in this mockup is a simulation. It makes no network request and no Macaulay iframe is embedded here, so the band heights are a faithful model, not a measurement: a spectrogram that scales with tile width, a 42px timeline strip, and a 52px transport row. Treat 230px and 280px as the values to build, and confirm the play control on the live desktop app against real data before the ship.
