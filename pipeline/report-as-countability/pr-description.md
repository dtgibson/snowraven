# Report-As Countability

### What this does

SnowRaven decided what counts as a species by looking at the shape of the name: a
trailing `sp.`, a `/`, an ` x `. eBird decides it with the `reportAs` field, which
is already in the taxonomy snapshot the app ships offline for favicons and
taxonomic sort. This replaces the string rule with eBird's own answer.

The rule, as a birder reads it: **ambiguity about which species does not count,
ambiguity about which subspecies counts as the parent.**

Three predicates (`isSpuhOrSlash`, `isNonCountableSpecies`,
`isNonCountableObservedName`) collapse into one, `isNonCountableForm`, taking one
input: the raw exported name.

### The delta, measured over all 17,891 published names

Two-way, and both directions are intended.

**Direction A: 88 names eBird counts that SnowRaven excluded, folding into 59
parent species.** Subspecies-group slashes inside a trailing parenthetical, and
ordinary for a North American birder: `Canada Goose (moffitti/maxima)`, `Redpoll
(Common/Hoary)`, `Dark-eyed Junco (Slate-colored/cismontanus)`, `Iceland Gull
(thayeri/kumlieni)`, `Red-tailed Hawk (calurus/abieticola)`, `Song Sparrow
(melodia/atlantica)`. Most people's totals go up.

**Direction B: 81 names SnowRaven counted that eBird does not.** 3 named hybrids
carrying no ` x ` (`Brewster's Warbler (hybrid)`, `Lawrence's Warbler (hybrid)`,
`Bogota Sunangel (hybrid)`), 25 spuhs with a parenthetical after the `sp.`, and 53
undescribed or unrecognized forms (48 `(undescribed form)`, 4 `(unrecognized
species)`, and one `(undescribed Panay form)`). This direction was not
recorded anywhere before the change brief: a birder holding Brewster's Warbler had
it counting as a species.

The same number now appears on Statistics, the Calendar, county Completeness and
the Multimedia count, which previously ran three slightly different rules.

### The engineering decision, and the evidence

The open question was where the rule's data comes from. Both options were built
far enough to measure.

`lib/speciesUtils.ts` is on `App.tsx`'s **static** import graph, so anything it
imports rides the entry chunk on first paint. That rules out deriving the set at
load from the dynamic-imported snapshot: the predicate is called synchronously
inside render memos, so a rule that changed value after load would leave every
already-computed memo stale with no re-render to correct it. Fixing that properly
would need a `useSyncExternalStore` seam at every consumer, which is the
call-site churn the brief rules out. It also puts 1.7 MB on first paint.

So: a companion artifact, statically imported, synchronous, complete the moment
the module loads. The remaining question was how big.

Shipping a verdict for all 17,891 names is ~105 KB gzipped. It does not have to
be: eBird's own naming convention already reproduces its verdict on 17,722 of
them, so the artifact ships the convention plus the **169 corrections**. Measured
on real builds, not extrapolated:

| entry chunk | raw | gzip | delta gz |
|---|---|---|---|
| HEAD (no artifact) | 286,562 | 74,250 | — |
| **shipped (169 names)** | **293,356** | **77,241** | **+2,991 (+4.0%)** |
| alternative (2,604 names) | 367,168 | 98,369 | +24,119 (+32.5%) |

The 2,604-name form costs **8.1x the increase for provably zero behavioural
difference**, because the convention already rejects all 2,523 names it would add.
That is a size choice rather than a semantic one, which is only safe because it is
verified rather than argued: `countableForms.test.ts` asserts the shipped
predicate equals the full `reportAs` lookup **name by name over all 17,891
published names**, and re-derives the artifact independently (it does not import
the generator, so a generator bug cannot pass).

The artifact is generated by `scripts/build-countability.mjs`, which
`build-ebird-taxonomy.mjs` calls in the same run, so the annual Clements refresh
writes both files together and they cannot drift. A version field pins the
artifact to the snapshot it came from.

**Fallback.** A name eBird does not publish falls back to the naming convention,
never to "counts". `isNonCountableNameShape` is byte-identical to the predicate it
replaced, so anything outside those 17,891 names behaves exactly as before. The
v0.5.87 escapee precedent runs the other way and deliberately does not transfer:
there an unresolved name would erase a bird the birder really saw, and resolution
is a live network pass that starts empty.

### The 37-versus-36 loose end: reconciled, nothing to correct

Both figures are right and count different things. 37 is the number of published
names containing ` x ` that eBird counts; 36 is what v0.5.86's parser convergence
actually rescued, into 26 parent species. The gap is exactly one name,
`Common Tern (hirundo/tibetana x longipennis)`: it carries a `/` inside its
parenthetical, so the slash half still excluded it and it was never among the 36.
It sits inside direction A, so this build is what finally admits it. Pinned in
`countableForms.test.ts` so the discrepancy cannot be rediscovered as a defect.

### Design decisions implemented

1. **Labels.** `Count all forms` (Statistics, Calendar) and `Show all forms`
   (Multimedia, Species Detail), plus the three Calendar strings. Single-sourced
   in `lib/countabilityCopy.ts` — a separate module from `exoticCopy.ts` because
   `LifeList.tsx` is on the entry chunk and `exoticCopy.ts` is lazy (~3.7 KB gz);
   importing it there to share one 15-character string would move all of it onto
   first paint. `exoticCopy.ts` imports the label it quotes.
2. **Widened** the Multimedia and Species Detail toggles from `isSpuhOrSlash` to
   the whole non-countable set, so the rows and the `X of N species` count agree.
   Delivering that at the DEFAULT view needed more than swapping the predicate:
   `mergeSubspecies` defaults to true, so the row key is the normalized base, and
   `Brewster's Warbler (hybrid)` collapses to `Brewster's Warbler`, which reads
   exactly like a species. Countability is therefore decided from the RAW names
   and carried alongside the key: `LifeListEntry.nonCountable` on Multimedia and
   a `countableKeys` set on Species Detail, both a monotone OR over the raw names
   behind a key (countable if at least one counts), which is the same shape the
   escapee rule uses.
3. **Kept** the Statistics same-tab asymmetry and stated it. The shared note is
   now unconditional on the two fixed-scope surfaces and gains
   `ALWAYS_COUNTABLE_NOTE`. The two rule sentences are generated from one base
   plus an optional clause, not written twice.
4. **No explanatory panel.** The reassurance clause ("They stay on your Life List;
   only the count changes.") is in `HELP.md` and the changelog.

### Verification

- **Full suites:** frontend 2,536 tests / 180 files, backend 227 tests, `npm run
  build` and `npm run lint` clean.
- **Mutation testing, 21 mutations across three harnesses, each sanity-checked
  against an unmutated baseline first.** That check earned its place: the first call-site run reported
  a red baseline (13 tests already failing on stale labels), which would have made
  every "expected FAIL, got FAIL" meaningless. 14 of 15 behaved as expected,
  including a must-stay-GREEN control (swapping the two correction-set branches,
  which is equivalent because the lists are disjoint).
- **Four mutations that should have gone red did not**, which is a finding about
  the tests rather than a clean bill. Three were real gaps and are now closed with
  discriminating guards: the Calendar's `buildDayCells`, county Completeness, and
  the media coverage denominator (which needed a new test file,
  `BirdingStatsCoverageDenominator.test.tsx`, because the existing BirdingStats
  fixture loads no ML export and every coverage assertion there would be vacuous).
- **The fourth is genuinely non-discriminating and is recorded as such** in
  `frivolousLists.ts` rather than papered over: normalizing its argument changes
  which names enter `recorded`, but no themed list names a direction-B base
  (swept, zero overlap), so the mutation is behaviour-neutral today. The comment
  names the tests that do carry the guarantee.
- **Probe set** (`countableForms.test.ts`): real data cannot distinguish the
  fallback's normalization choice at all, because every eBird name is well formed,
  so a snapshot-only sweep would pass a wrong implementation. Both numbers are
  asserted: **0 divergences across all 17,891 published names**, and **105 across
  37,448 exhaustively enumerated probes**. Enumerated to length 5 rather than 4
  because at length 4 all 13 divergences run one way; length 5 is where the second
  mechanism appears and diverges the other way.
- **Entry chunk:** `entryChunk.test.ts` extended — it now asserts the 1.7 MB
  taxonomy snapshot stays off the static graph (a live risk now that the rule is
  derived from it) and that the countability artifact is on it and stays small.
  Its comment-stripping weakness, recorded in CLAUDE.md since v0.5.87, is closed.
- **CSS:** `dist/assets/index-BeHPZBJc.css` is **byte-identical to a HEAD build,
  same content hash**, with a determinism control (HEAD built twice) and a
  reproducibility control (this tree built twice). This change touches `.test.ts`
  files, so the Tailwind auto-source-detection check is owed and was run.
- **Calendar zero-network:** `exoticProvenanceGraph.test.ts` passes unchanged. The
  artifact is a leaf JSON with no imports, so no passive module gains a network
  edge.

### Notes for reviewer

- **The predicate takes the RAW exported name.** This is the one thing to hold
  onto: normalization destroys the form, and the form is the whole question.
  `Brewster's Warbler (hybrid)` becomes `Brewster's Warbler`, which reads exactly
  like a species. Five call sites are guarded against passing a normalized name.
- **Frivolous Lists changed behaviour**, deliberately. It was the one site that
  classified a raw name with the normalized-name predicate, so intergrades like
  `Northern Flicker (Yellow-shafted x Red-shafted)` ticked nothing there while
  counting as their parent species elsewhere. That deviation dissolves.
- **`csvParserIntergradeFilter.test.ts`'s figures moved** from 36/0 to 124/81.
  124 = the 36 v0.5.86 intergrades plus the 88 new admissions; the 36 subset is
  pinned separately so a change that dropped them while adding the slashes cannot
  keep the total green.
- **`exoticCrossTabSentence.test.tsx`'s contract changed shape.** Its "absent
  case" for the two fixed-scope surfaces is no longer an absence, because the form
  exclusion is always in force there; what must be absent is the escapee *claim*.
  The pairs now assert the escapee-free variant renders instead.
- The design's watch item holds: `Show all forms` sits beside `Show subspecies`
  on both tabs. They are independent axes, and `Show subspecies` stays first. Both
  new test files pin that ordering.
- **`lib/exoticProvenance.ts` is git-BINARY**, from a deliberate NUL key separator
  at offset 7690 that predates this build (v0.5.87). Its diff does not render and
  it will break a `git apply` of a patch containing it. Its actual change here is
  a clean three-site rename of the predicate plus one comment correction; read it
  directly rather than through the diff.

### The wiring gap, found in QA and closed

Worth recording because it is the shape this build hit three times: **the
predicate was thoroughly guarded and the wiring was not.** QA measured that
reverting `SpeciesDetail.tsx`'s filter to the narrow spuh/slash rule left all
2,538 tests green, and that reverting `LifeList.tsx`'s two filters failed only an
unrelated `WeatherBacklog` pagination test that happened to cross a 100-row page
boundary. Neither component had a test file at all, so re-fixturing that
pagination test would have silently removed the build's only tripwire on its most
user-visible change.

Investigating it surfaced a real half-delivery rather than just missing coverage:
because `mergeSubspecies` defaults to true, the widened toggle was not actually
hiding the three named hybrids or the 53 undescribed forms in the default view.
That is now fixed (see design decision 2 above) and guarded by two new files,
`LifeListCountableForms.test.tsx` and `SpeciesDetailCountableForms.test.tsx`, each
asserting the rows AND the count together, in both toggle states, in both
directions of the delta. Six wiring mutations were run against them and all six go
red, including reverting each surface to the narrow rule and reducing the monotone
OR to last-write-wins.

One honest limit, recorded rather than papered over: measured over the snapshot,
**none of the 13,758 merged groups mixes a countable and a non-countable raw
name**, so no real eBird name can discriminate the monotone OR from
first-or-last-write-wins. Its guard uses an explicitly-labelled synthetic pair,
because a user's CSV is uncapped and a future Clements revision could introduce a
mixed group with nothing failing.
