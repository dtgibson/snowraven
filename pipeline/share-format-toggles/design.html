SnowRaven · Improve lane · design refinement

Three switches, eight payloads, one sentence that writes itself.

The Sharing preference stops being a two way choice and becomes three independent switches. Eight combinations follow, and with them the temptation to hand write eight button labels and eight mode lines. This refinement replaces all of that with one part table and two small functions, so a fourth destination costs one row and no new copy.

01 / The generating rule

One table. Two functions. No lookup of combinations.

Every string on every surface is derived from the ordered part table below. Nothing in the codebase should ever enumerate a combination. The mockup that follows is rendered by these exact functions, running in this page, so the eight states are checkable rather than claimed.

label is the visible switch text, which starts its own row. noun is the manifest form, which sits mid sentence after a colon. They are separate columns rather than one string plus a lowercasing call, because “lowercase unless it is a proper noun” is not derivable from a string: the trick reads correctly on today's three and silently produces Bing maps link on the fourth. qualifier and family exist only so the button can say map links instead of naming both providers. Adding a destination is one row here and nothing else.

The two functions

copyLabel(on)   // the popup button
  = 'Copy ' + phrase(on)

phrase(on)
  group the on-parts by family, order preserved
  a family with ALL members on   -> 'map links'
  a family partly on             -> list(qualifiers) + ' link(s)'
  no family                      -> the part's noun
  join the groups with ' and '
  (if a group already contains ' and ', join with ', and ')

modeLine(on)   // the popup line, and the Settings manifest
  = countWord(n) + (n === 1 ? ' line: ' : ' lines: ')
  + on.map(p => p.noun).join(', ') + '.'

n === 0 is not a ninth string. It is a different
structure: the button is replaced by a sentence, and
the example block is replaced by a sentence.

The two functions answer two different questions, which is why neither is redundant. copyLabel says what the press produces. modeLine says what it looks like when pasted, which is the one thing a short button cannot carry and the reason a collapsed map links is safe.

The Settings sub labels do not grow at all. The brief counts three surfaces reaching eight states; the third one is a false alarm. Each switch describes only its own line, so there are three descriptions, permanently. The live example does the work a combined description would have tried to do, and does it better because it is the literal payload.

The example block and the empty sentence swap with no transition. That is deliberate, not an omission. The whole safety argument for allowing all three off is that the consequence appears the instant the last switch flips; a fade would delay exactly the information the design depends on being immediate, and animating a text block on every flip is decoration, not explanation.

04 / All eight states, popup

The button label, and the state where there is no button.

Seven states carry a copy control. The eighth carries a sentence. The coordinate readout is payload independent, so it is present in all eight: the pin still shows the spot, and the text stays selectable by hand.

Longest label is 37 characters (Copy coordinates and Google Maps link), which fits the 224px compact popup in two lines and the 268px full popup in one to two. That bound is what the family collapse buys: the uncollapsed serial list would have run to 54 characters and three lines inside a card map popup.

06 / Migration

What the first launch after the upgrade looks like.

Nobody is told anything. There is no notice, no dialog, no changelog card. The only correct outcome is switch positions that already match what the person chose before, and these are the two states that must be exactly right.

A stored value the normalizer does not recognise, including anything written by a future build and read by this one, lands on all three on. That is today's default and today's superset, so a failed read never silently removes something the person was copying.

07 / 320px and 200% text scale

The hard case: a narrow phone with doubled text.

Three switch rows, a multi line payload holding a 45 character URL, and a manifest sentence, in one card, at 320px. Then the same card with the in app text scale at 200%, which is where a fixed width example block would break.

No horizontal page scroll at either scale. The example block already carries white-space: pre-wrap and overflow-wrap: anywhere from globals.css, so the Google Maps URL wraps inside the block instead of widening the page. The switch rows use .sr-action-row, which wraps the trailing switch onto its own line only when the label genuinely runs out of room, so a phone at 100% keeps the compact one line form and only the doubled scale stacks. Every size on this page is rem derived, so nothing was converted to px to make the narrow case fit.

08 / Accessibility decisions

Two calls worth stating out loud.

Names that stand alone

A screen reader user landing on the second switch hears its name with no row context, so “Google Maps link” alone is ambiguous. Each switch leads with the visible text, then says what it does, generated from the same table: 

'Coordinates. Include the coordinate pair
 when copying a location.'

'Google Maps link. Include a Google Maps link
 when copying a location.'

'Apple Maps link. Include an Apple Maps link
 when copying a location.'

Leading with the visible string satisfies Label in Name, and the repo already uses exactly this label + '. ' + aside formula on the row this replaces.

The live region: yes, but not the block

The example is a payload. Reading a coordinate pair and two full URLs aloud on every switch flip would be punishing, so the <pre> is not a live region. Silence is worse though: the switch announces its own on and off, which confirms the control but never the consequence, and the all off consequence is the one that must not be discovered later on a map.

So a visually hidden role="status" region announces the manifest sentence, which is short, already generated, and is the exact string a sighted user watches change. It renders no child until the first user change, so it never speaks on mount, and each announcement is a sequence keyed child node per the v0.5.80 convention. Honest caveat: with three switches every flip changes the string, so a consecutive repeat is not reachable today. The key stays because it costs one integer, this repo has already shipped that bug once, and a fourth destination or a reset control makes it reachable.

09 / The all-off copy

A consequence, not a scolding.

Settings, in place of the example

“Nothing to copy. The share pin will still show the coordinates on the map.”

States the outcome, then hands back the thing that still works. No imperative, no warning color, no alert icon. It sits in the example's own slot on the same subtle surface, with a dashed border rather than a solid one, so it reads as an empty container and not a message about a problem.

Popup, in place of the copy control

“Nothing is selected to copy. Choose what to copy in Settings under Sharing.”

The second sentence is an imperative because it is wayfinding, which is the one place an imperative is a service. A disabled button was rejected: no control that looks pressable may put an empty string on the clipboard, and a greyed control invites a press that explains nothing.

No em dashes anywhere in shipped copy: switch labels, manifest sentences, empty states, helper text and every aria-label. Periods and colons carry the joins.
