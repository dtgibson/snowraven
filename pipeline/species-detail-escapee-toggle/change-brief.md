# Change Brief: Species Detail Escapee Toggle

## What is changing
Species Detail gains a third toolbar switch, off by default, beside "Show subspecies" and "Show all forms". With it off, a species that eBird tags Exotic: Escapee on every checklist the user recorded it on is hidden from the species selector and left out of the "N species" figure, so that figure reads the same as the Statistics headline at both tabs' defaults. One press restores the rows and the number, exactly as "Show all forms" does for non-countable forms. Species Detail reads the escapee set PASSIVELY through the shipped `useProvenanceLookup` hook (the Calendar and Map Explorer pattern): it initiates no request, needs no key, and confirms each published name against the persisted checklist ledger using its own observations. The rule composes with the existing countable-form filter and never replaces it. With an empty cache every number and option on the tab is byte-identical to today.

## Why now
A saved idea from the user's inbox: the Species Detail species count does not match Statistics. Measured, not assumed: both tabs load the same parsed backup through `loadEbirdObservations` and derive the same species set (demo export, 7,869 rows: Statistics 149, Species Detail 149, identical set). The one mechanism by which they differ is `countableLifeList(lifeList, excludedNames)` on Statistics, which Species Detail has no counterpart for. On the reference export that is 267 on Species Detail against 264 on Statistics (Graylag Goose, Swan Goose, Muscovy Duck; DECISIONS v0.5.87).

## User-facing impact
One new switch in the Species Detail toolbar. Once Statistics has run the exotic-status check on a device, the selector loses the escapee-only species and the count drops by the same number; the switch puts them back. Where Statistics has never run the check nothing on the tab changes. Cross-tab: the escapee list on Statistics links each name to Species Detail, and that request must reveal the species rather than be dropped silently (open question 1). Statistics, the Calendar, the Map Explorer and Multimedia are unchanged; no new request, no new stored data, no privacy-policy change. `docs/HELP.md` changes in the same edit (the Species Detail toolbar bullet, and the Statistics paragraph that lists where the rule flows), as does the `bird-names.md` scope rule.

## Design pass
Needed. The surface being refined is the Species Detail toolbar row (`.sr-ctl-row`: two `ToggleSwitch` controls and the right-aligned "N species" figure), which gains a third switch and must still read as one control group and hold at 320px and 200% text scale on macOS, iOS, Windows and web. The Designer settles three things: the label (recommended `Show escapees`: `countabilityCopy.ts` records the rows-moving verb "Show" for this tab; single-source it in `exoticCopy.ts`, which the copy-hygiene sweep already covers); whether the count carries a one-line rule note when escapees are excluded (Calendar precedent: `.sr-count-rule-note` with `COUNT_RULE_SENTENCE`) or the toggle is the whole account (v0.5.89 decision 4, the recommended default); and that no `ExoticProvenanceAccount` panel is mounted here. The control is the shipped `ToggleSwitch`, matching its neighbours, ordered after "Show all forms".

## Preference: separate and session-only
The new switch is its own `useState(false)`, not a shared or persisted preference. Statistics' `includeEscapees` is session-only by its own stated design (no storage seam, resets on relaunch), as are `includeSpuh` there and `showSpuh` here; no toggle in this family persists, and the one persisted-toggle precedent (`hotspotTierRings`, v1.0.2) was a logged deviation for a vision aid. The idea's requirement is that the DEFAULTS agree, which both defaulting to off satisfies. A shared store would let a press on Statistics silently reshape the Species Detail selector, and possibly deselect the open species, while that tab sits hidden but mounted.

## Out of scope
- Statistics' Geographic Stats per-county species counts (ROADMAP): a different seam (`computeGeo` over `filteredObs`), and the stated prerequisite for Completeness on the Statistics map. Stays on the roadmap.
- Multimedia's rows and its "X of N species" figure: the other list surface with a "Show all forms" switch, and the same passive seam would fit it. The idea names Species Detail only; after this ships it becomes the one list count without the rule. Flag as a follow-on, do not build here.
- Initiating a provenance pass from Species Detail: FR-17 makes Statistics the only initiator, and `exoticProvenanceGraph.test.ts` enforces it.
- Any offline stand-in for provenance (the bundled taxonomy's `category`): forbidden by DECISIONS, under any label.
- Persisting the switch through the storage seam.

## Open questions for the Engineer, each with the default to take
1. `openSpeciesInTab` returns silently when the target is absent from `displaySpeciesList`, so a click on an escapee in the Statistics disclosure would open the tab with nothing selected. Default: when the target is in `sortedSpeciesList` and hidden only by the escapee switch, turn the switch on and select it. The same silent drop exists today for a name hidden by "Show all forms"; if the fix is the one condition, cover both, otherwise leave the forms case and note it.
2. Switching off while an escapee species is selected: deselect, mirroring `handleToggleSpuh`.
3. Under "Show subspecies" on, keys are raw names; hide a key when `escapeeNames.has(normalizeSpeciesName(key))`, so a domestic-type form of an escapee-only species hides with its parent. Build it as a layer on `displaySpeciesList`; leave the `countableKeys` memo untouched.
4. Hook input: `useProvenanceLookup(phase.tag === 'ready' ? phase.observations : EMPTY_OBSERVATIONS)` with a module-level constant, as `MapExplorer.tsx` does; the confirmation pass is memoized on that reference.
5. Render the switch always, as Statistics renders its checkbox regardless of resolution state; with an empty set it is a no-op. Never gate its presence on the set's size (a control that appears after a Statistics visit is a layout shift and a discoverability gap).
6. If the Designer adds the rule note, render it only when `escapeeNames.size > 0` and the switch is off, and assert it renders with an absent case (one test per surface, per the docs rule).
7. Component test: mock `../lib/exoticProvenanceCache` (`getSnapshot`, `loadSnapshot`, `subscribe`) to publish `excludedNames` with the carrying checklist in the ledger; assert the selector options AND the counter in both switch states; add a case where the carrier is absent from the ledger and the name stays visible. Stub the maps as the sibling test does.

- With a published escapee set whose carriers are all in the ledger, Species Detail's "N species" equals the Statistics headline at both tabs' defaults, the escapee species are absent from the selector, and one press restores both; with an empty cache every number and option is byte-identical to today.
- A published name whose carrying checklist is not in the ledger stays visible; `SpeciesDetail.tsx` imports `useProvenanceLookup` and never `useExoticProvenance`.
