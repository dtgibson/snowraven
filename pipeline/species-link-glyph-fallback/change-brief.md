# Change Brief - Species Link Glyph Fallback

## What is changing

One thing: the failure state of the two link marks beside every bird name (`frontend/src/components/SpeciesLinks.tsx`). Both `<img>` favicons stay, both hosts stay, both hrefs stay. Today a failed load runs `onError` and sets `visibility: hidden`, which empties the mark but keeps the anchor, so the user is left with a **fully invisible, still focusable, still clickable 24x24 target** beside the name, and offline that happens to every mark on every surface. Instead, a failed load renders a bundled lucide glyph in the same 14px slot.

**Non-destructive and per image, following v0.5.66.** The `<img>` is never unmounted, only hidden; the glyph sits absolutely positioned in the slot; `onLoad` clears the flag so a load that does succeed restores the real favicon in place. That is the shape v0.5.66 approved and v1.0.16 named, and it is why this is not a permanent latch. Each mark decides for itself, so a mixed pair is a real state (see below). No retry or re-request is added: nudging a failed `src` would be a new outbound-request policy and is out of scope. The two anchors become one internal sub-component called twice, so the glyph lives in one place rather than being inlined twice (the nav-rework principle). One bounded addition rides along: `ROADMAP.md:106`'s missing href shape gate (`/^[a-z0-9-]{2,16}$/` on `speciesCode`, render nothing on a miss, as the component already does with no code). **No durable cache** (below). Renaming `.sr-favicon-slot` is dropped: `img.sr-favicon` survives, so the name is still accurate and two guards stay untouched. **Removing the favicons entirely was considered, is wider than this idea authorizes, and has been captured as a separate idea for the user to decide; it is out of scope here.**

## Why now

- **The defect.** `onError` leaves an invisible but clickable target beside the name, and it is a permanent latch on a transient per-call failure. That is exactly the shape v0.5.66 rejected for embeds and v1.0.16 named as a family: a failure rendered as an unremarkable success.
- **A published claim is false today.** `docs/HELP.md:663` says "Even on a first-ever launch with no connection, bird names sort in taxonomic order and show their eBird and Birds of the World icons." The bundled taxonomy snapshot resolves the code offline so the `href` is right, but no image can load and the mark is an invisible hole. (`CHANGELOG.md:592` carries the same over-claim; it is a historical record and is not edited.)
- **Measured, and it corrects the idea in one place and sharpens it in another.** `ebird.org/favicon.ico` is a 302 carrying no `Cache-Control`, no `Expires` and no `Last-Modified`, so it is refetched on every cold image load (not on every React render) and returns `set-cookie: _9bf17=...` each time; its S3 target is 1,166 bytes at `max-age=2592000`. `birdsoftheworld.org/favicon.ico` is a direct 200, 15,086 bytes at `max-age=3600`. **The two therefore fail at different moments**: offline the eBird mark goes immediately while the Birds of the World mark can survive up to an hour from cache, so one favicon beside one fallback glyph is an ordinary state, not an edge case.
- **The cache half of the idea is redundant, not merely unwise.** The cache was the idea's mechanism for making the marks work offline; the fallback delivers that directly, because offline is precisely when the glyph renders. (It is also declined by name at the founding gate, and the `countyCompletenessCache` lineage is a JSON-document pattern with a code-unit budget, structurally wrong for image bytes.)

## User-facing impact

**Online, with both favicons loading, nothing a user sees changes.** The change is visible only where a mark fails: offline, behind a content blocker, or on a slow or refused response. There, an invisible hole becomes a visible glyph that opens the same page. Nothing moves in either state: same 14px slot, same 5px gap, same 6px left margin, same 24x24 targets, same accessible names, same destinations, same hover opacity step. A mixed pair (one favicon, one glyph) is expected and must read as a coherent pair. Surfaces where a mark can appear at all: Species Detail (header pair plus rows), Statistics (`BirdingStats`, Frivolous Lists, the escapee account), Multimedia (`LifeListTable`, media comments), Breeding Codes, Named Birds, Checklists, List Comparer, Map Explorer (panel, target and nearby-lifer markers, county layer and completeness popup). Calendar and Weather render no bird names; the Subspecies and forms control renders `BirdName` with no taxon code, so none of the three has marks today or gains any.

## Design pass

**Needed**, and narrower than a mark swap: nothing changes in the state a user normally sees, so the pass is about the failure state only. The Designer settles five things. (1) **Which glyph for each destination.** The idea proposes lucide `Binoculars` and `BookOpen`; both exist in the installed `lucide-react@1.14.0`, but both already carry a meaning in this app: `BookOpen` is the authoritative Species Detail glyph in `lib/tabIcons.tsx`, and a book beside a name that already links to Species Detail would read as that tab; `Binoculars` is the Map Explorer "lifers" mode-bar glyph. `Globe`, `Earth`, `Library` and `BookOpenText` are available alternatives. (2) **Size and stroke** inside the doctrine's in-content register (`pipeline/design-system.md:198`, lucide 11-15px, stroke ~2.2) in the fixed 14px slot. (3) **Token colours in both themes**, and whether the glyph takes the same resting `opacity: 0.75` / hover `1` step the favicon has; the dark-mode `filter: brightness(0) invert(1)` will not reach it, since that selector is `img.sr-favicon`-scoped. (4) **The 3:1 non-text contrast floor for the fallback state**, at rest, in both themes. (5) **The mixed pair**: a favicon beside a glyph must not look broken. What should feel better: a target that is currently invisible becomes visible, and the offline app stops showing holes where its marks should be.

The spec's `onError -> display: none` was already drifted to `visibility: hidden` in shipped code, which holds the slot and is why the fallback drops in cleanly.

## What done looks like

- **The shape built is the fallback alone**: both favicons and both hrefs kept, `onError` renders a bundled lucide glyph in the reserved 14px slot, `onLoad` restores the favicon, per image, `<img>` never unmounted. **No durable cache**, because the fallback already delivers the offline marks the cache was proposed to buy. **No privacy-policy edit is owed**: both hosts are still contacted on exactly the same schedule, so `PRIVACY_POLICY.md:74`, its `website/privacy.html:180` mirror and `appstore/LISTING.md:160-162` all stay true and are not edited.
- **Verified on** Species Detail, Statistics, Multimedia, Breeding Codes, Named Birds, Checklists, List Comparer and Map Explorer, in both themes, online, with the network off, and with one host blocked so the mixed pair is seen; at 320px and 200% in-app text scale. Both anchors keep their literal `tabIndex={0}` and their accessible names, both targets still measure >=24x24, the glyph is `aria-hidden` so it never doubles the name, and the Breeding Codes phone name cell still wraps without escaping its column.
- **Tests**: `BirdName.test.tsx:41-46`, `breedingNameColumnCss.test.tsx:78-84` and the existing `SpeciesLinks.test.tsx` cases all stay green, since the `<img>` and the slot geometry survive. `SpeciesLinks.test.tsx` gains the new state: fire `error` and assert a glyph appears with the anchor's name and target intact; fire `error` then `load` and assert the favicon is back, which is the case a latched implementation fails; assert the glyph is `aria-hidden`. `tabOrderCoverage.test.ts` and `entryChunk.test.ts` stay green. Run `npm run build`, not just vitest.
- **Docs change, at paragraph scope, and only two spots.** `docs/HELP.md:663` is the one that is false: offline a mark now shows, but it is the stand-in, not the eBird and Birds of the World icons the sentence names, so reword the whole paragraph to state the property rather than the specific icons. `docs/HELP.md:137`, the one place that defines the bird-name format, gains a clause for the fallback state. **Dropped as not needed under this shape**: `docs/HELP.md:441`, `:505`, `:570`, `README.md`, `website/index.html`, `PRIVACY_POLICY.md`, `website/privacy.html`, `appstore/LISTING.md`, `pipeline/design-system.md:194`. `ACCESSIBILITY.md:49` stays true (targets unchanged) and `:39` needs no roster edit, since it already names links; confirm the glyph meets 3:1 rather than editing the claim.
