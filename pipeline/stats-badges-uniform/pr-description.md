## Stats Badges Uniform

### What this does
The milestone badges in Statistics > Firsts & Milestones become one uniform tile, repeated: every badge is the same width and height, on a grid whose columns line up from row to row, the last row included. Each badge reads threshold, species, date, in that order. The threshold now carries a thousands separator (`1,000`). A long species name wraps inside its badge, and its eBird and Birds of the World marks drop beneath it as one unit. The redundant check mark and the stray rule above the set are gone. The sub-label now reads "Life list milestones", and it also names the list for screen readers.

### How to test
1. Load an eBird backup with at least 10 species and open the Statistics tab.
2. Scroll to Firsts & Milestones (or use its chip in the jump nav).
3. Check that every badge is the same size, the columns line up row to row, and the last row starts in the first column.
4. Check that thresholds of 1,000 and above print with a separator, and that no badge shows a check mark.
5. Switch the theme (Settings > Color theme) and confirm the four tier colors in both themes.
6. Set Settings > Text size to 200% and narrow the window toward 320px. The grid drops to fewer columns, then to one, and nothing spills out of the card or scrolls the page sideways.
7. Tab through a badge: the species name, the two marks, then the date link, each with the standard focus ring.

### Notes for reviewer
- **One deliberate deviation from the approved spec: the track minimum is 7.25rem, not 7.5rem.** The spec chose 7.5rem so a 320px phone gets two columns at 100% text and one at 200%. Measured in the built app, the card's content box at 320px is 242px, not the mockup's 258px. At 7.5rem two tracks need 248px, so the phone got one 242px column of 95.55px-tall badges. At 7.25rem (116px) it gets two columns of 117 x 128.05px, which is the spec's own measured result (2 columns, 128.1px tall), and one column at 200%. The widest one-line item, a month-first date with its glyph, keeps 9.7px of room at that width in both engines. The design-system pattern entry records 7.25rem.
- **Date color.** `ChecklistLink` writes an inline accent color that no class can out-rank, so the badge passes `style={{ color: 'var(--sr-ms-date)' }}`. That is the badge-local property the `data-tier` rule maps to `--sr-milestone-N-date`. The spec's literal (`var(--sr-milestone-${tier}-date)`) renders the same. Reading the badge-local property keeps the tier-to-token mapping in one place, the stylesheet. No `fontSize` is passed; `.sr-ms-date` sets it by inheritance.
- **No token values changed.** The four `--sr-ms-*` names are badge-local custom properties, never declared on a theme block. `--sr-milestone-N-check` stays: Frivolous Lists still paints a white check on tier 1's. `milestoneContrast.test.ts` keeps every row, and only its comments changed to say what the check rows now guard.
- **Mark hover stays instant**, as everywhere else in the app (the spec left this optional). The name's hover and focus color eases over 120ms (`cubic-bezier(0.2, 0, 0, 1)`), and the global reduced-motion block collapses that. No entrance motion.
- **Test.** `BirdingStats.test.tsx` gained a hoisted observations override (reset in `afterEach`) and one test. A 1,010-species backup goes through the real accumulation and must render one `li.sr-ms-badge` per reached threshold, across all four tiers, in a `ul` named "Life list milestones". The test also checks DOM order threshold / species / date, the separator, the checklist link, the date color property, no inline style on the list or a badge, and no check glyph. Mutation-checked: red against the pre-change source, a dropped date color, an unformatted threshold, a shifted tier boundary, and an inline style on the badge.
- **Built stylesheet.** Diffed rule by rule against a HEAD build made in the same tree (with a determinism control): exactly the 13 `.sr-ms-*` rules were added, nothing was removed, and the utilities layer is identical. No comment or test string emitted a Tailwind rule.
- **Real-engine measurement.** A scratch probe reused the gate's apparatus (`serveDist`, `selectTab`, `dismissWelcome`) to drive the built web app against a stub backend serving a synthetic 1,042-species backup. All 36 badges rendered, with real marks on 35 and none on one. The sweep covered 18 widths from 320 to 1440px, at 100 / 150 / 200% text, in both themes, in Chromium and WebKit: 216 of 216 configurations, 0 failures. Every set had one width and one height (within 1/32px track rounding), every badge sat on a column, no element box or text ink fell outside its badge, the grid stayed inside the card, and the page never scrolled sideways. One transient page-scroll reading appeared mid-resize and cleared within 500ms. It was attributed by re-measuring that configuration on this build and on HEAD: 0px at every settle time on both. Control legs that undo the grid (the old flex-wrap shape), the equal rows (`grid-auto-rows: auto`) or the name wrap (forced one-line name) each went red. The probe is not committed, because this build does not touch `website/`. Promoting it into `website/tools/verify/` is the Tester's call.
- **Published surfaces untouched.** `docs/HELP.md`'s Firsts and Milestones paragraph stays true (it never named the check mark), and nothing in `website/`, `README.md`, `appstore/` or `PRIVACY_POLICY.md` changed.
