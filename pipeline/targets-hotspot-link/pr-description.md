## Targets hotspot link (targets-hotspot-link)

### What this does
On the Targets tab, the place under the date in each row's Last report cell becomes a link to its eBird hotspot page when it is a public eBird hotspot, the same way hotspot names already link on Checklists, Statistics and Named Birds. A personal location stays the same muted plain text it was. After the user's live look, the shared `HotspotLink` also changed in its full-name branch: on a name that wraps, the open-on-eBird glyph now sits right after the last word instead of at the far edge of the column, on every surface that shows a full hotspot name.

### How to test
1. Build the frontend (`cd frontend && npm run build`) and start the backend with an eBird key (`cd backend && uvicorn main:app --port 1620`), then open http://localhost:1620.
2. Open **Targets**. It picks the county with the most checklists in your backup. Wait for the live band to read "Checked today at ...".
3. Press **Breeding** (a county you bird a lot may have few lifers with a recent report).
4. In **Last report**, hotspot names are green, weight 500, with a small glyph right after the last word, also on a name that wraps to a second line. Hover one: it underlines, last word included. Click it: `https://ebird.org/hotspot/L...` opens in a new tab.
5. Find a personal location (an address or a private pin): it is muted gray plain text, no glyph, no hover, exactly as before.
6. Narrow the window below 640px: rows become cards and long names wrap within their half of the card, glyph after the last word, with no sideways scroll. Tab to a link: the focus ring sits close (1px offset) so it does not run into the Distance cell.
7. Species Detail: pick a species with comments at a hotspot with a long name (for example Ridgway's Rail). Narrow the window until the comment's place wraps: the glyph follows the last word.
8. Turn the network off (or remove the key) and reload Targets: every place reads as plain text and nothing else changes.

### Notes for reviewer
- **Targets scope.** `LiveCell` gains `locId`, taken in `deriveLive` from the same newest record as `place`, so the name and the link always match; a newest record with no id gives `null`, never an older report's id. One `useHotspotSet()` call in the tab, passed down. The stored day-obs document, the backend, both transports, the shared fixture and the Rust iCloud code are untouched; `hotspotSet.ts` and `useHotspotSet.ts` are untouched.
- **`HotspotLink` (shared), full-name branch only.** When neither `truncate` nor `compact` is set, the anchor is ordinary inline flow (`textDecoration: none`, the caller's style, then the accent color LAST so a muted caller color never bleeds onto the link). The name is split at its last space: the lead (with its trailing space) in a plain span, then one `inline-block` (`max-width: 100%`, `overflow-wrap: anywhere`) holding the last word and the glyph. The glyph carries `display: inline-block`, `margin-left: 3px` and `vertical-align: baseline`. `aria-label` is unchanged. The `truncate` and `compact` branches keep their code verbatim and render byte-identically to the base commit (asserted against a fixture captured before the component was edited); the plain branches are untouched.
- **One deviation from the amended spec, required by the repo rules.** The spec gave the glyph `margin-left` and `vertical-align` only, assuming "no global svg rule". Tailwind preflight makes every `svg` `display: block` (`.claude/rules/ui.md`, the inline lucide glyph rule), which in the real build dropped the glyph onto its own line under the last word and made a one-line name 28px tall instead of 18px. The real-engine probe caught it; jsdom cannot. The glyph's inline `display: inline-block` fixes it and a test pins it.
- **Callers.** Verified by grep: the full-name callers are `BirdingStats.tsx:860`, `NamedBirdLocations.tsx:65`, `SpeciesDetail.tsx:1710` and `TargetsList.tsx`; every other call site passes `truncate` or `compact`. None needed changing. On Species Detail the link is a flex item in a wrapping row; an in-page swap with the old markup measured the same line start, link height and row height at 1280px, 375px and 320px at 200% in WebKit and Chromium.
- **CSS.** The link: `.sr-tg-place > a { font-weight: 500 }`, the underline-color rules on both of the anchor's spans, and in the established 640px tier `padding-block: 5px` and `outline-offset: 1px`. The hang (QA amendment, `decisions.md`; reshaped at the QA retry): `--sr-tg-glyph-hang: 13px` on the Last report cell (HotspotLink's 3px gap plus its 10px glyph); the glyph's `margin-inline-end` is minus the hang, so it adds no width to its line and shares the last word's line whenever the word alone fits; the LINK takes end padding of the hang cancelled by a negative end margin, so it adds nothing to line fitting but its last line fragment reaches the glyph's far edge; the last-word box takes no padding or margin, so its content can use the whole column; and in the phone tier the cell gets end padding of the hang less the 12px column gap, because on a phone the cells have no padding and the gap alone is 1px short of the hang. Why the room sits on the link and not the box: WebKit outlines a link's own line fragments whenever the link has padding (the phone tier gives it `padding-block`), so a cancelling margin on the box ended that fragment at the last letter and the focus ring missed the glyph (the Tester's re-verification); and end padding on the box alone came out of the width its content may use, which split last words that fit the column ("Sanctuar" / "y"). The earlier workaround rules (`max-width`, `> a > svg { align-self }`, the phone negative margin) are gone. The built CSS differs from a HEAD build by exactly these rules (rule-level diff, HEAD built twice as a determinism control); no utility class was emitted by the new comments, fixture or test strings. A cost of the hang, measured by real Tab focus in WebKit and Chromium: while a link is focused at phone width, its ring can paint over a few pixels of the first letter of the Distance column's text where the glyph hangs closest; the word stays readable. At 820px and wider, and at 320px with 200% text, nothing touches Distance text. (Row and pixel counts were measured by the Engineer and re-measured by the Tester, differ slightly between runs, and shift with each day's eBird data, so this states the property; the measurements are in `qa-report.md`.) The glyph itself never overlaps Distance text (0 in the sweep); at the phone tier a hung glyph's box can end as close as 0.03px from it, with the glyph's drawn stroke about 0.7px inside that box.
- **One network assertion re-checked.** `Targets.test.tsx`'s "renders before any network call" row asserted `tGet` was never called. The tab now asks for the shared hotspot Set (the same per-state lookup every other tab makes), so the row asserts that nothing *other than* `/map/hotspot-region` was asked, and says why in the test.
- **Tests.** `targetsLive.test.ts` extends the "greatest obsDt" row (the id comes from the newest record, including one with no id). `Targets.test.tsx` gains three rows (a hotspot link with its literal href and name beside a muted personal place, a null id with the Set loaded, plain until the Set arrives) and resets the module-level hotspot cache before every test. `HotspotLink.test.tsx` gains 19 rows: the split over a literal table (one-word, multi-word, "--" names, a hyphenated last token) and over a generated corpus of 2,508 distinct names (lead plus last equals the name, the last part holds no space), the glyph inside the last-word box, one-word names, the anchor's inline style and accent rule, the unchanged accessible name, and the seven base-markup fixture rows. No existing test needed changing for the component change. `targetsSortSelectCss.test.ts` (the Targets cascade guard) gains an F4 block of five rows plus three bundle rows: the hang equals the glyph the real `HotspotLink` renders in the Targets call (gap plus `width`, read off server-rendered markup), the hang declarations resolve on the link and the glyph at both tiers and never on the last-word box or the lead span (the property that keeps words whole and the WebKit ring around the glyph), the room to the column's right is at least the hang at each tier (desktop: both cells' padding; phone: the column gap plus the end padding, which must beat the tier's `padding: 0`), and the hang is emitted unlayered as logical properties. Its matcher learned structural pseudo-classes (`:last-child`), declared by the chain element. Mutations run: seven on the Targets change, twelve on `HotspotLink` and nine on the reshaped hang (including both rejected shapes: the hang back on the box, and end padding on the box), every one red.
- **The glyph never starts a line alone on Targets (QA amendment).** The Tester found the glyph alone on its own line far more often than first recorded (17 of 119 rows at 680 to 1040px at the default text size, including iPad portrait, and at every desktop width at 200%). The user chose to let it hang into the cell's spare padding. Measured on the final build in WebKit and Chromium over the Tester's sweep (320 to 1280px in 40px steps, 100% and 200% text) plus three dark-theme widths per scale, 112 readings: 0 rows with the glyph alone (the same sweep with the hang neutralized reports 1,416), 0 last words split mid-word, the glyph 3px after the last word (error at most 0.02px), the hang at most 12.97px past the column, 0 overlaps of the glyph with the Distance column's text, and the table's scroll inside its wrapper identical with and without the hang. The page never scrolls sideways; one reading (WebKit, 840px, 200%, dark, taken after resizing down from 1280px) showed 34px, identically with the hang neutralized, and a fresh load at that configuration reads 0. The keyboard focus ring encloses the glyph in every sampled link (all `:focus-visible` by a real Tab) in both engines at every width and scale above, (by 3.1 to 4.5px on phones, a 1px offset plus a 3px ring, and 5.1 to 6.4px on desktop, per the Tester); with the link's new padding and margin removed, it encloses as few as 0 of 25. A last token wider than the column still wraps inside its box with the glyph after its last fragment. On other tabs the shared component's behavior stands: a last word that nearly fills its line puts the glyph at the start of the next line. Screenshots: `targets-820-lake-elizabeth-light.png` and the two focus shots.
- **Pre-existing, outside this change.** At 320 to 400px with 200% text, the Targets table scrolls sideways inside its own wrapper by up to 104px, because of the Species column (bird names such as "Long-billed Dowitcher" with their reference-site marks). No place line is involved, the page itself does not scroll, and it reads the same with and without this change. Worth a roadmap item.
