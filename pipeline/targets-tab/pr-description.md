## Targets tab

### What this does

Adds a **Targets** tab (after Calendar in the default order) that turns one US county into a target list over the user's own record: the county's lifers, the recorded species still missing a photo, audio or video, and the recorded species with no breeding code (or no confirmed code). Each row carries two kinds of figure that are kept apart in words: **probability**, eBird's own frequency read from a county bar-chart file the user downloads from ebird.org and adds, and **live**, how many of the last 30 days eBird's API reported the species in the county, with the last report's date, place and distance. Distances are measured from the Default Location until the user picks another point from the status line under the controls: their location, a place they search for by name (one OpenStreetMap lookup per press of Search, never as they type), or a place the county's live data already names (no request at all); the choice lasts for the session and is never stored. It also fixes the shared `isWithinWindow` day-window predicate across a DST change, which the new window filter depends on.

### How to test

1. Load an eBird backup in Settings (the ML export is optional; without it the Media toggle is off with its reason).
2. Open **Targets**. The county picker opens on the county with the most checklists; type a county or state name to narrow it.
3. With no eBird API key and a county never loaded before: one line says the key is needed; nothing spins and no request is made. With a key: the county's species list loads, then the live band sweeps the last 30 days newest first and the rows fill in.
4. Visit a county loaded before with the network off: the list, badges, Alphabetical and Taxonomic sorts all work offline, and the live columns show the days already checked.
5. Toggle **Lifer**, **Media**, **Breeding**; pick Photo / Audio / Video chips; switch Breeding to **Confirmed**. The summary line always equals the rows shown.
6. In the **eBird bar chart** section, use the link to open the county's bar chart on ebird.org (it opens in the system browser), sign in, choose **Download Histogram Data**, then **Add file**. The probability columns fill with "%" figures naming the county and the file's year range; the default sort becomes this month's frequency. Try adding another county's file (refused with the reason) and a non-bar-chart file (refused), then **Replace** and **Remove**.
7. With live data present, try **Last report** (Day / Week / 30 days) and the **Distance** slider (Any, 1 to 50 miles). Nothing is hidden for a day that has not been checked yet.
8. Press **Default Location** in the line under the slider ("Distances from your Default Location."). The **Measure distances from** dialog opens with focus on **My location**. Pick a place under **Places in this list**: the dialog closes, focus returns to the line, which now reads "Distances from {place}, a place in this list.", and every Distance cell, the Distance sort and the slider re-measure from it. Open it again, type a town and press Enter or Search: exactly one OpenStreetMap lookup, none while typing; a miss reads "No location found. Try a different search term." and keeps the anchor. Escape closes it. Switch county: the point stays. Reload: distances are from the Default Location again. With no Default Location saved, the line offers "Choose where to measure from" and the Default Location item is disabled with "Not set in Settings".
9. Click a recorded species name: Species Detail opens on it. A lifer's name is plain text.

### Notes for reviewer

**Alameda pin not run (blocking the probability figures' method, not the build).** Schema section 2.6 asks for the pin against the user's real Alameda bar-chart file (Lincoln's Sparrow must print 3.29% year-round) before any UI shows a figure. The file is not on this machine. Everything the pin needs is built: `frontend/scripts/barchart-pin.mjs` (runs the shipped parser and both derivations, exits 0 only when one method prints 3.29, and writes the fixture with `--fixture`), the scaffold in `barChartFrequency.test.ts` (an explicit `it.todo` naming the missing `alameda.fixture.json`), and `FREQUENCY_METHOD` as one constant (currently `'sample-weighted'`, unconfirmed). The parser and both derivations are tested against clearly named synthetic fixtures. Until the pin runs, the figures the tab shows use an unconfirmed method.

**Deviations from schema.md / design-spec.md, each deliberate:**

- **Window and distance hiding is stricter than the literal spec.** A row is hidden only when no report falls inside the window AND every day in the window has been checked; a known-old last report with an unchecked (failed) window day stays visible. This is the spec's own "never hide an unchecked row" rule applied to its first arm too.
- **A chosen sort persists across county changes while available** (PRD FR-49 / design-spec Interaction Notes), rather than the mockup's reset on county change.
- **`TabLoadErrorAlert` gained an optional `onRetry`** (a Retry button after Go to Settings, outside the live region) so the Targets load error has a retry; no existing caller passes it, so every other tab renders byte-identically.
- **`barChartFilesChanged.ts` is not on the entry chunk.** Only the lazy Targets tab reads it today; it is dependency-free (closure size 1, asserted in `entryChunk.test.ts`), so a future Settings listing can import it safely.
- **The species name's accessible name is BirdName's own** ("Song Sparrow"), not the spec's "{Name}, open in Species Detail": the suffix would mean changing the shared `BirdName`, used app-wide.
- **The anchor status line names "your Default Location" without the place name** (the spec's "(Oakland)"); the stored Default Location carries coordinates the tab reads, and no label. The chooser's Default Location item reads "Set in Settings" for the same reason.
- **The measuring-point chooser (Stage 4 re-entry, FR-51a)** differs from the spec in five small ways, each recorded in decisions.md: "Places in this list" is built from every pool species' last report (the mockup and the PRD) rather than only the rows on screen, so a narrowing filter cannot remove the places a user would re-anchor to; a click outside returns focus to the trigger only when it left focus nowhere; the slider's `aria-describedby` points at a hidden plain-text twin of the status line, because the line now holds the trigger and its accessible name would be spliced into the description; the chooser's non-offline failure line is "Location search failed. Try again." (Map Explorer's line offers coordinate entry, which the chooser has not got); and the no-anchor trigger's accessible name is its visible text "Choose where to measure from" (the spec's "Choose where distances are measured from" did not contain the visible words, WCAG 2.5.3).
- **On a phone the anchor trigger renders at the house 16px control floor** inside the 12px status line (`.sr-ctl-row :is(button, …)`), as the earlier "Use my location" link did. Flagged for the Designer rather than overridden.
- **The table's sticky header rows pin within the table's own horizontal scroll box, not to the page** (the `.sr-scroll-x` wrapper binds `position: sticky`; the same constraint recorded for Breeding Codes).
- **`mapFabCascade.test.ts` gained a `NEVER_A_FAB_ANCESTOR` row for `sr-tg-table`**: the Targets sort-header icon rule (`.sr-tg-table .sr-th-sort[data-active="true"] > svg`) ends in a bare `svg` compound, which the scan must resolve by name; the Targets tab mounts no map. Its "every reason is used" check now reads both scans, because `resolveAll` excuses competitors in both and this is the first reason only the glyph scan needs.
- **`parseBarChart.test.ts`'s linearity legs now time small and large interleaved at min-of-7** (was back to back at min-of-3): a full-suite run beside another session's browser probes read a 5.88 quotient on one shape that measures 1.6 to 2.0 in isolation at every doubling from 2 MB to 16 MB. Threshold unchanged at 3.2.

**QA round 1 fixes:** the sort `<select>` carries `overflow: hidden`, because WebKit (unlike Chromium, whose UA sheet already clips a select) counted its full selected label as page overflow, clipped on screen but widening the document to 693px at 360 to 640px and 962px at 320px / 200% with a probability sort selected; it sits on the select, not its wrap, so the input focus ring is not cut. And the glyphs inside `.sr-tg-status` and `.sr-tg-link` are `display: inline-block`, because Tailwind preflight blocks every `svg` and put each leading glyph on a line of its own. Both are pinned as resolved cascade values by `targetsSortSelectCss.test.ts`.

**Shared-code changes outside the tab:** `isWithinWindow` in `lib/nearbyLifers.ts` rounds instead of flooring (Nearby Lifers and Media Targets on the map, the Calendar's recency, and the iOS widgets agree; the widget parity fixture's DST row now asserts agreement, and the ROADMAP item is removed). `tabLayout.ts` adds `targets` with the one-generation migration (a saved layout equal to the 1.0.19 default moves to the new default; any custom layout is kept and gets Targets appended). `storage.ts` gains the four bar-chart methods on both adapters (Tauri writes chained on the manifest path; web/Pi through `backend/routers/barcharts.py`). The new `/map/county-day-obs` route is in `EBIRD_GATED_PATHS` on both transports. The new durable day cache is its OWN document (`data/county-day-obs.json` on Tauri, the `county-day-obs-v2` key on web/Pi, three typed seam methods on `storage.ts`, the `replay.json` precedent) with its own ordered writer, a 10,000,000-code-unit budget and a comparator eviction; it is registered in `clearDerived.ts` as `county-day-obs.json`, and it deletes the preview builds' `county-day-obs-v1` settings key once per session. Measured on the build Mac for a full 10 MB store: one flush costs 23 ms on the main thread in WebKit (stringify plus the fs plugin's encode) and the first load 40 ms (parse plus validation), both recorded in decisions.md. **Map Explorer's place-name search was lifted into `components/AddressSearch.tsx` + `lib/placeSearch.ts`** so the chooser runs the same one: Map Explorer's markup is unchanged, and it now also validates the Nominatim answer (a malformed body reads "No location found") and sends nothing on a second press while a search is outstanding.

**Published copy not written:** `PRIVACY_POLICY.md`, `website/` and `README.md` are unchanged. The exact proposed text (the two privacy sentences with the before and after of the eBird bullet, an optional third, and one sentence each for the website and README) is in `pipeline/targets-tab/copy-proposals.md`, for the user's approval. `docs/HELP.md` carries its `## Targets` section and an offline bullet; `targetsPublishedClaims.test.ts` holds that passage to the code. No version bump or changelog entry in this change.

**Known limitations:** the day cache's first load validates every record of the store on the main thread (about 40 ms in WebKit at the full 10 MB budget, once per session); the linearity guard turns a per-line whole-text rescan red on three of its five shapes but makes the row-dense shape run for minutes rather than fail (a synchronous loop cannot be interrupted by a test timeout; CI's job timeout still ends it red).
