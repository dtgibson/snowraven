## upload-origin-table-wrap-copy

### What this does

Four confirmed defects, one fix. On the web/Pi backend, a state-changing request that a browser sends from another site is now refused with 403 before routing (so nothing is read or written), `POST /settings/{key}` requires `application/json`, and every response carries `X-Frame-Options: DENY`, `Content-Security-Policy: frame-ancestors 'none'`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: strict-origin-when-cross-origin`. On every platform, the Targets Species cell wraps a long scientific name at phone widths instead of widening the table, and two Settings sentences now say where things are really saved (Appearance, per platform; Bar-chart files, "this server" on web/Pi).

### How to test

1. Backend: `cd backend && .venv/bin/python -m pytest tests/ -q` (2,044 pass). The new `tests/test_browser_protections.py` sends each deployment shape the brief names, with the headers a browser would send, against every write route.
2. Cross-site refusal by hand, with the backend running (ideally on a throwaway `SR_DATA_DIR`): `curl -i -X POST -H 'Origin: https://evil.example' -H 'Content-Type: application/json' -d 'true' http://localhost:1620/settings/sr-origin-check` returns `403 {"detail":"Cross-site request refused."}` and writes nothing; the same command without the Origin header returns 200 (then `curl -X DELETE http://localhost:1620/settings/sr-origin-check` to remove it). A multipart upload to `/settings/files/ebird` with that Origin is refused the same way.
3. Headers: `curl -I http://localhost:1620/` shows the four headers.
4. The app still works: under `./start.sh` and under `npm run dev` (Vite proxy), upload a backup, save a setting (for example the Text size), and remove a file. Each should succeed.
5. Targets: open the Targets tab at 320px wide with Settings, Appearance, Text size 200%, on a county whose list includes Yellow-headed Blackbird or Bonaparte's Gull. The table does not scroll sideways; the scientific name wraps under the common name.
6. Settings, Appearance: with no saved choice, pick Dark. On web/Pi the prompt reads "Your preference will be saved on this server and used by every browser that opens SnowRaven here."; in the desktop app, "Your preference will be saved in this app's settings on this device."
7. Settings, Bar-chart files on web/Pi reads "No bar-chart files are saved on this server." (or "Saved for N counties on this server.").

### Notes for reviewer

- **Mechanism (decisions.md 1):** backend-only. `Sec-Fetch-Site` decides when present, and only `same-origin` passes (`same-site` is another origin; `none` is a user navigation, never a write). Without it (Safari before 16.4) the `Origin` must match `Host`, an `X-Forwarded-Host`, or the dev page origin `http://localhost:5173` (the Vite proxy rewrites Host); `Origin: null` matches nothing. Neither header (curl, TestClient, Node `fetch` in `website/tools`) passes. A missing port takes the Origin scheme's default, so a TLS-terminating proxy that keeps Host works, and a proxy that sends `host:443` too. Known limit, documented at the definition: an old Safari behind a proxy that rewrites Host and adds no `X-Forwarded-Host`, or a dev page opened on a LAN host, is refused (a failed save, never a silent one).
- **Middleware order is load-bearing** (`backend/main.py`): `SecurityHeaders` is outermost, so a CORS preflight answer and the guard's 403 carry the headers; the guard sits outside CORS. One residual: an unhandled exception's 500 is written by Starlette's `ServerErrorMiddleware`, outside every user middleware, and carries only a plain-text body.
- **`nosniff` cannot break a load:** Vite's module scripts and workers already require a JavaScript MIME type, Python's `mimetypes` types `.js`/`.mjs` as JavaScript and `.css` as `text/css` (one test reads the running host's answer, so CI checks Linux), and the map's `.pbf` glyphs are fetched as bytes, which `nosniff` does not govern. No MIME registration was needed.
- **`settingskv`** now answers 415 for any non-JSON content type before reading the body; `test_non_json_body_rejected_422` became a 415 row over `text/plain`, form, multipart and no type (each carrying a valid JSON body), plus a 422 row for invalid JSON sent as JSON.
- **Targets CSS** is three rules in the established 640px tier, scoped to `.sr-tg-name` like the Breeding Codes and Rainbow Connection repairs. The shared `.sr-birdname-sci` is untouched, and the built CSS differs from HEAD's by exactly those three rules (rule-by-rule diff, utilities identical). The 1.0.47 Last report hang (F4) is untouched; its rows pass unchanged.
- **Mutation-checked:** 15 backend mutations (guard removed, `same-site`/`none` allowed, `Sec-Fetch-Site` ignored, `X-Forwarded-Host` ignored, dev origin dropped, no default port, `null` passes, prefix host match, credentials allowed, both middleware orders, one header dropped, two `settingskv` arms) and 12 frontend mutations (each CSS rule deleted, `break-word` for `anywhere`, selector renamed, rules moved to top level, shared rule changed, the old Appearance sentence, swapped branches, `here` reverted, server word everywhere, the BirdName wrapped in a span) each turn at least one row red; restores verified by hash.
- **Built-app check (scratch probe, not committed):** the Targets tab served from the built `dist` with a stubbed backend, 320 to 420px in 10px steps at 100/150/200%, Chromium and WebKit: 66/66 configurations measured, table and page scroll 0, no box or text ink past the cell (worst 0.02px), favicons inside the cell, every 24px hit target unclipped, and the scientific name wrapping in 20 configurations. The same dist with HEAD's stylesheet reproduces the brief exactly (74px of table scroll at 320px/200%, 34px at 360px) in both engines. Promoting it into `website/tools/verify/` would be a `website/` change, which this build was told not to make.
- **One captured fixture string moved on purpose:** `settingsOffIos.fixture.json`'s web entry now reads "saved on this server" in the Bar-chart files status; Windows and Mac entries are as captured.
