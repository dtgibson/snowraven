# Design Spec — weather-tides

**Lane:** New Feature · **Stage 4 (Designer)** · Source: `prd.md`, `schema.md`
**Canonical design system:** existing `frontend/src/globals.css` tokens. No new
tokens; the tide box reuses the weather box's styling verbatim, so it reads as a
sibling, not a bolt-on. (No `design-system.md` needed — nothing new to establish.)

## Placement

Inside the same Weather `sr-card`, directly below the weather `<pre>`, after a
matching `<hr>` divider. The tide section appears whenever a lookup runs; it has
its own independent state (loading / result / notice) so it never affects weather.

## Result box (mirrors "Weather output")

- A label row: **"Tide output"** (uppercase muted label, same as "Weather output")
  on the left; a **Copy** button on the right, identical to the weather Copy button
  (accent-bg → accent on click, Check/Clipboard icon, "Copied!").
- The formatted block in the same `<pre>` styling: `var(--sr-surface-subtle)` bg,
  `var(--sr-border)`, radius 8, monospace 0.84375rem, line-height 1.75,
  `white-space: pre`.

### Formatted block (the data contract from schema.md, finalized wording)

```
🌊
Observed
Water level: 3.2 – 4.1 ft
Tide: Rising
Previous low: 0.6 ft at 5:02am
Next high: 5.1 ft at 11:18am
Station: San Francisco (9414290), 3.4 mi away
Relative to MLLW
Tide data from NOAA CO-OPS · via SnowRaven
```

- Line 1: 🌊 (the tide analog of the weather emoji).
- Line 2: **Observed** or **Predicted** — the "condition" line (raw `q`/`v`/`p`
  codes are never shown).
- **Water level is a RANGE over the checklist's duration window**, exactly like
  weather samples start→end: `min – max ft` (weather's `lo - hi` format). A
  zero/short-duration checklist collapses to a single value (`3.2 ft`). If a high
  or low tide falls *within* the checklist window, append "(turned during your
  checklist)" to the Tide line.
- "Tide: Rising / Falling" — net trend across the window (derived).
- Previous/Next H/L bracketing the window, with heights + local times.
- Station name + id + distance ("N.N mi away").
- Datum line ("Relative to MLLW"); attribution line mirrors the weather
  attribution. Copy copies this exact text.

## Loading

While the tide call is in flight (and weather has resolved), show a single muted
line under the divider: a small spinner + "Loading tide…" (same `Loader2 .spin` +
`var(--sr-text-muted)` idiom used elsewhere). No layout jump when it resolves.

## Notice + override states (the two "errors")

Both render as a soft **notice** (not a hard red error — data is reachable via the
override): `var(--sr-warning-bg)` background, `1px var(--sr-warning-subtle)` border,
`var(--sr-warning)` text, radius 8, padding 12–14, an `AlertCircle` icon, the
message, and a right-aligned override button.

- **Too far (in US):** "The nearest tide station is **N miles** away
  (<station name>). Tide data may not reflect your spot." Button: **Show it anyway**.
- **Outside US:** "Tide information is only available in the US. The nearest US
  station is <station name>, N miles away." Button: **Show nearest US station**.
- The override button uses the accent style (like Copy). Tapping it re-runs with
  the force flag and replaces the notice with the result box (which then names the
  station + distance, so the user sees how far it was).

## Copy Weather and Tide Together (bottom of the card)

Below the tide box, a full-width **"Copy Weather and Tide Together"** button
(secondary/accent style). It copies the weather block and the tide block as one
text, with a SINGLE SnowRaven attribution at the very bottom:

```
⛅
Partly cloudy
Temperature: 58 - 61°F
Wind: Light breeze
Wind Direction: NW
Cloud Cover: 40 - 60%
Humidity: 78 - 84%
Dew point: 52°F
Sunrise: 6:13am
Sunset: 8:09pm

🌊
Observed
Water level: 3.2 – 4.1 ft
Tide: Rising
Previous low: 0.6 ft at 5:02am
Next high: 5.1 ft at 11:18am
Station: San Francisco (9414290), 3.4 mi away
Relative to MLLW
Tide data from NOAA CO-OPS

Weather and tide generated by SnowRaven
```

- The two per-block SnowRaven attributions are **removed** and replaced by one
  combined line at the very bottom. The **NOAA data credit stays** (it's a
  data-source credit, not the app attribution) — "Tide data from NOAA CO-OPS"
  with the "· via SnowRaven" suffix dropped.
- The button appears **only when both blocks have results**. If the tide is a
  notice/error (no tide text), the combined button is hidden — the individual
  weather Copy covers that case.
- Same Copy affordance (Check/"Copied!" feedback) as the per-block buttons.
- Implementation: the formatters expose the block **body** separately from the
  attribution so the combined copy composes one attribution (small refactor of
  `weatherFormatter` to factor its attribution line out).

## Hard error (service failure)

If the tide service itself fails (network/NOAA down), show one muted line:
"Tide data unavailable right now." — never blocks or restyles the weather box.

## Accessibility

- Loading line `role="status"`; notice `role="status"` (recoverable, not alert);
  a true service-failure line `role="status"` as well (it's informational, weather
  still succeeded). Override is a real `<button>` with an explicit `aria-label`.
- Copy button `aria-label="Copy tide output to clipboard"`.
- All color via `var(--sr-*)`; respects light/dark automatically.

## Out of scope (design)

No graph/chart, no map, no animation beyond the existing spinner. Text block only,
to match the weather box.
