# Architecture — weather-tides

**Lane:** New Feature · **Stage 3 (Architect)** · Source: `prd.md`
**Detection path:** Incremental — no DB; this is an external-API integration that
mirrors the existing weather path. No `schema.md` migration; this doc is the
integration + data design.

## Shape: mirror the weather path, dual-runtime

`transport.get('/tide/{checklistId}')` →
- **web/Pi:** `backend/routers/tide.py` → `services/ebird.fetch_checklist` (reused)
  + `services/noaa.py` (new) + `formatters/tide.py` (new).
- **desktop:** `frontend/src/lib/tauri/tideService.ts` (new), dispatched in
  `TauriTransport.get` beside the `/weather/` block, using `tauriFetch`, reusing
  `getRegionInfo` + `invoke('get_timezone')` + `parseLocalDateTimeInZone`, and a
  shared `frontend/src/lib/tideFormatter.ts` (new, TS twin of the Python formatter).

The response matches the weather shape: `{ formatted, checklist_id, loc_name,
obs_dt, station, source, error? }` — `formatted` is the newline text block;
`station`/`source` let the UI show structured bits if desired.

## NOAA CO-OPS (keyless)

- **Checklist DURATION window (mirror weather):** the weather path computes
  `start = obs_dt`, `end = obs_dt + duration_hrs` and shows ranges across it. The
  tide path uses the SAME window: the water-level reading is a **range (min–max)
  over [start, end]**, not a single instant, and any H/L falling inside [start,end]
  is flagged "turned during your checklist".
- **Data:** `https://api.tidesandcurrents.noaa.gov/api/prod/datagetter`
  - Observed: `product=water_level&datum=MLLW&units=english&time_zone=lst_ldt&
    format=json&application=SnowRaven` over **[start, end]** (6-min points); take
    min/max for the range and the net trend (first→last). `q` flag v=verified,
    p=prelim. If the window is <6 min, one point → single value.
  - Predictions: `product=predictions&interval=hilo&datum=MLLW&units=english&
    time_zone=lst_ldt` over a window from the day before [start] to the day after
    [end]; gives the bracketing + within-window High/Low events (`type` H/L) and
    the fallback level range over [start,end] when observed is absent.
  - **Error handling:** NOAA returns `{ "error": { "message": ... } }` (often
    HTTP 200) when no data. Parse the body, never trust status. If `water_level`
    errors → use predictions, label **Predicted**.
- **Labels carry the request params:** unit (ft) + datum (MLLW) come from the
  request, not the body — the formatter must state "ft relative to MLLW" to match
  what was requested (no drift).

## Station resolution — bundled, US-only

- **Bundle** `frontend/src/assets/noaa-tide-stations.json` (precedent:
  `ca-atlas-blocks.json`), trimmed to `{ id, name, lat, lng, state, obs }`:
  - Union of NOAA `type=waterlevels` (mark `obs:true`) and `type=tidepredictions`
    (`obs:false` unless also in waterlevels).
  - **Filter OUT non-US** stations (the ~30–40 foreign `tidepredictions` entries +
    the 2 Bermuda gauges) so "nearest" is always a US station and distance is
    meaningful. Keep US states + territories (PR, VI, GU, AS, MP, Pacific).
  - Drop Great Lakes (`tidal:false`) for a tides feature, or keep + label — keep
    OUT by default (not tidal).
  - Generated by a committed script `scripts/build-tide-stations.mjs` (fetches both
    lists, trims, filters, writes the asset). Quarterly-stable; refresh at release.
  - Backend reads the same asset (shared path) so both runtimes use one list.
- **Nearest** = haversine over the bundle. Pick the single nearest station for the
  box (its name/id/distance shown). Query observed + predictions on it; if it's
  predictions-only, observed errors → Predicted. (Optional refinement: prefer the
  nearest `obs:true` station for the observed reading if within range — keep simple
  unless QA shows it matters.)

## Outside-US vs too-far (the two errors)

Hybrid test (PRIMARY country, FALLBACK geometry):
1. **Country (primary):** extend the shared checklist resolver to also surface the
   eBird **countryCode/subnational1Code** when the `checklist/view` response
   carries it (NO extra request — read from data already fetched; verify the exact
   field at build). If country is present and not US / a US territory → **Error B
   (outside US)**, short-circuit (don't call NOAA).
2. **Geometry (fallback + the in-US far case):** haversine to the nearest bundled
   (US-only) station.
   - country == US/territory (or unknown) **and** nearest > 25 mi → **Error A**
     ("nearest station is N mi away").
   - country unknown **and** the point is outside coarse bundled US bounding
     regions **and** nearest > 25 mi → **Error B**.
   - nearest ≤ 25 mi → show it, no error.
- **Override** (both errors): a one-tap action re-requests with a `force=1` flag
  that skips the threshold/country guard and renders the nearest US station
  regardless of distance.

## Concurrency & shared resolution

- UI fires weather + tide concurrently (`Promise.allSettled`) from one action;
  independent state per box.
- **Avoid double eBird fetch (perf nicety, not a blocker):** wrap the eBird
  `checklist/view` resolution in a short-TTL memo shared by weather + tide
  (desktop: a `regionInfo`-style memo; web/Pi: a small in-process TTL cache in
  `services/ebird`, or accept two cheap calls). Correctness first; optimize if easy.

## Data shapes (internal)

```
TideStation = { id, name, lat, lng, state, obs }
TideReading = {
  levelMin: number, levelMax: number,  // ft MLLW, range over [start,end]
  source: 'observed'|'predicted',
  trend: 'rising'|'falling',           // net first->last over the window
  turnedDuring: boolean,               // an H/L fell inside [start,end]
  prevHL: { type:'H'|'L', v:number, timeLocal:string },
  nextHL: { type:'H'|'L', v:number, timeLocal:string },
  station: TideStation,
  distanceMi: number,
}
```
Trend from first→last level over the window; `turnedDuring` true if an H/L event
lies inside [start,end]. Single-point windows set levelMin==levelMax.

## Attribution composition (for "Copy Weather and Tide Together")

Factor each formatter into **body** + **attribution** so the combined copy emits
ONE SnowRaven line:
- `weatherFormatter`: expose `formatWeatherBody()` (no attribution) + the existing
  `ATTRIBUTION`; `formatWeather` = body + attribution (unchanged output).
- `tideFormatter`: `formatTideBody()` ends with "Tide data from NOAA CO-OPS"
  (NOAA credit kept); individual `formatTide` appends " · via SnowRaven".
- Combined copy (App): `weatherBody + '\n\n' + tideBody + '\n\nWeather and tide
  generated by SnowRaven'`. NOAA credit stays inline; one SnowRaven line at the
  very bottom. Same split applies in the Python formatter for parity, though the
  combined copy itself is composed client-side.

## Formatter output (mirrors weather block)

```
🌊
Predicted              ← or "Observed"
Water level: 3.2 ft at 7:42am
Previous high: 5.1 ft at 4:28am
Next low: 0.6 ft at 10:55am
Tide: Rising
Station: San Francisco (9414290), 3.4 mi away
Relative to MLLW
Tide data from NOAA CO-OPS · via SnowRaven
```
Exact wording is the Designer's; this is the data contract. Rendered in the same
`<pre>`/`sr-card` styling with a Copy button.

## Risks / decisions for downstream

- Confirm the eBird field that carries country at build (else geometry fallback
  governs — acceptable).
- Preliminary observed (`q=p`) for very recent checklists may later be revised;
  treat as Observed but acceptable (historical checklists are verified).
- Station bundle staleness is quarterly; refresh script is committed.
